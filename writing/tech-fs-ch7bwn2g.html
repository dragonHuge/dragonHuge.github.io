ES理论&实践总结

2025-08-16"飞书工作积累" · 飞书原文 ↗

理论

  • 学习文章：https://www.cnblogs.com/buchizicai/p/17093719.html
  • 一篇很不错的入门文章：https://mp.weixin.qq.com/s/wlh2AHpNLrz9dHxPw9UrkQ
  • ES缓存讲解文章：https://www.easyice.cn/archives/367

以下进行个人理解总结。

1.简介

  1. 一个开源的分布式搜索引擎，可以用来实现搜索、日志统计、分析、系统监控等功能。

  2. 注意： 在没有创建库的时候搜索，ES会创建一个库并自动创建该字段并且设置为String类型也就是text。elasticsearch是一款非常强大的开源搜索引擎，具备非常多强大功能，可以帮助我们从海量数据中快速找到需要的内容。

2.正排索引 & 倒排索引

正排索引

💡

其实就是MYSQL中的索引方式："根据索引找数据"

MYSQL中使用"聚簇索引"的数据存储方式，且如果设置了索引，那么可以根据索引在B+树上进行快速查找，找到索引对应的数据。这种根据索引找数据的方式，就是所谓的正向索引。

  • 如果是根据id查询，那么直接走索引，查询速度非常快。

    但如果是基于title做模糊查询，只能是逐行扫描数据，流程如下：

    1）用户搜索数据，条件是title符合"%手机%"
2）逐行获取数据，比如id为1的数据
3）判断数据中的title是否符合用户搜索条件
4）如果符合则放入结果集，不符合则丢弃。回到步骤1

    逐行扫描，也就是全表扫描，随着数据量增加，其查询效率也会越来越低。当数据量达到数百万时，就是一场灾难。

倒排索引

💡

是指将文档中的每个单词映射到包含它的文档id上（是<单词,文档id>的一个映射关系）。

倒排索引中有两个非常重要的概念：

  • 词条（Term）-Key：对文档数据或用户的搜索数据，利用某种算法分词，得到的具备含义的词语就是词条。例如：我是中国人，就可以分为：我、是、中国人、中国、国人这样的几个词条
  • 文档（Document）-Value：实际数据，每一条数据其实就是一个文档(Json)。例如一个网页、一个商品信息
  • 分词：将每一个文档的数据利用算法分词，得到一个个词条
  • 创建表：每行数据包括词条、词条所在文档id、位置等信息
  • 给词条创建索引：因为词条唯一性，可以给词条创建索引，例如hash表结构索引
  • 用户输入条件"华为手机"进行搜索。
  • 对用户输入内容分词，得到词条：华为、手机。
  • 拿着词条在倒排索引中查找，可以得到包含词条的文档id：1、2、3。
  • 拿着文档id到正向索引中查找具体文档。

  • 如图：

  • 虽然要先查询倒排索引，再查询倒排索引，但是无论是词条、还是文档id都建立了索引，查询速度非常快！无需全表扫描。

两者对比

概念区别：

  • 但根据词条查询时，必须先逐条获取每个文档，然后判断文档中是否包含所需要的词条，是根据文档找词条的过程。

  • 是先找到用户要搜索的词条，根据词条得到包含词条的文档的id，然后根据id获取文档。是根据词条找文档的过程。

  • 💡

    倒排索引由两个主要部分组成：

    • 词汇表（Vocabulary）→ 词汇表存储了所有不同的单词
    • 倒排列表（Inverted List）→ 倒排列表存储了每个单词文档中的分布情况。
💡

核心浓缩：

  • 正排索引是从文档到关键字的映射（已知文档求关键字）
  • 倒排索引是从关键字到文档的映射（已知关键字求文档）

2.ES滚动搜索（Scroll Search）

💡

Scroll 是一种基于游标的分页方式，允许用户在大量数据上进行高效的分页查询。

它通过创建一个快照来保存搜索上下文，并使用一个滚动ID（scroll_id）来获取后续的数据。

  • 优点：Scroll 分页适用于需要按顺序获取大量数据的场景，如数据导出。
  • 缺点：但不支持随机访问页面，且会消耗更多服务器资源来维护搜索上下文和快照。
  • 业务背景：此时需要从ES中读取日志信息，再以一定的业务逻辑进行风险计算，若此条日志计算后存在风险，则将其存入MYSQL持久化。
  • 方案分析：此需求的常见做法是，从ES中读出所有日志，在逐条风险计算后，将风险日志存入MYSQL。但这样的实现方式，时间复杂度/空间复杂度都是很高的。因为它先要从ES读出所有日志，再分析完成后，统一批量导入MYSQL。

那么这个时候，ES滚动搜索就很香了。

1.简介

Elasticsearch的滚动搜索（Scroll Search）是一种用于高效检索大量数据的机制。

  • 允许用户在大量数据中进行分页查询，而无需使用传统的from和size参数，这在处理大数据集时特别有用。
  • 通过保持搜索上下文的活跃状态，允许用户在多个请求之间连续检索数据，而不需要对每个请求重新计算。
💡

滚动搜索不适用于实时用户请求，而是用于批量处理数据，例如日志分析或大规模数据迁移。

2.执行逻辑解析

滚动搜索的主要逻辑解析：

  1. 用户提交一个带有scroll参数的搜索请求，例如scroll=1m，这指示Elasticsearch保持搜索上下文打开一段时间（这里是1分钟）

  1. Elasticsearch执行搜索并返回第一批结果，同时返回一个_scroll_id，这个ID用于后续检索更多的结果。

  1. 用户使用返回的_scroll_id和scroll参数发起新的请求，以检索后续批次的结果。这个过程可以重复执行，直到检索完所有结果。

  1. Elasticsearch通过在每次滚动请求中指定scroll参数来重置搜索上下文的超时时间。

  1. 一旦完成数据检索，用户应该使用_clear_scroll API来清除滚动上下文，释放服务器资源。这可以通过传递scroll_id完成，或者使用_all参数清除所有滚动上下文

3.示例代码与分析

💡

核心工具类有：

  • Scroll：滚动搜索
  • SearchScrollRequest：滚动请求
  • ClearScrollRequest：清除滚动搜索

示例代码：

/**
 * 使用 Elasticsearch的滚动搜索功能来处理特定时间范围内的日志数据，并执行风险计算的逻辑。
 * @param start
 * @param end
 */
public void run(long start, long end) {
    final Scroll scroll = new Scroll(TimeValue.timeValueMinutes(1L)); // 设置滚动搜索的持续时间为1minute
    SearchRequest searchRequest = new SearchRequest(midunLogIndex);
    searchRequest.scroll(scroll); // 打入滚动搜索参数
    BoolQueryBuilder queryBuilder = QueryBuilders.boolQuery(); // 布尔查询构造器
    queryBuilder.filter(QueryBuilders.matchQuery("reqUri", "/afterservice/afterservice!api.action"));
    queryBuilder.filter(QueryBuilders.matchQuery("reqMethod", "GET"));
    queryBuilder.filter(QueryBuilders.matchQuery("logicRouter", "router=service_info_detail"));
    queryBuilder.filter(QueryBuilders.rangeQuery("ts").gte(start).lte(end));
    SearchSourceBuilder sourceBuilder = new SearchSourceBuilder(); // 搜索源构造器
    sourceBuilder
            .size(500)
            .timeout(TimeValue.timeValueSeconds(60))
            .query(queryBuilder);
    searchRequest.source(sourceBuilder); // 将搜索源构造器设置到搜索请求中
    SearchResponse searchResponse = null;
    try {
        searchResponse = searchHelper.search(searchRequest); // 执行搜索获得响应

    } catch (IOException e) {
        log.error("查询失败", e);
        return;
    }
    // 获取滚动搜索的ID和初次搜索的结果集
    String scrollId = searchResponse.getScrollId();
    SearchHit[] searchHits = searchResponse.getHits().getHits();
    // 滚动搜索，直到没有更多结果
    while (searchHits != null && searchHits.length > 0) {
        // 业务代码逻辑，即：计算风险，最终的结果是存入MYSQL
        calcRisk(searchHits);
        // 创建滚动请求，继续获取下一批结果
        SearchScrollRequest scrollRequest = new SearchScrollRequest(scrollId);
        scrollRequest.scroll(scroll);
        try {
            searchResponse = searchHelper.getRestClient().scroll(scrollRequest, RequestOptions.DEFAULT);
        } catch (IOException e) {
            log.error("查询失败", e);
            return;
        }
        // 更新滚动ID和获取新一批结果集
        scrollId = searchResponse.getScrollId();
        searchHits = searchResponse.getHits().getHits();
    }
    // 清除滚动搜索，释放服务器资源
    ClearScrollRequest clearScrollRequest = new ClearScrollRequest();
    clearScrollRequest.addScrollId(scrollId);
    ClearScrollResponse clearScrollResponse = null;
    try {
        clearScrollResponse = searchHelper.getRestClient().clearScroll(clearScrollRequest, RequestOptions.DEFAULT);
    } catch (IOException ignore) {
    }
    // 检查滚动搜索是否成功清除
    boolean succeeded = clearScrollResponse.isSucceeded();
}

3.分组Bulk向ES写入数据

💡

ES的概念学习中学到，ES元数据中 index，type，id 唯一标识一个文档，因此在进行ES的写入工作时，必须指定此三者元素，再进行数据写入。

  • BulkRequest：用于批量执行索引、删除、更新等操作

    使用 BulkRequest，你可以添加多个 IndexRequest、DeleteRequest 或 UpdateRequest 对象，然后一次性发送到 Elasticsearch

  • IndexRequest：用于创建或更新 Elasticsearch 索引中的单个文档。

    你可以设置文档的索引名、类型（通常是 _doc）、ID、源数据（通常是 JSON 格式）和其他元数据。

    IndexRequest 通常与 RestHighLevelClient 的 index 方法一起使用来执行单个文档的索引操作。

  • XContentType.JSON：Elasticsearch 中的一个枚举类型，表示 JSON 格式的内容

    在创建或更新文档时，你可以使用 XContentType.JSON 作为参数，以指定传递给 Elasticsearch 的数据是 JSON 格式的。这确保了 Elasticsearch 能够正确解析文档的源数据。

  • RestHighLevelClient：Elasticsearch Java 高级客户端的入口点，用于与 Elasticsearch 服务进行通信。

    通过 RestHighLevelClient，你可以执行各种操作，如索引、查询、更新、删除文档，以及执行批量和搜索操作。

  • /**
* List 分组bulk写入es
* @param workOrders
*/
public void splitPush(List<String> workOrders) {
  if (CollectionUtils.isEmpty(workOrders)) {
      return;
  }
  log.info("工单数据插入，数量: {}", workOrders.size());
  List<List<String>> partitionOrders = Lists.partition(workOrders, 500); // 将一个工单列表workOrders分割成多个子列表，每个子列表包含最多500个元素。
  partitionOrders.forEach(this::workOrderWrite); // 将所有子列表写入ES
}

private String workOrderIndex = "risk_risk_xms_work_order"; // 写入的文档索引
/**
* 工单实质写入ES的逻辑
*/
public void workOrderWrite(List<String> workOrders) {
//      BulkRequest对象，用于批量写入
  BulkRequest request = new BulkRequest();
  for (String workOrderStr : workOrders) {
      try {
//              分割单个工单字符串，获取其属性。因为此时工单的存储方式是String，即：一个String就是一条工单数据。
          String[] workOrderSplit = workOrderStr.split(SEPARATOR);
          String brandClassId = workOrderSplit[0].trim();
          String goodsName = workOrderSplit[1].trim();
          String imei = workOrderSplit[2].trim();
          int flashType = Integer.parseInt(workOrderSplit[3].trim());
          long createTime = Long.parseLong(workOrderSplit[4].trim());
          long updateTime = Long.parseLong(workOrderSplit[5].trim());
          long createPerson = Long.parseLong(workOrderSplit[6].trim());
          long updatePerson = Long.parseLong(workOrderSplit[7].trim());
          String incId = workOrderSplit[8].trim();
          String workOrderId = workOrderSplit[9].trim();
          String orderId = workOrderSplit[10].trim();
          String sn = workOrderSplit[11].trim();
          String docId = DigestUtils.sha1Hex(createPerson + createTime + updateTime + incId); // 构造文档id，使用SHA1散列值
          request.add(new IndexRequest(workOrderIndex + DateTime.now().toString(NormalConst.ES_EXTERNAL_DATE))
                  .id(docId)
                  .source(XContentType.JSON,        // 设置文档的_source，包含工单数据的JSON表示
                          "brandClassId", brandClassId,
                          "imei", imei,
                          "goodsName", goodsName,
                          "flashType", flashType,
                          "createTime", createTime,
                          "updateTime", updateTime,
                          "createPerson", createPerson,
                          "updatePerson", updatePerson,
                          "workOrderId", workOrderId,
                          "orderId", orderId,
                          "sn", sn,
                          "timestamp", System.currentTimeMillis()));
      } catch (Exception ignore) {
      }
  }
  try {
      elasticSearchHelper.getRestClient().bulk(request, RequestOptions.DEFAULT); // 执行批量写入
    // 这里的elasticSearchHelper.getRestClient()其实就是一个RestHighLevelClient，只不过自定义包装了一层
  } catch (IOException e) {
      log.info("bulk error", e);
  }
}
