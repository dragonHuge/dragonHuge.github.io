Hermes Agent 调研：它和 OpenClaw 的区别、联系与对比

2026-04-22 · 飞书原文 ↗
💡

Agent 框架的选择，很多时候是在选一种价值观：是要一个听话的工具(Claw🦞)，还是一个会自己长大的伙伴(Hermes)？

Hermes Agent 是 Nous Research 在 2026 年初开源的自改进 AI Agent，两个月内斩获 27,000+ GitHub Stars，并且直接内置了从 OpenClaw 迁移过去的工具链。

这份文档就是把它拆清楚，顺带和 OpenClaw 做个正面比较。

技术圈🔗：[内部链接]

💡

Hermes 和 OpenClaw 不是竞争关系，而是两种不同哲学的产品。

OpenClaw 是你养出来的龙虾，Hermes 是自己会长大的龙虾。

一、Hermes Agent 是什么

官网：https://github.com/nousresearch/hermes-agent

Nous Research 出品，MIT 开源，定位是"自改进 AI Agent"，官方口号"The agent that grows with you"。

核心理念一句话：AI 自己给自己造缰绳（Self-Harnessing）。

不靠用户手动配 SOUL.md，Agent 从使用过程中自动提炼规则、创建技能、优化记忆。这是它与大多数 Agent 框架最本质的差异。

关键数据：

  • GitHub Stars：27,000+（发布仅两个月，截至 2026 年 4 月）
  • 当前版本：v0.7.0（2026 年 4 月 3 日发布）
  • 支持消息平台：Telegram、Discord、Slack、WhatsApp、Signal、CLI 等 12+ 个
  • 最低部署成本：$5/月 VPS（Hetzner / DigitalOcean / Vultr）
  • 内存占用：<500MB（不跑本地 LLM 时）

安装只需一行：

curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash

支持 Linux、macOS、WSL2、Android（Termux）。

装完执行 hermes 就能开聊。

与其他工具的关系：

👍

Claude Code 是实时结对编程，OpenClaw 是配置驱动的 7×24 后台 Agent，Hermes 是自主后台 + 自改进.

三者均采用 agentskills.io 标准，Skill 互通。

二、理解 Hermes 的关键：从 Harness Engineering 说起

💡

要真正理解 Hermes 的设计哲学，得先讲一个词：Harness Engineering（驾驭工程）。

2026 年 AI 编程圈最重要的范式转变，就是从 "Prompt Engineering（写好提示词）" 和 "Context Engineering（组装好上下文）" 进化到 Harness Engineering —— 给 AI 造一套缰绳，让它在有边界、有约束、有反馈的环境里稳定产出。

核心逻辑是：人给 AI 造缰绳，AI 在缰绳内跑。

Hermes 做了一个极其大胆的反转 —— Self-Harnessing：

不再是人给 AI 造缰绳，而是 AI 从使用中自己给自己造缰绳。

这个反转让 Agent 市场出现了三种 Skill 范式的光谱：

一句话版本：OpenClaw 是让人去 harness AI，Hermes 是让 AI 自己 harness 自己。

三、核心架构：一条线串联一切

Hermes 的整体结构一行话：

学习循环 → 三层记忆 → Skill 系统 → 40+ 工具 → 多平台 Gateway

核心机制一：学习循环（Self-Harnessing Loop）

这是 Hermes 的"心脏"，五个环节构成自动改进飞轮：

  1. 策划记忆：每轮对话结束后，Agent 主动决定哪些信息值得记住，写入 SQLite 并建立 FTS5 索引。不是被动存储，是主动筛选。类比人类写日记。
  1. 自主创建 Skill：完成复杂任务后，Agent 自评该方案是否可复用，可复用则提炼成 Markdown Skill 文件，存入 ~/.hermes/skills/
  1. Skill 自改进：执行 Skill 时根据用户反馈自动修改 Skill 文件，下次执行用新版本，持续进化
  1. FTS5 跨会话召回：新对话开始时用全文搜索按需检索历史记忆，而非全量加载，避免上下文膨胀
  • FTS5：SQLite 的全文搜索引擎，让 AI 在新对话开始时能像搜索引擎一样"按关键词检索"历史记忆，只拉取相关片段而非加载全部历史，解决 context window 爆炸问题。
  1. 用户建模（Honcho 集成）：可选，分析用户行为模式，推理深层偏好、习惯、目标，形成多维身份画像
  • Honcho：一个开源的用户状态管理框架，通过分析用户历史行为自动推断其偏好、习惯、目标等"隐性特征"，让 AI 记住的不只是"你说过什么"，还有"你是什么样的人"。
🔥

这五个环节构成 Hermes 的自动改进飞轮。

关键点是：记忆、Skill、用户模型三条数据通路并行写回，下一次任务能同时复用三者。传统 Agent 只有记忆（对话历史），没有 Skill 沉淀和用户建模——这是 Hermes 和其他 Agent 最根本的架构级差异。

核心机制三：Skill 系统（自进化能力）

三种来源：

  • Bundled Skills：安装时预置的 40+ 个基础能力
  • Agent 自主创建：核心特色，任务完成后自动提炼，无需用户介入
  • Skills Hub：社区贡献，兼容 agentskills.io 标准，一键安装

Skill 自改进流程：执行 Skill → 收集用户反馈 → 分析并更新 Skill 文件 → 下次执行用新版本。

工具与调度

  • 40+ 内置工具：分为执行（代码/文件）、信息（搜索/抓取）、媒体（图片/视频）、记忆、协调（子 Agent）五大类
  • MCP 集成：通过 Model Context Protocol 可连接 6,000+ 外部应用
  • 子 Agent 委派：最多 3 个并发
  • Cron 调度：支持自然语言定时任务，日报、夜间备份、周度审计，全部无人值守
  • 模型自由切换：支持 Nous Portal、OpenRouter（200+ 模型）、OpenAI、Kimi、MiniMax 等，hermes model 一键换，零代码改动

四、Hermes 和 OpenClaw 的关系

这两个不是竞争关系，是两种不同哲学的互补产品，生态上还有直接连接。

生态层面：两者都采用 agentskills.io 标准，Skill 可以互通。

Hermes 还内置了 hermes claw migrate 命令，支持一键把 OpenClaw 的所有资产迁移过去。

也就是说，如果你是 OpenClaw 用户，迁移成本极低。

但迁移不等于必须迁移——两个系统的设计哲学不同，要根据实际需求选择。

  • SOUL.md（人格文件）
  • MEMORY.md 和 USER.md 中的记忆条目
  • 用户创建的 Skill（迁移至 ~/.hermes/skills/openclaw-imports/）
  • 命令白名单
  • 消息平台配置
  • API Key（Telegram、OpenRouter、OpenAI、Anthropic、ElevenLabs 等）
  • TTS 素材和工作区配置（--workspace-target 选项）

定位差异：

  1. OpenClaw 像一个精密可控的通信枢纽，你掌控一切行为规则。
  1. Hermes 像一个自主成长的认知系统，规则由 Agent 从经验中自动提炼。

五、优缺点对比

Hermes Agent

优势：

  • 自改进学习循环，越用越好，不依赖用户手动维护规则，门槛极低
  • 三层记忆系统，科学分层，FTS5 按需检索避免上下文膨胀
  • Skill 自动创建和进化，有机成长，高度个性化
  • 用户控制优先，无内容审查，模型可自由切换
  • 数据完全本地，隐私有保障
  • MIT 开源，27k Stars 社区活跃，增速极快

劣势：

  • 生态不如 OpenClaw 成熟，社区 Skill 数量差距较大
  • 自动生成的 Skill 和记忆可能不准确，需定期人工审查，有维护成本
  • 无自动过期机制，记忆积累后需手动清理，存在"记忆污染"风险
  • 对底层 LLM 能力依赖高，模型弱则自改进效果打折
  • 最多 3 个并发子 Agent，重度编排场景有限制
  • 暂无原生浏览器控制能力

OpenClaw

优势：

  • 平台支持最广，23+ 消息平台（含飞书、WeChat、iMessage、LINE 等）
  • 配置精准可控，用 SOUL.md 精确定义行为，没有"黑箱自改进"的不确定性
  • 伴侣 App 生态成熟（macOS/iOS/Android），Live Canvas、Voice Wake 等原生体验
  • 企业级安全：DM 配对、沙箱隔离、命令白名单、细粒度权限控制
  • 浏览器控制（CDP），节点系统（摄像头/屏幕录制/位置）
  • Skill 生态规模大，ClawHub 社区活跃

劣势：

  • 需要用户主动维护，SOUL.md、记忆、Skill 全靠人写人管，有学习成本
  • 没有自改进机制，行为能力上限取决于用户维护质量
  • 跨会话记忆依赖手动写 MEMORY.md，不够智能

选错了会怎样？三个常见陷阱

⚠️

陷阱 1：看功能多就选 OpenClaw → 现实：你用不到 80% 的功能，反而要为这些功能的复杂度买单。

⚠️

陷阱 2：Hermes 太新不敢用 → 现实：底层团队是分布式系统硬核背景（Jeffrey Quesnelle、Karan Malhotra、Teknium），稳定性不弱。小号先试一个月再评估。

⚠️

陷阱 3：选了一个就不能用另一个 → 现实：两者 Skill 生态互通（都遵循 agentskills.io 标准），hermes claw migrate 一键迁移。完全可以混用——这反而是最优解。

各自的"不能做"（比"优缺点"更实用）

Hermes 不能做的：

  • 多人协作 / 权限隔离 / 审计追踪（企业级缺失）
  • 浏览器自动化（没有原生 CDP 支持）
  • iMessage 接入（OpenClaw 独占）
  • 超过 3 个子 Agent 并发（轻量场景够用，重量级受限）

OpenClaw 不能做的：

  • 从使用中自我进化（静态 Skill，不会自己变聪明）
  • 飞书 / 企业微信原生接入（Hermes v0.6.0 独占）
  • 零配置开箱即用（SOUL.md + MEMORY.md 手动维护门槛高）
  • 严格的安全审计（2026 年初曝出 400+ 恶意插件 + 多个关键 CVE，135K+ 实例暴露在公网）

八、架构对比

架构核心差异：

  • Hermes 以 "学习循环" 为核心，数据库驱动，自底向上的自动化，重点是 Agent 怎么从经验中学习。
  • OpenClaw 以 "Gateway 控制平面" 为核心，文件驱动，自顶向下的配置化，重点是 把多平台消息高效路由到 Agent。

两者并不互斥。

从技术思路上看，完全可以借鉴 Hermes 的三层记忆和 FTS5 召回思路，来改进 OpenClaw 现有的 Markdown 文件记忆体系——这也是 Hermes 对 OpenClaw 用户最有价值的参考方向。

Hermes 架构（认知系统驱动）

用户输入（CLI / Telegram / Discord / ...）
    ↓
Agent 主循环
    ↓
学习循环（Self-Harnessing Loop）
    ├── FTS5 历史召回
    ├── 持久记忆读取
    └── Skill 加载
    ↓
工具执行（40+ 内置 + MCP 6,000+ 扩展）
    ↓
结果处理
    ├── 策划记忆 → 写入 SQLite
    ├── 自主创建/更新 Skill
    └── 用户建模（Honcho，可选）

OpenClaw 架构（通信枢纽驱动）

消息平台（23+ 渠道）
    ↓
Gateway（WebSocket 控制平面 ws://127.0.0.1:18789）
    ├── 会话管理
    ├── 渠道路由
    ├── Cron 调度
    └── 工具注册
    ↓
Pi Agent（RPC 模式，流式工具调用）
    ├── SOUL.md / AGENTS.md 注入
    ├── Skill 加载
    └── 工具调用
    ↓
节点系统（macOS / iOS / Android）
    └── system.run / camera / canvas / location

九、下一步：你可以怎么做

看完这份文档，不同背景的读者应该走不同的路径。

🧑💻 如果你是个人开发者，从未用过这类 Agent

  1. 最低投入方案：一台 Mac 或一台 $5 VPS，跑下面这条命令：
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
  1. 接 Telegram 或 CLI，不要一上来就接工作微信（避免封号风险）
  1. 用 30 天，不追求立刻出效果。前两周是 Hermes 学你的风格，后两周开始看到复利

🦞 如果你已经是 OpenClaw 用户

  1. 不要急着迁移。先评估迁移成本：
hermes claw migrate --dry-run

这条命令只预览不执行，能看清 SOUL.md / MEMORY.md / Skills / API Key 各有多少会被搬过去。

  1. 混合使用比迁移更香：OpenClaw 继续做你已经跑顺的多账号运营，Hermes 单独起一个实例做深度工作（代码、文档、分析），用 sessions_spawn 机制让两者互调
  1. 留意 OpenClaw 的安全公告（CVE-2026-25253 等），如果你的部署暴露在公网，优先升级 / 加防火墙

👥 如果你想在团队内推

  1. 先别推。Hermes 当前缺失权限管理、审计追踪、多人协作——这是企业级刚需
  1. 有多少 Skill 沉淀下来
  2. 有没有人出现"技能库污染"问题
  3. 团队共享 Skill 的需求是否强烈
  1. 如果验证下来确实有价值，再看 Hermes 是否演进出企业版，或者用 OpenClaw 做团队壳 + Hermes 做每个人的内核
