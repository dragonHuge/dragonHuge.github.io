1.ThreadLocal有什么用？

通常情况下，我们创建的变量是可以被任何一个线程访问并修改的。如果想实现每一个线程都有自己的专属本地变量该如何解决呢？

JDK 中自带的ThreadLocal类正是为了解决这样的问题。 ThreadLocal类主要解决的就是让每个线程绑定自己的值，可以将ThreadLocal类形象的比喻成存放数据的盒子，盒子中可以存储每个线程的私有数据。

如果你创建了一个ThreadLocal变量，那么访问这个变量的每个线程都会有这个变量的本地副本，这也是ThreadLocal变量名的由来。他们可以使用 get() 和 set() 方法来获取默认值或将其值更改为当前线程所存的副本的值，从而避免了线程安全问题。

ThreadLocal是作为Thread的成员变量使用的，用于存储线程局部变量。

再举个简单的例子：两个人去宝屋收集宝物，这两个共用一个袋子的话肯定会产生争执，但是给他们两个人每个人分配一个袋子的话就不会出现这样的问题。如果把这两个人比作线程的话，那么 ThreadLocal 就是用来避免这两个线程竞争的

2.如何使用ThreadLocal？

使用ThreadLocal时，通常需要执行以下步骤：

  1. 创建ThreadLocal对象：首先，需要创建一个ThreadLocal对象，用于存储线程本地变量的副本。

```Java private static ThreadLocal<String> threadLocal = new ThreadLocal<>(); // 一般设置为静态变量 ```

  1. 设置线程本地变量的值：可以通过ThreadLocal的set方法设置线程本地变量的值。

```Java threadLocal.set("value"); ```

  1. 获取线程本地变量的值：可以通过ThreadLocal的get方法获取线程本地变量的值。

```Java String value = threadLocal.get(); ```

  1. 移除线程本地变量的值（可选）：在不需要使用线程本地变量时，可以调用ThreadLocal的remove方法将其从当前线程中移除。

```Java threadLocal.remove(); ```

此外，为了防止内存泄漏，建议在不需要使用线程本地变量时及时调用remove方法移除其值。

public class ThreadLocalTest {
    private List<String> messages = Lists.newArrayList();

    public static final ThreadLocal<ThreadLocalTest> holder = ThreadLocal.withInitial(ThreadLocalTest::new);// 初始化ThreadLocal

    public static void add(String message) {
        holder.get().messages.add(message);
    }

    public static List<String> clear() {
        List<String> messages = holder.get().messages;
        holder.remove();

        System.out.println("size: " + holder.get().messages.size());
        return messages;
    }

    public static void main(String[] args) {
        ThreadLocalTest.add("一枝花算不算浪漫");
        System.out.println(holder.get().messages);
        ThreadLocalTest.clear();
    }
}

需要注意的是，ThreadLocal对象一般声明为静态变量，可以确保多个线程可以共享同一个ThreadLocal实例。

因为ThreadLocal的作用是为每个线程提供一个独立的变量副本，而不同线程之间无法共享变量的值。

因此，将ThreadLocal对象声明为静态变量可以使得多个线程在访问同一个ThreadLocal实例时，能够获得各自独立的变量副本，而不会相互干扰。

💡 Q1：为什么不会相互干扰，不是访问同一个实例吗？

虽然多个线程访问同一个ThreadLocal实例，但每个线程实际上都拥有该实例的一个副本。这意味着每个线程可以独立地修改自己的副本，而不会影响其他线程的副本。

这是因为ThreadLocal对象内部维护了一个Map，其中键是线程，值是变量的副本。

当一个线程访问ThreadLocal对象时，实际上是在访问自己线程对应的Map中的值，而不是其他线程的值。这样就保证了线程之间的变量副本是相互独立的，不会相互干扰。

3.ThreadLocal原理、与ThreadLocalMap的区别

每个线程都只有一个ThreadLocalMap实例，用于存储该线程所有使用ThreadLocal作为键的变量。

  1. 最终的变量是放在了当前线程的 ThreadLocalMap 中，并不是存在 ThreadLocal 上。

ThrealLocal 类中可以通过Thread.currentThread()获取到当前线程对象后，直接通过getMap(Thread t)可以访问到该线程的ThreadLocalMap对象。

  1. 每个Thread中都具备一个ThreadLocalMap，而ThreadLocalMap可以存储以ThreadLocal为 key ，Object 对象为 value 的键值对。

💡 Q1：用的不是同一个ThreadLocal实例吗，为啥可以将其作为键？

虽然多个线程可以共享同一个ThreadLocal实例，但是每个线程在使用ThreadLocal实例时，都会创建自己的ThreadLocalMap实例，并且ThreadLocalMap中的键值对是线程私有的。

这样就保证了每个线程对应的ThreadLocal实例在ThreadLocalMap中作为键是独立的，不会相互干扰。

因此，尽管多个线程共享同一个ThreadLocal实例，但在每个线程的ThreadLocalMap中，该ThreadLocal实例对应的键值对是各自独立的，不会产生冲突。

💡 比如我们在同一个线程中声明了两个 ThreadLocal 对象的话， Thread内部都是使用仅有的那个ThreadLocalMap 存放数据的，ThreadLocalMap的 key 就是 ThreadLocal对象，value 就是 ThreadLocal 对象调用set方法设置的值。

ThreadLocal数据结构：

  • ThreadLocal是一个抽象类，用于创建线程局部变量；
  • 而ThreadLocalMap是ThreadLocal的内部类，用于实际存储线程局部变量的键值对。

4.ThreadLocal内存泄漏问题是怎么导致的？

  1. ThreadLocalMap 中使用的 key 为 ThreadLocal 的弱引用，而 value 是强引用。

所以，如果 ThreadLocal 没有被外部强引用的情况下，在垃圾回收的时候，key 会被清理掉，而 value 不会被清理掉。

  1. 这样一来，ThreadLocalMap 中就会出现 key 为 null 的 Entry。

假如我们不做任何措施的话，value 永远无法被 GC 回收，这个时候就可能会产生内存泄露。

  1. 解决方法：调用 set()、get()、remove() 方法的时候，会清理掉 key 为 null 的记录

ThreadLocalMap 实现中已经考虑了这种情况，在调用 set()、get()、remove() 方法的时候，会清理掉 key 为 null 的记录。使用完 ThreadLocal方法后最好手动调用remove()方法
