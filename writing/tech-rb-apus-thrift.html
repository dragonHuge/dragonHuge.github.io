apus thrift Server / Client 规则

2026-07-09"本地沉淀 · 风控工程知识库"

本文是工程规则（团队约定 + 踩坑结论），不是入门教程： 适合「已经知道要做什么，只想知道怎么做才不出事」的场景。

1. 适用范围

风控服务对外暴露 thrift RPC（Server），以及风控服务 / Spark 离线 / BVT 脚本调下游 thrift（Client）。

不覆盖：HTTP API（不用）、gRPC（不用）、Dubbo（不用）。

2. 版本 / 依赖

坐标备注
com.example:apus-serverServer 侧
com.example:apus-clientClient 侧
com.example:apus-registry-zookeeperZK 服务注册/发现
com.example:公司-common-zookeeperZKFacade / EnvironmentType（单 ZK + ZONE 用）
org.apache.thrift:thriftapus 编译期依赖的公司 fork（含 TBinaryProtocol$Factory(long,long)）

版本号通过 ${apusVersion} 在根 pom 统一管理；新项目对齐同版本。

thrift IDL 单独 module（如 ${artifactPrefix}-thrift），不在 reactor 内，独立发包，避免循环依赖。

3.1 Application（Spring Boot main）

    public static void main(String[] args) {
        SpringApplication.run(${serviceApplicationClass}.class, args);
    }

3.2 Server（ApplicationRunner 启动 apus）

铁律：Bootstrap.start() 必须在 ApplicationRunner.run() 里，不能写在 main() —— 否则 Spring 还没装配完 BeanConfiguration，apus 拿不到 RPC impl。

@Slf4j
public class ${apusServerClass} implements ApplicationRunner {

    @Value("${apus.port}")
    private int port;

    private final Environment env;
    private final ${serviceImplClass} serviceImpl;

    public ${apusServerClass}(Environment env, ${serviceImplClass} serviceImpl) {
        this.env = env;
        this.serviceImpl = serviceImpl;
    }

    @Override
    public void run(ApplicationArguments args) throws Exception {
        String zkEnv = resolveZkEnv();
        if (isBlank(zkEnv)) {
            PerfCounter.setMeterCount("${metricPrefix}.startup.zk_env_missing", 1);
            log.error("zkEnv is empty, shutting down");
            System.exit(1);
        }

        EnvironmentType currentEnv = EnvironmentType.valueOf(zkEnv);
        ServerConfig<${serviceImplClass}> config = new ServerConfig.Builder<>(${serviceImplClass}.class)
                .registryFactory(new ZookeeperRegistryFactory<>(${serviceImplClass}.class,
                        () -> ZKFacade.getZKSettings().getZKServers(currentEnv)))
                .port(port)
                .threadPoolsize(2000)
                .build();

        Bootstrap<${serviceImplClass}> bootstrap = new Bootstrap<>(config, serviceImpl);
        try {
            bootstrap.start();
        } catch (Exception e) {
            PerfCounter.setMeterCount("${metricPrefix}.startup.apus_failed", 1);
            log.error("bootstrap failed, zkEnv={}, port={}", zkEnv, port, e);
            throw e;
        }
        PerfCounter.setMeterCount("${metricPrefix}.startup.apus_started", 1);
        log.info("${apusServerClass} started, zkEnv={}, port={}", zkEnv, port);
    }

    private String resolveZkEnv() {
        // staging: 直接读 zookeeper.host.staging
        // 生产: 读 env[ZONE] -> zookeeper.host.{zone}
        // ...
    }
}

完整 resolveZkEnv 实现见 recipes/apus-thrift-server-client/templates/server/${apusServerClass}.java.tpl。

3.3 ServiceImpl（thrift Iface 实现）

@Slf4j
public class ${serviceImplClass} implements ${ServiceName}.Iface {

    private static final int BATCH_LIMIT = 100;

    private final ${dependencyA} depA;
    private final ${dependencyB} depB;

    public ${serviceImplClass}(${dependencyA} depA, ${dependencyB} depB) {
        this.depA = depA;
        this.depB = depB;
    }

    @Override
    public ${RespType} ${methodName}(${ReqType} r) throws ${ExceptionType} {
        long start = System.currentTimeMillis();
        try {
            // 1) 入参校验
            RequestValidator.requireNonEmpty(r.get${BusinessKey}(), "${businessKeyField}");
            // 2) 业务逻辑（可调下游）
            try {
                return doWork(r);
            } catch (${ExceptionType} e) {
                if (e.getCode() == 50301) {  // 下游不可用 → fail-open
                    PerfCounter.setMeterCount("${metricPrefix}.service.${methodName}.fail_open", 1);
                    return default${RespType}();
                }
                PerfCounter.setMeterCount("${metricPrefix}.service.${methodName}.failed", 1);
                throw e;
            }
        } finally {
            PerfCounter.setTimerValue("${metricPrefix}.service.${methodName}.all",
                System.currentTimeMillis() - start);
        }
    }
}

4. Client 标准骨架（BVT 脚本 / 下游调用）

private static ${ServiceName}.Iface newRpcClient(String zkEnvName) {
    EnvironmentType env = EnvironmentType.valueOf(zkEnvName);
    ClientConfig<${ServiceName}.Iface> cfg =
            new ClientConfig.ClientConfigBuilder<>(${ServiceName}.Iface.class)
                    .registryFactory(new ZookeeperRegistryFactory<>(${ServiceName}.Iface.class,
                            () -> ZKFacade.getZKSettings().getZKServers(env)))
                    .build();
    return new SwiftClientManager<>(cfg).createClient(3000L);
}

调用：

${ServiceName}.Iface client = newRpcClient("STAGING");
${RespType} resp = client.${methodName}(new ${ReqType}().set${BusinessKey}("..."));

5. 配置项

key来源说明
apus.portyml服务监听端口
threadPoolsize代码内业务线程池大小，默认 2000
ZK env 名maven profile 注入 + ${ZONE} 环境变量多 region 路由

ZK env 解析逻辑：

  • env=staging：直接读 zookeeper.host.staging
  • 其他：读 ${ZONE} 环境变量（c3/sgp/ind/rus/eur）→ zookeeper.host.{zone}
  • 都缺：zookeeper.default

6. 监控与日志

  • 必备指标：
    • ${metricPrefix}.startup.apus_started / apus_failed
    • ${metricPrefix}.startup.zk_env_missing / zone_missing / zone_unmapped
    • ${metricPrefix}.service.{method}.all (timer)
    • ${metricPrefix}.service.{method}.failed (meter)
    • ${metricPrefix}.service.{method}.fail_open (meter，下游降级)
  • 日志：启动日志固定 ${apusServerClass} started, zkEnv={}, port={}，便于运维排查

7. 常见踩坑

7.1 🔴 Bootstrap.start() 写在 main()

后果：Spring 还没装配 RPC impl，apus 直接拿 null，启动后调用 NPE。 正确：ApplicationRunner.run() 里启动（§3.2）。

7.2 🔴 ${ZONE} 环境变量丢失但 env != staging

后果：生产环境跑 staging 配置或者根本起不来。 正确：resolveZkEnv 在 ${ZONE} 缺失时 System.exit(1)，触发上游 K8s 重拉。

7.3 🟠 thrift IDL 改了但 Server / Client 没同步

后果：序列化错位，运行时报 TProtocolException。 正确：thrift module 改后先发包，再让 service / client 模块更新版本号引用。

7.4 🟠 RequestValidator 漏掉某字段

后果：业务方传错参数，Server 内部 NPE / 数据脏。 正确：每个 thrift 方法首行必须有 requireNonEmpty / requireBatchLimit。

7.5 🟢 下游 fail-open 误用

fail-open 只在"下游短暂不可用 + 业务允许返回默认值"时用（如缓存查不到返回未命中）。 写操作 / 强一致场景不能 fail-open，应直接抛错。

8. 边界

  • Spring Boot 启动顺序：springboot.md §3
  • Talos 异步通知：调用方写完 Redis 后 producer.asyncSend()，见 talos.md §4
  • fail-open 来源：Redis 不可用 → redis.md §6
