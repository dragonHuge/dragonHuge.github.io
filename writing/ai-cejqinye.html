Claude code 好用技巧

2026-05-08 · 飞书原文 ↗

核心概念

CLAUDE.md — 项目记忆

Claude Code 的"大脑"，决定每次对话的行为基线。

层级

路径

作用域

全局

~/.claude/CLAUDE.md

所有项目通用规则

项目根

./CLAUDE.md

当前项目专属约束

子目录

./src/CLAUDE.md

特定模块的补充规则

最佳实践：

  • 用 /init 自动生成项目级 CLAUDE.md
  • 把团队规范、代码风格、架构约束写进去
  • 每个人的 CLAUDE.md 应该不一样——你的工作习惯就是你的竞争力

权限模型

模式

说明

适用场景

默认

每次文件写入/命令执行都要确认

生产环境、不熟悉的代码库

--dangerously-skip-permissions

跳过所有确认

信任环境快速迭代

--allowedTools

白名单精细控制

半自动化，只放行安全操作

MCP（Model Context Protocol）

Claude Code 支持通过 MCP Server 扩展能力边界：

# 添加 MCP Server
claude mcp add <name> <command>

# 常见 MCP
claude mcp add playwright npx @anthropic/mcp-playwright
claude mcp add postgres npx @anthropic/mcp-postgres

配置文件位置：.claude/settings.json

命令速查

启动参数（CLI）

命令

说明

claude

启动交互式 REPL

claude "query"

带初始问题启动对话

claude -p "query"

Pipe 模式——非交互，输出纯文本，可管道串联

claude --dangerously-skip-permissions

跳过所有权限确认（⚠️ 适合信任场景快速迭代）

claude --resume

恢复上次会话继续

claude --model <model>

指定模型启动

claude --allowedTools "tool1,tool2"

限定可用工具白名单

claude --max-turns N

限制最大轮次（自动化脚本用）

claude --output-format json

JSON 输出（程序化集成用）

管道用法示例：

cat bug.log | claude -p "分析这个报错，给出修复方案"
git diff | claude -p "review 这个改动"

实战技巧

模型配置

  • 记得把 context window 配到 1M（200K 默认太小，长文件会被截断）
  • Opus 用于复杂推理/架构设计，Sonnet 用于日常编码——按任务切

多实例并行

开多个终端窗口各跑一个 claude 实例：

  • 配合 git worktree 一个修 bug、一个加 feature，互不干扰
  • 用 /rename 给每个会话命名，避免混乱

图片 + 截图

  • 直接在终端粘贴图片，Claude 能看懂并分析
  • 调试 UI 时截图贴进去比描述高效 10 倍

CDP + Playwright

  • Claude Code 可以通过 Playwright MCP 直接操控浏览器
  • 写前端 → 自动打开页面 → 截图验证 → 修复问题，全自动闭环
  • npx playwright codegen 录制交互生成测试代码

自动化串联

# 批量处理文件
find . -name "*.ts" | head -5 | xargs -I {} claude -p "review {}"

# CI 集成
claude -p --max-turns 3 "运行测试并修复失败的用例"
  • Prompt Engineering 解决「怎么对模型说」
  • Context Engineering 解决「让模型在这一轮看到什么」。
  • Harness Engineering 解决「整套系统怎么运行、怎么持久化、怎么验证、怎么兜底」

类比（Beren Millidge 2023）：裸 LLM = 没有 RAM/磁盘/IO 的 CPU，上下文窗口是内存，外部数据库是磁盘，工具集是设备驱动，Harness 就是让这台机器持续跑起来的操作系统。

Harness 回答的是一个工程问题：怎样把一个无状态、会推理的模型，变成一个能持续交付结果的系统。
