Q3：Error：Unable to connect.Is the computer able to access the url？

Case1：WSL DNS解析崩溃，ping不通任何域名

首先自测下，opencode启动时是否有如下报错（若无，则看Case2）：

ERROR 2026-02-28T02:18:41 +207ms service=models.dev error=Unable to connect. Is the computer able to access the url? Failed to fetch models.dev

ERROR 2026-02-28T02:18:42 +123ms service=models.dev error=Was there a typo in the url or port? Failed to fetch models.dev

解决方法： 把阿里 + 腾讯的公共 DNS 地址，写入新的 /etc/resolv.conf 文件里。

sudo rm /etc/resolv.conf echo -e "nameserver 223.5.5.5\nnameserver 119.29.29.29" | sudo tee /etc/resolv.conf

Case2：无法连内网模型URL

自测：测试wsl网络是否连通内网，ping一下试试：ping 内部主机

解决方法：

  1. nano /etc/resolv.conf

粘贴下边的配置：
nameserver [内网IP]
search [内部链接]
nameserver 8.8.8.8
nameserver 1.1.1.1
  2. sudo chattr -i /etc/resolv.conf  -- 解除文件的「不可修改」锁定
sudo chmod 644 /etc/resolv.conf
sudo nano /etc/resolv.conf
  1. wsl配置中「网络模式」改为 镜像模式 Mirrored

Q6：安装OMO，且想保留原生Plan、Build SubAgent

omo：oh-my-opencode。

安装 oh-my-opencode 后，默认可能会替换原生的 plan 和 builder Agent。如果你希望保留这两个原生 Agent（例如用于执行轻量级任务以节省 Token），可以通过修改配置文件来实现。

在 ~/.config/opencode/oh-my-opencode.json 文件的第一层级中添加以下配置：

{
  "sisyphus_agent": {
    "default_builder_enabled": true,
    "replace_plan": false
  }
}

参考：https://www.opencodecn.com/docs/best-practices/oh-my-opencode-keep-native-agents。

Q9：Invalid argument for parameter maxOutputTokeens: maxOutputTokens must be >= 1

原因：omo 某一版本 BUG 导致。

解决方案：

方案 1：在 opencode.json 模型配置中显式添加 "limit": {"context": 1000000, "output": 128000}，重启并新开 session。

方案 2：可以换个可用的模型，把这句话丢给它：

标准解决方法：https://github.com/anomalyco/opencode/issues/21522

方案 A（限自定义模型，且要覆盖所有 agent 用到的模型才有效）：
如果你用的是自定义 provider 里声明的模型，可以在 opencode.json 的对应模型
条目下加 limit.output，让 oh-my-openagent 读到正确值而不是缓存里的 0：
{
  "provider": {
    "your-provider": {
      "models": {
        "your-model-id": {
          "limit": {
            "output": 4096,
            "context": 128000
          }
        }
      }
    }
  }
}
注意：oh-my-openagent 会启动多个 agent，每个 agent 用不同模型。
必须给所有涉及的模型都加上 limit.output，漏一个就还会触发。

Q14：飞书 MCP 超时或授权 7 天过期后无法使用

原因：飞书 MCP 的 OAuth 授权有效期仅 7 天，过期后连接失败；部分用户还遇到 MCP 调用超时问题。

解决方案：

  • 方案 1：切换到 feishu mcp pro，授权有效期更长、功能更强
  • 方案 2：直接用 Skill（feishu cli）替代 MCP，稳定性更好（使用指南）
来自 风控小龙虾🦞

Q15：opencode 读不了飞书文档中的图片

原因：默认模型不支持多模态输入，无法解析文档内嵌图片。

解决方案：

  • 方案 1：切换到支持多模态的模型（如 mimo-v2 系列）
  • 方案 2：使用 use mcp "feishu-mcp" 命令通过 MCP 读取飞书文档内容（含图片描述）
来自 风控小龙虾🦞
