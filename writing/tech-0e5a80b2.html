3.单例模式

1.简介

这种模式涉及到一个单一的类，该类负责创建自己的对象，同时确保只有单个对象被创建。这个类提供了一种访问其唯一的对象的方式，可以直接访问，不需要实例化该类的对象。

单例模式是一种创建型设计模式，它确保一个类只有一个实例，并提供了一个全局访问点来访问该实例。

注意：

  • 1、单例类只能有一个实例。—— 将构造函数用private修饰
  • 2、单例类必须自己创建自己的唯一实例。
  • 3、单例类必须给所有其他对象提供这一实例。—— static关键字

2.优缺点 & 使用场景

  1. 优点：
  1. 在内存里只有一个实例，减少了内存的开销，尤其是频繁的创建和销毁实例（比如管理学院首页页面缓存）。
  1. 避免对资源的多重占用（比如写文件操作）。
  1. 缺点：

没有接口，不能继承，与单一职责原则冲突，一个类应该只关心内部逻辑，而不关心外面怎么样来实例化。

  1. 使用场景：
  • 1、要求生产唯一序列号。
  • 2、WEB 中的计数器，不用每次刷新都在数据库里加一次，用单例先缓存起来。
  • 3、创建的一个对象需要消耗的资源过多，比如 I/O 与数据库的连接等。

注意事项：getInstance() 方法中需要使用同步锁 synchronized (Singleton.class) 防止多线程同时进入造成 instance 被多次实例化。

简单实现：

1.创建一个 Singleton 类。

public class SingleObject {
 
   //创建 SingleObject 的一个对象
   private static SingleObject instance = new SingleObject();
 
   //让构造函数为 private，这样该类就不会被实例化
   private SingleObject(){}
 
   //获取唯一可用的对象
   public static SingleObject getInstance(){
      return instance;
   }
 
   public void showMessage(){
      System.out.println("Hello World!");
   }
}

2.获取单例对象：

public class SingletonPatternDemo {
   public static void main(String[] args) {
 
          //不合法的构造函数
      //编译时错误：构造函数 SingleObject() 是不可见的
      //SingleObject object = new SingleObject();
 
          //获取唯一可用的对象
      SingleObject object = SingleObject.getInstance();
 
         //显示消息
      object.showMessage();
   }
}

3.单例模式的6种写法：

1.饿汉模式

在类加载时就完成了初始化，所以类加载较慢，但获取对象的速度快。

这种方式基于类加载机制避免了多线程的同步问题，但是也不能确定有其他的方式（或者其他的静态方法）导致类装载，这时候初始化instance显然没有达到懒加载的效果。

public class Singleton {  
     private static Singleton instance = new Singleton(); // 直接静态创建  
     private Singleton (){
     }
     public static Singleton getInstance() {  
     return instance;  
     }  
 }
2.懒汉模式(线程不安全)

申明了一个静态对象，在用户第一次调用时初始化，虽然节约了资源，但第一次加载时需要实例化，反映稍慢一些，而且在多线程不能正常工作。

public class Singleton {  
      private static Singleton instance;  
      private Singleton (){
      }   
      public static Singleton getInstance() {  
      if (instance == null) {  // 首次加载才会初始化
          instance = new Singleton();  
      }  
      return instance;  
      }  
 }
3.懒汉模式(线程安全)

使用synchronized关键字修饰getInstance()。

每次调用getInstance方法时都需要进行同步，造成不必要的同步开销，而且大部分时候我们是用不到同步的，所以不建议用这种模式。

public class Singleton {  
      private static Singleton instance;  
      private Singleton (){
      }
      //  synchronized关键字修饰，达到同步目的
      public static synchronized Singleton getInstance() {   
      if (instance == null) {  
          instance = new Singleton();  
      }  
      return instance;  
      }  
 }
4.双重校验锁实现对象单例（线程安全）：

volatile关键字修饰单例，确保多线程环境下对其的修改能够立即被其他线程可见。

public class Singleton {
    private volatile static Singleton uniqueInstance;
    private Singleton() {
    }

    public  static Singleton getUniqueInstance() {
       //先判断对象是否已经实例过，没有实例化过才进入加锁代码
        if (uniqueInstance == null) { // 第一次校验，排除不必要的同步
            //类对象加锁
            synchronized (Singleton.class) {
                if (uniqueInstance == null) {
                    uniqueInstance = new Singleton();
                }
            }
        }
        return uniqueInstance;
    }
}

这种写法在getSingleton方法中对singleton进行了两次判空：

  • 第一次是为了不必要的同步。

这是指，单例已经创建，此时大量的线程来访问的话，就可以直接将这些线程拒绝掉。

  • 第二次是在singleton等于null的情况下才创建实例。

这是指，在单例未创建时，此时涌进大量线程，但此时只能有一个进行new操作，因此在使用同步锁排除掉并发问题后，再进行一次判空。

uniqueInstance 采用 volatile 关键字修饰也是很有必要的， uniqueInstance = new Singleton(); 这段代码其实是分为三步执行：

  1. 为 uniqueInstance 分配内存空间
  1. 初始化 uniqueInstance
  1. 将 uniqueInstance 指向分配的内存地址

但是由于 JVM 具有指令重排的特性，执行顺序有可能变成 1->3->2。指令重排在单线程环境下不会出现问题，但是在多线程环境下会导致一个线程获得还没有初始化的实例。例如，线程 T1 执行了 1 和 3，此时 T2 调用 getUniqueInstance() 后发现 uniqueInstance 不为空，因此返回 uniqueInstance，但此时 uniqueInstance 还未被初始化。

  1. 详细分析：
  1. synchronized (Singleton.class) { ... }：这是一个同步块，使用 Singleton.class 对象作为锁。这意味着只有一个线程能够同时进入这个同步块。
  1. if (uniqueInstance == null) { ... }：在同步块中，首先检查 uniqueInstance 是否为 null。这是第一次检查，用于避免不必要的同步开销。如果 uniqueInstance 不为 null，说明已经有其他线程创建了 Singleton 实例，这时就不需要再进入同步块。
  1. uniqueInstance = new Singleton();：如果 uniqueInstance 为 null，说明当前线程是第一个尝试创建 Singleton 实例的线程。在同步块内部，创建新的 Singleton 实例，并将其赋值给 uniqueInstance 变量。由于这个操作是原子性的，因此其他线程无法看到未完全初始化的实例。

通过使用双重检查锁定，可以避免在大多数情况下对同步块进行加锁，从而提高了性能。只有在 uniqueInstance 为 null 且需要创建实例时，才会进入同步块，确保了线程安全性。

  1. 如果不使用volatile，会出现什么情况？

在没有 volatile 的情况下，一个线程可能在写入 uniqueInstance 的值后，其他线程无法立即看到修改后的值，从而可能导致其他线程在进行第二次检查时仍然认为 uniqueInstance 为 null，从而导致多个实例被创建。

5.静态内部类单例模式(推荐)

此时将该实例定义在静态内部类中。

  1. 第一次加载Singleton类时并不会初始化sInstance，实现延迟加载
  1. 只有第一次调用getInstance方法时虚拟机类加载SingletonHolder 并初始化sInstance 。

只有在第一次调用getInstance()方法时才会初始化单例实例，节省了内存空间。

这样不仅能确保线程安全也能保证Singleton类的唯一性，所以推荐使用静态内部类单例模式。

静态内部类在类加载时会被初始化，由JVM来保证线程安全性，因此无需额外的同步措施。

public class Singleton { 
    private Singleton(){
    }
      public static Singleton getInstance(){ // 获取单例的方法
        return SingletonHolder.sInstance;  
    }  
    private static class SingletonHolder {  // 静态内部类
        private static final Singleton sInstance = new Singleton();  
    }  
}

💡 Q1：为什么只有在第一次调用时才会加载，不是使用static修饰了吗？

静态内部类中的静态成员变量只有在类第一次被加载时才会初始化，并且只会被加载一次。这是因为静态内部类的静态成员变量在类加载时就会被初始化，而类加载是由类加载器（ClassLoader）负责的，保证了线程安全。

而且静态内部类的加载是在外部类被加载的时候才会进行，所以实现了延迟加载的效果，只有在需要时才会初始化静态内部类，进而初始化单例对象。

6.枚举类实现单例模式

是的，单例模式可以使用枚举类实现。

在Java中，枚举类的每个枚举常量都是单例的，因此使用枚举类实现单例模式是一种简单且线程安全的方式。

以下是使用枚举类实现单例模式的示例：

public enum Singleton {
    INSTANCE; // 定义单例对象
    
    // 示例方法
    public void doSomething() {
        System.out.println("Singleton method called");
    }
}
