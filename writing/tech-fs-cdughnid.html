7.UDF开发 SOP总结 & UDF开发记录

2026-11-19"飞书工作积累" · 飞书原文 ↗

2025-03-19 发现一篇较好的教程：Hive UDF开发手册。

需求背景

💡

UDF(User Defined Function)：自定义函数，执行某些特定任务(如：数据工厂的数据解密）。

  • 在数据工厂复杂场景的数据检索中，简单的select语句无法满足需求，这时我们就可以根据自身需求自定义一些函数，在数据查询时就做好数据解析。

  • 若无UDF，做法是：从Hive拉取ip -> 撰写脚本遍历解析ip
  • 若有UDF IpCity()，做法是：select IpCity(ip) from tmp_table即可。

本次开发需求：

数据工厂中的risk_risk.风险事件表表中，有敏感字段做了加密处理。

riskcontrol_phone_locV2(phone)用V3即可。

💡

V2版本改进点：

  1. 国内手机号返回值新增"中国"，以便区分国内外手机号。
  1. 国内数据源idf文件已更新为最新的202504版。
  1. 国内手机号：
    • 大陆：兼容+86、0086、+0086。如：008613669130993、+8613669130993、13669130993、+008613669130993都可以识别。
    • 港澳台：兼容“+区号、00区号、+00区号”。如：+85268476749、0085268476749、+0085268476749.
  2. 国外手机号：兼容"+国家代码、00国家代码、+00国家代码"的格式。
  1. 国外手机号新增合法性校验。
  • 返回值类型：List<String>
  • 国内手机号：[中国,省,市]；
  • 国外手机号：[国家]，并做手机号合法性校验，非法则返回：['error','错误明细']。其中错误明细有如下枚举：
  • 1. FormatError // 一方面：未通过正则校验("^\\+\\d+$")；另一方面：未通过GoogleJar的格式校验
2. MissingRegionCode // 非法区号（由于数据不全，部分合法区号此Jar包无法解析）
3. NotActiveNumber // 根据区号，且用该国家的手机号规则校验手机号时，校验失败
  • 补充：
    • 国内手机号：若查不出来归属地，则返回值为：['中国']。
    • 国外手机号：若手机号格式校验正确且查不出来归属地，则返回值为['']。
  • 详情文档：@2025-04-09 手机号归属地UDF
CREATE TEMPORARY FUNCTION riskcontrol_phone_loc AS 'com.example.udf.risk.PhoneLocInfoV2';
select riskcontrol_phone_loc('+008613669130993')

与1.0相比，手机号归属地填补率能达到100%。

riskcontrol_phone_locV3(phone)

V3 效果评测：@v3版手机归属地udf评估

改进原因：

2.0中，没有对输入特殊值做过滤(如：""、"null"、\n、\t等)，导致全量查询时，脏数据导致UDF解析error。

改进点：

  • 手机号归属地idf资源更新到20250624版本。
  • 特殊值过滤，新增错误明细 "InvalidParameter"。

UDF返回值解析：

  1. 返回值类型：List<String>
  2. 返回值：国内手机号：[中国,省,市]；国外手机号：[国家]
  1. 返回错误信息，返回格式：['error','错误明细']。其中错误明细有如下枚举：
1. InvalidParameter // 非法参数：包含字母、特殊符号、空格、空字符串等。。。。
2. FormatError：// 电话号码格式错误
// 一方面：未通过正则校验(国内手机号：^[1-9]\\d{10}$)(国外手机号："^\\+\\d+$"),在做正则校验时，会将国内手机号"若包含则去除 +86/+0086/0086"，国外手机号 "将"00"或"+00"替换为+"
// 另一方面：未通过GoogleJar的格式校验
3. MissingRegionCode // 非法区号（由于数据不全，部分合法区号此Jar包无法解析）
4. NotActiveNumber // 根据区号，且用该国家的手机号规则校验手机号时，校验失败
