实时风控 · 通用离线处罚能力建设（MYSQL+Redis）

需要解决的痛点：@风控痛点总结 & 能力规划建设

痛点拆解归类

痛点整体可划分为两类问题：

  1. 处罚型。属于危险操作，如：账号密码重置、账号处置、账号恢复等。因此此类操作注重「操作幂等、可追溯、失败精准重试」，能力建设需考虑更多。
  1. 分析型。属于日常操作，用于辅助风险分析，如：账号风险分批量查询。此类操作则无需考虑过细，失败可全部重试、操作可不幂等，当前可用脚本做临时平替。

而通用离线处罚能力建设就针对「处罚型」问题，建设通用能力。

目标

建设风控-通用处罚能力，将账号批量处置、账号批量处置、账号密码重置等高危操作收敛到通用任务中心，做到操作提效、降低高危操作成本，并且保证操作留痕可追溯。

实现方案

设计目标：

  1. 可溯源：任务元数据持久化保存，支持查看/下载，如：原文件、失败明细、执行人、执行时间、执行结果。
  1. 高可用：支持任务终止、状态查看、失败重试。同时保证同一子任务执行幂等。

MYSQL用于持久化存储主任务、子任务以及处罚方式。

处罚动作表(task_table)

这里直接复用规则处置配置即可，参考文档：@规则处置-需求实现记录

用于存储所有处罚方式。如：密码重置、账号冻结。。

task_action所使用的插件中，保持一个expiredTs参数，作为全局处罚成功锁的过期时间。

CREATE TABLE `task_table` (
  `id` int(11) unsigned NOT NULL AUTO_INCREMENT COMMENT '主键',
  `name` varchar(256) NOT NULL DEFAULT '' COMMENT '处罚动作名称',
  `plugin` varchar(128) NOT NULL DEFAULT '' COMMENT '具体执行处罚插件',
  `params` json DEFAULT NULL COMMENT '处罚参数',
  `status` tinyint(3) unsigned NOT NULL DEFAULT '0' COMMENT '0: offline, 1: online',
  `created_by` varchar(64) NOT NULL DEFAULT 'risk' COMMENT '创建人',
  `created_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_by` varchar(64) NOT NULL DEFAULT 'risk' COMMENT '更新人',
  `updated_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUEKEY `uk_name` (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4

父任务表(task_table)

用于存储父任务元信息，与子任务是1对多的关系。

  1. 有一个大key存储父任务的所有原数据(即：传入的csv文件)，后续在切分时，根据此csv文件数据，做子任务切分即可。
  1. csv文件包含表头，且保证仅有1列有效数据，且表头字段=csv_header。csv_header需要前端配置此字段，且若是csv文件方式上传。
  1. 游标先干掉，子任务唯一索引保证切分结果幂等。
拟字段有：id、main_task_code、task_action_id、status、reason、created_by、create_at、
-- 父任务表：存储主任务元信息（1:N 子任务）
CREATE TABLE `task_table` (
  `id` bigint(20) unsigned NOT NULL AUTO_INCREMENT COMMENT '主键',
  `task_action_id` int(11) unsigned NOT NULL COMMENT '关联处罚动作ID（外键，关联task_action.id，标识执行哪种处罚）',
  `status` tinyint(3) unsigned NOT NULL DEFAULT '0' COMMENT '任务状态',
  `reason` varchar(256) NOT NULL DEFAULT '' COMMENT '处罚原因',
  `csv_file` LONGBLOB COMMENT 'CSV文件二进制内容（最大支持4GB）',
  `csv_header` varchar(256) NOT NULL DEFAULT '' COMMENT 'CSV表头（如"ip,用户ID"，用于解析字段映射）',
  -- 游标机制核心字段
  `split_cursor` bigint(20) unsigned NOT NULL DEFAULT '0' COMMENT '切分游标：记录已切分到的数据条数',
  `total_records` bigint(20) unsigned NOT NULL DEFAULT '0' COMMENT 'CSV总记录数（不含表头，解析CSV后更新）',
  `splited_records` bigint(20) unsigned NOT NULL DEFAULT '0' COMMENT '已切分的记录数（每次切分成功后累加，最终应等于total_records）',
  `split_batch_size` int(11) NOT NULL DEFAULT 1000 COMMENT '每批切分大小',
  
  `created_by` varchar(64) NOT NULL DEFAULT 'risk',
  `created_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_by` varchar(64) NOT NULL DEFAULT 'risk',
  `updated_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='含原始CSV文件的父任务表';

子任务表(task_table)

用于存储子任务元信息。

  • 如：{"用户ID":"123"}、{"ip":"1.1.1.1"}。

  • sub_task_code：基于 “父任务编码 + 行号” 生成，唯一键确保同一行号不会被重复插入子任务（即使多个 worker 同时处理，数据库会阻止重复）。
CREATE TABLE `task_table` (
  `id` bigint(20) unsigned NOT NULL AUTO_INCREMENT COMMENT '子任务主键ID',
  `main_task_id` bigint(20) unsigned NOT NULL COMMENT '关联父任务ID（关联task_main_task.id）',
  `task_action_id` int(11) unsigned NOT NULL COMMENT '关联处罚动作ID（关联task_action.id）',
  `sub_task_code` varchar(64) NOT NULL UNIQUE COMMENT '唯一编码：SUB_{main_task_code}_{row_num}',
  `status` tinyint(3) unsigned NOT NULL DEFAULT '0' COMMENT '子任务状态：0-待执行，1-执行中，2-成功，3-失败，4-重试中，5-已取消',
  -- CSV相关字段（对应父任务CSV中的一行数据）
  `biz_params` json NOT NULL COMMENT '业务参数（如{"user_id":"123"}，用于处罚执行和留痕）',
  `start_time` datetime DEFAULT NULL COMMENT '开始执行时间',
  `finish_time` datetime DEFAULT NULL COMMENT '执行完成时间',
  `reason` varchar(512) NOT NULL DEFAULT '' COMMENT '备注（如失败原因："账号不存在"）',
  `created_by` varchar(64) NOT NULL DEFAULT 'risk' COMMENT '创建人',
  `created_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_by` varchar(64) NOT NULL DEFAULT 'risk' COMMENT '更新人',
  `updated_at` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_sub_task_code` (`sub_task_code`) COMMENT '子任务编码唯一，避免重复创建',
  KEY `idx_main_task_id` (`main_task_id`) COMMENT '按父任务ID查询所有子任务',
  KEY `idx_status` (`status`) COMMENT '筛选待执行/失败的子任务',
  KEY `idx_task_action_id` (`task_action_id`) COMMENT '按处罚动作类型统计',
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='子任务表：关联父任务CSV中的单行数据，存储处罚执行信息';
