关键参数说明：

  • taskName：稳定句柄，后续可用 subagents steer/kill 精确定位子 Agent
  • context: "fork"：子 Agent 继承当前对话完整上下文（含所有工具调用结果）
  • context: "isolated"（默认）：子 Agent 从零开始，需在 task 中传递所有必要信息

三、巡检多 Agent 方案

方案 A：串行编排（最简单）

主 Agent
  ├─ spawn({ taskName: "sql-exec", task: "执行策略SQL" })
  │   └─ 返回结果 → 主 Agent 拿到
  ├─ spawn({ taskName: "verify", task: "交叉验证", context: "fork" })
  │   └─ 返回结果 → 主 Agent 拿到
  └─ spawn({ taskName: "report", task: "生成巡检报告" })
      └─ 返回报告 → 主 Agent 推送群聊
  • 特点：每步等上一步完成，主 Agent 串联结果
  • 适合：流程有依赖关系（SQL → 验证 → 报告）
  • 等待方式：sessions_yield 等子 Agent 完成事件

方案 B：并行编排（效率最高）

主 Agent
  ├─ spawn({ taskName: "strategy-A", task: "执行策略A" })  ─┐
  ├─ spawn({ taskName: "strategy-B", task: "执行策略B" })  ─┤ 并行
  ├─ spawn({ taskName: "strategy-C", task: "执行策略C" })  ─┘
  └─ sessions_yield → 等三个都完成 → 汇总 → 报告
  • 特点：多个策略同时跑，不互相等待
  • 适合：多个独立策略的检测互不依赖
  • 等待方式：一次 sessions_yield 等所有子 Agent

方案 C：Fork 上下文（需要共享数据时）

主 Agent（已读取 YAML、已执行部分 SQL）
  └─ spawn({
       taskName: "deep-verify",
       task: "对以下检出结果做深度取证...",
       context: "fork"
     })
  • 特点：子 Agent 能看到主 Agent 之前的所有工具调用结果
  • 适合：子 Agent 需要依赖主 Agent 已获取的数据
  • 代价：token 消耗更高（复制整个 transcript）

方案 D：Skill 封装（跨会话复用）

把多 Agent 编排逻辑写入 Skill 的 SKILL.md，每次触发巡检自动走多 Agent 流程。

五、建议落地路径

第 1 步：当前巡检直接用方案 B（并行 spawn）

  • 验证多 Agent 编排跑通
  • 观察 token 消耗和耗时
  • 不需要任何配置变更

第 2 步：跑通后封装为方案 D（Skill）

  • 固化流程，后续巡检自动走多 Agent
  • 跨会话一致，可复用

第 3 步：拿到管理员权限后

  • 注册命名 Agent（独立 SOUL.md / 工具 / 模型）
  • 子 Agent 有独立人格，不再继承主 Agent 全部 prompt
  • 配置 agents.list + bindings 实现渠道路由

7.2 ACP 外部引擎能力（需管理员安装插件）

ACP（Agent Client Protocol）让 OpenClaw 调用外部编码引擎，每个引擎有独立的运行时、工具链和模型。

引擎

harness id

说明

Claude Code

claude

需要主机上有 Claude Code 认证

Codex

codex

OpenAI Codex，原生 /codex 的 ACP 备选

GitHub Copilot

copilot

需要 Copilot CLI 认证

Cursor

cursor

Cursor CLI ACP

Gemini CLI

gemini

需要 Gemini CLI 认证或 API Key

Factory Droid

droid

需要 FACTORY_API_KEY

Kimi/Moonshot

kimi

需要 Kimi 认证

OpenCode

opencode

开源编码引擎

使用方式：

/acp spawn claude --bind here     # 绑定当前对话到 Claude Code
/acp spawn codex --thread auto    # 自动创建线程绑定到 Codex
/acp doctor                       # 检查 ACP 健康状态
/acp list                         # 列出活跃 ACP 会话

代码方式：

sessions_spawn({ runtime: "acp", agentId: "claude", task: "重构这个函数" })
