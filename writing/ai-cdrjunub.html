OpenCode、Claw🦞 联网指南：搜索、抓取、浏览器，什么场景用什么方法？

2026-09-20 · 飞书原文 ↗
💡

用 OpenCode 或 OpenClaw 时，想让 AI 上网找资料，到底该用哪个工具？

搜索用 WebSearch，抓网页用 web_fetch，搞不定的上 Browser CDP，主流平台用 Defuddle 更干净。

这四个工具覆盖了 99% 的场景，关键是知道什么时候用哪个。

技术圈链接🔗：点击。

其他干货文档见：@聊聊AI-Coding、AI提效、AI底层认知 - 研发效能与工程化探索

最佳实践：web-access Skill(主) + Defuddle Skill(补)

  1. web-access Skill 做主力调度（web_fetch → Jina → CDP 自动降级）
  1. GitHub / YouTube / Reddit 等已适配平台单独用 Defuddle 拿更干净的结果。

一、四个工具，各管一摊

先把底牌亮出来。OpenCode / OpenClaw 里联网能力主要靠四个工具，各自干不同的事：

工具

一句话定位

技术原理

WebSearch

搜索引擎入口，回答"去哪找"

调用搜索引擎 API，返回标题 + 摘要 + URL 列表

web_fetch

内置轻量抓取器，默认首选，零配置

HTTP GET 请求 + Readability 算法解析，输出 Markdown 或纯文本

Defuddle

增强版提取器，主流平台效果更好

增强 Readability + 网站专属 extractor，元数据更丰富

Browser CDP

真实浏览器，终极兜底方案

完整 Chromium 实例，通过 CDP 协议控制，JS 全执行

📖

名词解释

  • Readability：Mozilla 开源的正文提取算法，从杂乱的网页 HTML 中自动识别"正文区域"，去掉广告、导航栏、侧边栏等噪音。Firefox 的"阅读模式"就是用它实现的
  • CDP（Chrome DevTools Protocol）：Chrome 浏览器的远程调试协议。通过这个协议，程序可以像人一样控制浏览器——打开页面、点击按钮、填写表单、截图。Playwright、Puppeteer 等自动化工具底层都是走 CDP
  • Defuddle：Obsidian Web Clipper 的核心引擎，在 Readability 基础上做了增强。针对 GitHub、YouTube、Reddit、StackOverflow 等主流平台有专门的 extractor，提取质量比通用算法高一截
  • extractor：针对特定网站定制的内容提取规则。比如 GitHub 的 extractor 知道 README 在哪、Issue 列表怎么提取；YouTube 的 extractor 知道视频标题、描述、字幕在哪

四、调度逻辑：web-access Skill 怎么帮你选

在 OpenClaw 里，有一个叫 web-access 的 Skill。

它不是又一个抓取工具，而是一个使用指南——AI 读取后会根据场景自动选择合适的联网工具。

web-access 覆盖的工具：WebSearch（搜索）、web_fetch（轻量抓取）、Jina（r.jina.ai/ 前缀用法，省 token，不是独立工具）、Browser CDP（浏览器兜底）。

注：curl 在 web-access Skill 内部作为原始 HTML 获取的兜底手段，不是用户层面需要直接选择的工具。Defuddle 不在这条链路里，是独立安装的增强工具。

实际的决策流程长这样：

第一步：URL 预判

拿到 URL 后先看特征：

  • mp.weixin.qq.com（微信公众号）→ 直接跳到 Browser CDP，别浪费时间试轻量工具
  • 小红书、需要登录的站点 → 直接 Browser CDP
  • 已知重度反爬站点 → 直接 Browser CDP
  • 其他 → 进入正常流程

第二步：web_fetch 快速尝试

用最轻的方式先试。正文长度 > 200 字符、关键信息完整？直接用。大部分普通网页在这一步就搞定了。

第三步：Jina 辅助提取

但 Jina 是第三方服务，免费版有请求频率限制（具体限额以 Jina 官网为准），对非文章结构页面（商品页、数据面板）可能提取错误区块。

第四步：Browser CDP 兜底

前面都搞不定？上重武器。完整渲染页面，JS 执行、图片加载、交互操作，一步到位。调度精髓：每一步都给结果一个机会，但不在烂结果上浪费时间。

五、Browser CDP 的完整能力

作为兜底方案，Browser CDP 不只是"能渲染 JS"这么简单。

直连用户 Chrome

通过 CDP 协议控制浏览器，有两种模式：连接已有 Chrome（通过 --cdp-url 等配置）可复用登录态，或启动独立 Chromium 实例（默认行为）。

连接已有 Chrome 时：

  • 天然登录态：用户已登录的网站，CDP 都能直接访问
  • Cookie 和 Session 都在，不需要额外处理认证
  • 浏览器扩展也是生效的

七、微信公众号：一个典型的"看着简单实际很难"

微信公众号是最好的反面教材——看着就是一个网页链接，实际上轻量工具全军覆没：

  • web_fetch：拿到空壳页面。微信的 JS 渲染机制让纯 HTTP 抓取完全失效
  • Defuddle：能拿到部分文本，但图片全丢（微信用 data-src 延迟加载），排版错乱

两者都无法完整还原微信公众号内容——轻量工具在这个场景上已到极限。

只有 Browser CDP 能完整渲染微信公众号。 这也是为什么 web-access Skill 检测到 mp.weixin.qq.com 时会直接跳到 CDP，不浪费时间试轻量工具。

📖

为什么微信公众号这么难抓？

微信公众号页面的正文不是直接写在 HTML 里的，而是通过 JavaScript 动态渲染出来。web_fetch 这类工具只会做一次 HTTP 请求拿 HTML，拿到的是一个"空壳"——正文区域是空的。必须有一个真实浏览器去执行 JS，才能看到完整的内容。

另外，微信的图片用了 data-src 而非标准的 src 属性做延迟加载，不执行 JS 的工具连图片都拿不到。

八、哪些是自带的，哪些是额外装的？

容易混淆的一个概念：底层工具和调度 Skill 是两回事。

OpenClaw / OpenCode 自带的底层工具（开箱即用）

就这三件事：搜、抓、浏览器。 Jina 不算独立工具，只是 web_fetch 的一种用法（URL 前加 r.jina.ai/ 前缀）。

需要额外安装的（Skill / 工具）

没有 Skill，底层工具也能用——只是 AI 不一定知道什么场景该选哪个。Skill 的本质是一套调度指南，让 AI 自动做出正确的工具选择。

注：上表中的 web-access Skill 和 web-master Skill 在 OpenCode 和 OpenClaw 上均可安装使用，并非 OpenClaw 独占。

关键差异在 Browser CDP。 它需要一个真实的 Chromium 内核浏览器运行环境：

  • 本地电脑：天然满足，直连日常 Chrome，还自带登录态——这是 CDP 体验最好的环境
  • VPS / 云服务器：通常没有桌面环境，没有 Chrome，CDP 直接不可用。这意味着微信公众号、小红书、需要登录的页面都搞不定
  • Docker 容器：可以装 headless Chromium，但没有用户登录态，需要登录的场景仍然受限

环境不满足时会怎样？

不会报错崩溃。调度逻辑会自动跳过不可用的层级：

  • 没有 CDP → 跳过第四层，web_fetch / Defuddle 能搞定的照样搞定
  • 没有 Defuddle → 跳过第三层，web_fetch 兜底
  • 最差情况只有 WebSearch + web_fetch → 仍然覆盖大部分公开网页的搜索和抓取但有些场景就是搞不定了，典型的：

怎么补齐？

如果你的 OpenClaw 部署在 VPS 上但需要 CDP 能力，有几个思路：

  1. Node 连接：在本地电脑上运行 OpenClaw Node（伴侣应用），VPS 上的 Agent 通过 Node 远程控制本地 Chrome——这是官方推荐的方案
  1. 安装 headless Chromium：在 VPS 上装无头浏览器，能解决不需要登录态的反爬场景，但没有用户 Cookie
  1. 接受限制：如果主要需求是搜索和抓取公开内容，前两层够用了，不折腾

总结四个工具不是竞争关系，是分层协作。日常 90% 的场景 web_fetch 就够了，主流平台上 Defuddle 更干净，搞不定的上 Browser CDP 兜底。记住一个比例——90% 轻量，10% 重武器。不要动不动就启动浏览器，也不要在该用浏览器的时候死磕轻量工具。
