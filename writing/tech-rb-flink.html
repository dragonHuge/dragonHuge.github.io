Flink 实时任务规则

2026-07-09"本地沉淀 · 风控工程知识库"

本文是工程规则（团队约定 + 踩坑结论），不是入门教程： 适合「已经知道要做什么，只想知道怎么做才不出事」的场景。

1. 适用范围

公司编译版 Flink（${flink.version}-mdh）实时流任务：消费 Talos topic → 按 key 开窗 → 写 Redis / 回流 Talos。

不覆盖：Flink SQL / Table API / Iceberg sink / Hive 写入。

2. 版本 / 依赖

坐标scope备注
org.apache.flink:flink-streaming-java_2.11provided集群提供
org.apache.flink:flink-connector-taloscompile不在集群里，必须打进 jar
com.example.infra:galaxy-thrift-apicompileCredential / UserType
业务事件 thrift（如 ${SourceEventType}）compile通过 cloud streaming 仓库

Flink 任务打包：用 maven-assembly-plugin 的 jar-with-dependencies，不用 shade（DT 平台 fat-jar 大小限制宽松，不需要 relocate）。

3. 标准骨架

3.1 Main 方法（流水线骨架）

public static void main(String[] args) throws Exception {
    String env = args.length > 0 ? args[0] : "";
    log.info("Starting ${flinkJobClass} with env={}", env);

    JobConfig config = JobConfig.load(env);

    StreamExecutionEnvironment streamEnv = StreamExecutionEnvironment.getExecutionEnvironment();
    configureCheckpoint(streamEnv);
    buildPipeline(streamEnv, config);

    streamEnv.execute(config.appName());
}

3.2 Checkpoint 配置

private static void configureCheckpoint(StreamExecutionEnvironment env) {
    CheckpointConfig ckConfig = env.getCheckpointConfig();
    env.enableCheckpointing(${checkpointIntervalMs}, CheckpointingMode.AT_LEAST_ONCE);
    ckConfig.setMinPauseBetweenCheckpoints(${checkpointMinPauseMs});
    ckConfig.setCheckpointTimeout(${checkpointTimeoutMs});
    ckConfig.enableExternalizedCheckpoints(
        CheckpointConfig.ExternalizedCheckpointCleanup.RETAIN_ON_CANCELLATION);
}

实测：

  • checkpointIntervalMs = 5 * 60 * 1000 (5 min)
  • checkpointMinPauseMs = 5 * 60 * 1000
  • checkpointTimeoutMs = 10 * 60 * 1000
  • 模式 AT_LEAST_ONCE（业务幂等 + Redis 去重 → 不需要 EXACTLY_ONCE 代价）
  • RETAIN_ON_CANCELLATION 让人工 cancel 后还能从 ck 恢复

3.3 Pipeline 模式

streamEnv
    .addSource(buildTalosConsumer(config))
    .name("talos-source")
    .filter(x -> x != null)
    .name("filter-null")
    .map(new ${parserMapper}())          // 把外部事件解析为内部 ParsedEvent
    .name("parse")
    .filter(x -> x != null)
    .name("filter-unparseable")
    .keyBy(${ParsedEvent}::${businessKey})
    .window(TumblingProcessingTimeWindows.of(Time.seconds(config.windowSeconds())))
    .process(new ${windowFunctionClass}(
        config.redisHost(), config.redisPort(),
        config.redisPassword(), config.redisKeyPrefix()))
    .name("window-process")
    .flatMap(new ${sinkBytesFlatMap}())  // thrift → byte[]
    .name("serialize")
    .addSink(buildTalosProducer(config))
    .name("talos-sink");

铁律：

  • 每个算子都给 .name("xxx")，便于 Flink UI 排查
  • 不 disableChaining —— 切链只是诊断用，正常运行恢复链接节省序列化
  • 不 setParallelism —— 走 DT 平台 -p 参数控制
  • keyBy 用业务 key（如 userId / 用户ID），不要按 timestamp（窗口会失衡）
  • 窗口大小（典型 3s）由 ${windowSeconds} 配置，别写死

3.4 Window Function 模式

@Slf4j
public class ${windowFunctionClass}
        extends ProcessWindowFunction<${ParsedEvent}, ${SinkEventType}, String, TimeWindow> {

    private static final int MAX_REDIS_RETRIES = 3;
    private static final long REDIS_RETRY_BACKOFF_MS = 10L;

    private final String redisHost;
    private final int redisPort;
    private final String redisPassword;
    private final String redisKeyPrefix;

    private transient JedisPooled jedis;

    public ${windowFunctionClass}(String host, int port, String pwd, String prefix) {
        this.redisHost = host; this.redisPort = port;
        this.redisPassword = pwd; this.redisKeyPrefix = prefix;
    }

    @Override
    public void open(Configuration parameters) throws Exception {
        super.open(parameters);
        // 进程级单例：同 TaskManager JVM 内多 subtask 共享一个 JedisPooled
        jedis = ${jedisFactoryClass}.getOrCreate(redisHost, redisPort, redisPassword);
    }

    @Override
    public void close() {
        // 不要关 jedis：单例由 JVM ShutdownHook 统一处理
        jedis = null;
    }

    @Override
    public void process(String key, Context ctx, Iterable<${ParsedEvent}> elements,
                        Collector<${SinkEventType}> out) {
        long start = System.currentTimeMillis();
        try {
            List<${ParsedEvent}> events = new ArrayList<>();
            for (${ParsedEvent} e : elements) events.add(e);
            if (events.isEmpty()) return;

            events.sort(Comparator.comparingLong(${ParsedEvent}::ts));

            // 1) 预读 existing（HMGET 批读）
            // 2) 单遍扫描产出 WriteOp + 待 emit 事件
            // 3) 批写 pipeline + retry 3×10ms
            // 4) 写成功才 collect emit（避免"未生效写入"流到下游）
        } finally {
            PerfCounter.setTimerValue("${metricPrefix}.flink_window.process.all",
                System.currentTimeMillis() - start);
        }
    }
}

详细 retry / partial error / fail-open 模式见 redis.md §3.2-§3.5。

3.5 Source 解析与时间戳

外部事件转内部 ParsedEvent，事件时间统一取业务字段 epoch 秒：

private static class ${parserMapper} implements MapFunction<${SourceEventType}, ${ParsedEvent}> {
    @Override
    public ${ParsedEvent} map(${SourceEventType} action) {
        try {
            // 业务字段抽取
            String businessKey = action.get${BusinessKey}();
            long ts = parseEventTime(action.get${EventTimeField}());  // dt 字段转秒
            // 上报事件延迟指标
            PerfCounter.setTimerValue("${metricPrefix}.flink_source.event_delay_ms",
                eventDelayMs(ts, System.currentTimeMillis()));
            // 业务解析
            return ${parserClass}.parse(businessKey, ts, action);
        } catch (Exception e) {
            PerfCounter.setMeterCount("${metricPrefix}.flink_source.map.failed", 1);
            return null;
        }
    }
}

static long eventDelayMs(long eventTsSec, long processMs) {
    return Math.max(0L, processMs - eventTsSec * 1000L);
}

6. 常见踩坑

6.1 🔴 setParallelism() 写代码里

后果：DT 平台 -p 参数失效，无法运维侧调整并发。 正确：代码不设，全部走平台参数。

6.2 🔴 窗口内一条命令失败导致整窗 emit

错误：写一半 Redis 就 out.collect，写后续命令失败时下游已经看到部分事件。 正确：先收集 pendingEmits，整批 Redis flush 成功后才 collect（WindowFunction 注释 #3）。

6.3 🔴 JedisPooled 每 subtask new 一个

后果：同 TaskManager 内多 subtask 各起一个池，连接抢占。 正确：进程级单例 ${jedisFactoryClass}.getOrCreate，配合 JVM ShutdownHook。

6.4 🟠 事件时间用 processing time

后果：事件延迟看不见，回溯历史窗口失真。 正确：解析上游事件的业务时间字段（如 dt），缺失时再 fallback 到 processing time + 打点。

6.5 🟠 单 batch 重试粒度

错误：per-event 重试 → N 个 RTT 退化。 正确：per-batch（整 pipeline 整批重试），网络抖动通常是连接级，批失败率 ≈ 单命令失败率。

6.6 🟢 没禁用 chain

早期为了诊断慢算子用了 disableChaining，定位完瓶颈后已恢复链接。 正确：默认链接，除非确实在诊断单算子耗时。
