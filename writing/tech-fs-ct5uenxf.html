流程详解：

1.GitLab(代码仓库) - SSH密钥 与 Git本地配置

  1. Git本地配置

即：将本地Git的用户名与邮箱，设置为自己GitLab上的用户名和邮箱名。

如：我的用户名为 your-account；邮箱为 your-account@[内部链接]

  • 因此本地Git进行以下配置：
git config --global user.name "your-account" git config --global user.email "your-account@[内部链接]
  • 查看本地配置：

git config --global --list   // 查看当前git的配置信息
git config user.name
git config user.email
  1. 生成SSH密钥后，在GitLab上添加公钥。

首先输入下边命令-回车，生成个人SSH密钥，根据密钥存储位置，找到公钥，配置到gitLab上，详细配置教程见：https://juejin.cn/post/7079972561861214239

ssh-keygen -t rsa -b 2048 -C "your-account@[内部链接] // 生成密钥

图中红框内就是密钥的存储位置(.pub后缀是指公钥文件)，在配置好后，将代码拉到本地即可。

2.Maven - 配置本地Maven仓库

代码pull下来后，就要想办法让项目代码run起来，因此就开始配置本地环境啦。下载好Maven、配置好本机环境变量后，再按照手册配置好Maven仓库即可。

[内部链接] ：公司Maven用户配置手册

3.clone项目代码到本地，分支开发

4.MiFlow -流水线开发记录

此时已经将项目代码pull到了本地，并完成Maven配置，成功启动项目。接下来进行分支MiFlow的构建、合并与上线。

💡

今天跟峰哥讨论了一下，对流水线MiFlow的定义和用法有了更深点的理解，记录一下。

流水线上的每一个点，其实就是一个IAM镜像仓库。

  • 大致理解：其实流水线MiFlow只负责将我们所提交的代码，根据所设置的触发条件，打包成对应的镜像。不负责后续镜像的部署(Matrix的工作)
  • 细致理解：我们在push代码到GitLab后，流水线就会根据预先设置的触发条件，自动打包代码生成对应镜像。到这儿流水线的使命就结束了，后续镜像的部署、上线等，就是由其他组件完成。

1.建立本地分支，commit后push代码到远程仓库

先将开发代码提交到分支，然后在分支测试没问题后，才进行后续合并（创建分支，而不是直接push到master,是为了保证业务安全）。

git checkout dev-dragon-test // 1.创建分支后commit
                             // 2.将commit后的代码push到远程仓库

2.提交MR - 出现问题，解决问题

💡

MR(merge request):分支合并请求，即从dev分支合并到master主分支上。此时提出合并请求。

在提出MR后，确实出现了冲突，解决掉即可：

3.组内Code View

解决掉冲突后，就进行组内code view，确认无误后进行merge，就会触发流水线执行，在通过管道验证后(流水线执行完毕后)，就会成功merge到主分支(master)，并得到最新版本的镜像包。

之后根据此镜像进行验证、部署上线。

5.Matrix -镜像部署 & 访问

在上述的操作中，生成了我们所需的镜像，因此下一步就是将其部署到测试环境(云端),因此去Matrix下，找到我们的镜像，然后部署到测试环境。

💡

点发布，就能选你流水线生成的镜像部署了。

点终端，是以直接进入到部署的容器内的。

测试环境和本机电脑网络是通的，可以直接在本地调用服务的接口。

发布之后就可以直接访问服务：

    http://[内网IP]:8001/test/dragon

      至此，开发-上线流程完成。
