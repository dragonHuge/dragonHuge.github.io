Anthropic 发布 Claude Managed Agents，把沙箱、状态管理、权限、错误恢复全接管了。开发者只管定义任务和工具，Anthropic 负责跑。

Agent 从宠物变牲畜。

一、Anthropic 到底发布了什么

2026 年 4 月 8 日，Anthropic 发布 Claude Managed Agents——一套可组合的 API，用于构建和部署云托管的 AI Agent。

跟市面上的 Agent 框架不同，Anthropic 卖的核心不是模型调用，是 Harness（Agent 编排引擎）：一个经过调优的编排循环，自动处理工具调用决策、上下文管理、错误恢复，并且随模型能力升级自动演进。

之前 Anthropic 的产品线有个断层。消费者端有 claude.ai 和 Claude Code，开发者端有 Messages API。企业想做一个长时间运行的、能自主调用工具的 Agent？自己搭沙箱、做状态管理、处理权限、写错误恢复。这些基础设施工作可能比业务逻辑还重。

Managed Agents 填的就是这个空。你定义任务、工具和约束，Anthropic 负责跑。

具体能力清单

  • 生产级沙箱：每个 Agent 跑在安全云容器里，可预装 Python/Node.js/Go 等环境，配置网络规则，挂载文件
  • 长时间 Session：Agent 自主运行数小时，断连恢复，进度持久化
  • 内置 Harness：自动处理工具调用、上下文管理、错误恢复。内置 prompt caching、compaction 等优化
  • 多 Agent 协调（研究预览）：一个 Agent 可以启动其他 Agent，分配子任务并行
  • 自评估（研究预览）：定义成功标准，Claude 自己迭代直到达标。成功率比标准 prompting 提高最多 10 个百分点
  • 治理工具：Scoped permissions、身份管理、执行追踪，直接内置在 Claude Console

二、核心架构：三层虚拟化

这是这次发布技术含量最高的部分。Anthropic 同步发了一篇工程博客，详细讲了 Harness 的架构设计。

核心设计问题：如何为还没被想到的程序设计系统？

几十年前，操作系统通过把硬件虚拟化为抽象层（进程、文件）解决了这个问题。read() 不管底下是 1970 年代的磁盘还是现代 SSD，都能正常工作。抽象比硬件活得久。

Managed Agents 遵循同样的模式，把 Agent 虚拟化成三个部分：

Session（会话）

所有事件的追加写入日志，持久存储在 Harness 之外。活在上下文窗口之外，通过 getEvents() 按需取回切片。解决长任务超出上下文窗口的问题——压缩、裁剪、总结都是不可逆操作，Session 让你可以回到任意时刻重读上下文。

Harness（编排循环）

调用 Claude、把工具请求路由到对应基础设施的循环。无状态，崩溃后用 wake(sessionId) 从日志恢复。一个关键认知：Harness 编码的是模型做不到什么的假设，这些假设会过时。

具体例子：

Sonnet 4.5 在接近上下文限制时会提前收工（他们叫"context anxiety"），Anthropic 在 Harness 里加了上下文重置。但换到 Opus 4.5 后，这个行为消失了，重置变成了多余的负担。所以 Harness 要随模型进化定期审计简化。

Sandbox（执行环境）

Claude 跑代码的容器。通过 execute(name, input) → string 调用。Harness 不知道沙箱是容器、手机还是 Pokémon 模拟器。挂了换一个就行。三者完全解耦，任何一个故障不影响其他两个。

三、从宠物到牲畜 - 宠物坏了得救，牲畜坏了换一头

这个隐喻来自 DevOps 的经典理念。最初的设计把所有组件放在一个容器里。好处是文件操作直接走系统调用，没有服务边界。坏处是容器变成了一只"宠物" —— 宠物坏了得救，牲畜坏了换一头。

对比维度

耦合设计（宠物）

解耦设计（牲畜）

容器故障

会话丢失，必须救回来

provision({resources}) 起新的

Harness 崩溃

全部状态丢失

wake(sessionId) 从日志恢复

不可信代码和凭证在同一容器

凭证永远不在沙箱里

调试

每层独立可观测

扩展性

每个会话必须等容器起好

推理可在容器启动前开始

解耦后的安全收益：耦合设计里，一次提示注入就能说服 Claude 读环境变量、拿到 token、开出不受限制的新会话。解耦后：

  • Git token：初始化时写入本地 remote，Agent 不经手
  • OAuth token：存安全保管库，通过代理调用，控制器对任何凭证不知情

四、性能收益：多大脑多双手

解耦后推理可以在容器启动前就开始。实测数据：

  • p50 TTFT（首 token 延迟）下降约 60%
  • p95 TTFT 下降超过 90% 每双手就是 execute(name, input) → string。因为手不绑定大脑，大脑之间可以互相传递手。早期模型能力不足，只能用单容器。随着模型智能提升，单容器反而成了瓶颈。解耦后，一个大脑接多双手、多个大脑协调都成为可能。

五、商业信号

定位转移

Anthropic 从"模型提供商"变成"Agent 基础设施提供商"。之前卖 token，现在卖运行 Agent 的全套环境。

定价结构

  • 标准 Claude Platform token 费率照常
  • 每活跃 Session 小时 $0.08（按毫秒计量，空闲不计费）
  • Web 搜索 $10/千次$0.08/session-hour 意味着在 token 之外多了一条收入线。Token 收入跟使用量挂钩，session-hour 收入跟运行时长挂钩——后者更稳定、更可预测。

六、对我们的启发

三层解耦的普适性

这个 Session / Harness / Sandbox 的分离思路不只适用于 Anthropic 的服务。任何做 Agent 系统的团队都可以参考：

  • Session 外置日志：跨会话记忆、断点续传
  • Harness 无状态：崩溃不丢进度，水平扩展
  • Sandbox 可替换：执行环境和编排逻辑脱钩

meta-harness 的设计哲学

不对具体 Harness 实现做假设，只对 Claude 需要的接口形状做假设。借鉴操作系统思路——read() 不管底下是什么存储介质。接口比实现活得久。

Harness 不是一劳永逸

Harness 编码的是"模型做不到什么"的假设，这些假设会随着模型能力提升而过时。要定期审计、简化。今天必须的 workaround，明天可能成为瓶颈。
