昨天峰哥给我讲解了一遍RPC的业务开发逻辑，总结一下：

💡

顾名思义，RPC作为“远程过程调用”，在实际的开发中，就是根据规范与第三方要求，开发RPC接口供第三方调用。

开发时分为 server方 与 client方，根据不同角色，进行不同的开发步骤，大致如下。

  1. 编写thrift描述文件(第三方要求/本部业务需求)
  2. 根据thrift文件生成java代码接口

    首先我们会在pom.xml文件中引入插件，mvn compile 即可生成。

  3. 构建server部分，实现上述生成的接口即可

    大致需要以下步骤：添加依赖、实现接口、增加server启动类，指定zookeeper、配置log4j(可选)

  1. 添加Server方的pom依赖，用于访问远程服务
  2. 创建Client，指定zookeeper
  3. 配置log4j(可选)

逻辑图梳理如下：

1.搭建项目框架

由于在Apus RPC的整个项目中，共有api、Server、Client三个模块，因此用Maven分模块开发，便于管理。

2.完成api模块开发

💡

具体任务：根据thrift文件，生成Java代码接口。

  1. <project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>
    <parent>
        <groupId>org.example</groupId>
        <artifactId>apus-dragon</artifactId>
        <version>1.0-SNAPSHOT</version>
    </parent>

    <artifactId>api</artifactId>
    <packaging>jar</packaging>

    <name>api</name>
    <url>http://maven.apache.org</url>

    <properties>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    </properties>

    <dependencies>
<!--        插件的组织（Group ID）和名称（Artifact ID）。-->
        <dependency>
            <groupId>junit</groupId>
            <artifactId>junit</artifactId>
            <version>3.8.1</version>
            <scope>test</scope>
<!--            <scope>元素定义了依赖的可见性和生命周期,test是指它只会在测试阶段被使用。-->
        </dependency>
<!--        首先引入APus RPC所需依赖-->
        <dependency>
            <groupId>com.facebook.swift</groupId>
            <artifactId>swift-annotations</artifactId>
            <version>0.15.0-mdf1.1.4</version>
        </dependency>
        <dependency>
            <groupId>com.facebook.swift</groupId>
            <artifactId>swift-service</artifactId>
            <version>0.15.0-mdf1.1.4</version>
        </dependency>
        <dependency>
            <groupId>org.apache.thrift</groupId>
            <artifactId>thrift</artifactId>
            <version>0.5.0-mdf2.0.9</version>
        </dependency>
    </dependencies>
    <build>
        <plugins>
            <plugin>
<!--                引入 "Thrift文件生成Java代码" 插件-->
                <groupId>com.facebook.mojo</groupId>
                <artifactId>swift-maven-plugin</artifactId>
                <version>0.15.0-mdf1.1.3</version>
<!--                <execution>：定义了插件执行的阶段和目标  -->
                <executions>
                    <execution>
<!--                        指定插件在 Maven 生成源代码阶段（generate-sources）执行。-->
                        <phase>generate-sources</phase>
                        <goals>
<!--                            指定插件执行的目标，这里是生成代码。-->
                            <goal>generate</goal>
                        </goals>
                    </execution>
                </executions>
                <configuration>
<!--                    指定生成 Java 代码的风格。java-mi 表示生成的代码将使用多态接口。-->
                    <codeFlavor>java-mi</codeFlavor>
<!--                    定义了 Thrift 文件的位置和包含模式。-->
                    <idlFiles>
                        <directory>${project.basedir}/src/main</directory>
                        <includes>
<!--                    包含所有 *.thrift 文件。-->
                            <include>**/*.thrift</include>
                        </includes>
                    </idlFiles>
<!--                    指示生成的 Java 代码使用简单的 Java 命名空间，而不是完整的 Thrift 命名空间。-->
                    <usePlainJavaNamespace>true</usePlainJavaNamespace>
<!--                    指定生成的 Java 代码的输出目录-->
                    <outputFolder>${project.build.sourceDirectory}/</outputFolder>
                </configuration>
            </plugin>
        </plugins>
    </build>
</project>
  1. mvn clean compile install

3.完成Server模块开发

💡

具体任务：实现api模块中的Java接口，生成启动类，并学习zookeeper基本知识，将此Server注册到Zookeeper，使其可以被Client感知，从而提供服务。

  1. 需要注意的一点是：由于server是要实现api模块中的接口，因此它依赖于api模块，也因此在其pom.xml文件中，需要引入对api模块的依赖，如下：

  2. <!--  并且注意:由于Server要实现api模块下的接口,因此它依赖于api模块,所以此处也要引入对api模块的依赖(去查看api模块pom.xml文件的配置)-->
<!--   且：由于此时我们的api模块中，是继承了父模块信息，因此直接使用父模块的groupId即可-->
        <dependency>
            <groupId>org.example</groupId>
            <artifactId>api</artifactId>
            <version>1.0-SNAPSHOT</version>
        </dependency>

  1. 新建EchoServiceImpl类后，'Alt+Insert'一键override接口，再接着实现接口即可。

  1. 因为server作为服务端，是需要运行起来向外提供给服务的。

  2. public class Server {
    public static void main( String[] args ) {
        // 1.创建一个 ServerConfig 配置对象config，用于定义服务端的行为，例如服务的注册方式、监听端口等.
        //   这里设置了注册中心Zookeeper,并且服务端监听的端口号为12345
        ServerConfig<EchoServiceImpl> config = new ServerConfig.Builder<>(EchoServiceImpl.class)
                .registryFactory(new ZookeeperRegistryFactory<>(EchoServiceImpl.class))
                .port(12345)
                .build();
        // 2.Bootstrap 类通常用于封装服务提供者的配置和启动逻辑。
        //   2.1 Bootstrap 类：Bootstrap 是一个泛型类，它在这里用于创建服务启动的引导类实例。
        //   2.2 EchoServiceImpl：这是服务接口的实现类，它将被RPC框架用来提供服务。
        //   2.3 new Bootstrap<>(config)：使用之前创建的 ServerConfig 对象 config 来初始化 Bootstrap 类的实例。这通常意味着 Bootstrap 将使用 config 中定义的所有配置来启动服务。
        //
        // ⚠️：如果实现类依赖了 @Autowired，需要手动获取对应的 bean 传入 Bootstrap
        // 如：
        //     @Autowired
        //     private ApplicationContext applicationContext;
        //
        //     EchoServiceImpl echoService = applicationContext.getBean(EchoServiceImpl.class);
        //     Bootstrap<EchoServiceImpl> bootstrap = new Bootstrap<>(config, echoService);
        Bootstrap<EchoServiceImpl> bootstrap = new Bootstrap<>(config);
        bootstrap.start(); // 启动此服务
    }
}

  1. 因为zookeeper是注册中心，server要把自己注册上去，这样其他的服务(Client)就可以从注册中心找到它，以达到远程过程调用的目的。

  2. 参考：公司Zookeeper集群地址，Zookeeper文档

具体做法就是：构建zookeeper配置文件，写好配置即可，如下

zookeeper.host = onebox  // 表示将ZooKeeper服务的主机名设置为 onebox

  1. 配不配都可以。新建一个log4j.xml文件，并写入下方即可。

  2. <?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE log4j:configuration SYSTEM "log4j.dtd">
<log4j:configuration xmlns:log4j="http://jakarta.apache.org/log4j/">
    <appender name="stdout" class="org.apache.log4j.ConsoleAppender">
        <param name="Target" value="System.out"/>
        <layout class="org.apache.log4j.PatternLayout">
            <param name="ConversionPattern" value="[%-5p %d{yyyy-MM-dd HH:mm:ss.SSS} %t] %l (%m)%n"/>
        </layout>
    </appender>

    <root>
        <level value="info"/>
        <appender-ref ref="stdout"/>
    </root>
</log4j:configuration>
