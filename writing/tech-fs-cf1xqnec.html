Java日志框架-logback、log4j、Slf4j

2025-07-30"飞书工作积累" · 飞书原文 ↗
💡

概念区分：

  • 门面模式是一种设计模式，Slf4j 就像是一个统一的接口，它定义了日志记录的各种操作方法，如debug()、info()、warn()、error()等。其主要目的是为了让应用程序代码能够以一种统一的方式来记录日志，而不依赖于具体的日志实现框架。

  • Logback 和 Log4j 是可以实现 Slf4j 接口的日志实现框架，它们可以通过相应的适配机制与 Slf4j 配合使用。

日志级别：

TRACE < DEBUG < INFO <  WARN < ERROR

logback.xml 案例：

<?xml version="1.0" encoding="UTF-8"?>
<configuration>
    <springProfile name="dev">
        // 定义一个名为 STDOUT 的控制台输出器（appender），用于将日志输出到控制台。
        <appender name="STDOUT" class="ch.qos.logback.core.ConsoleAppender">
            <encoder>
                <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%-5level] [%X{trace_id}] [%thread] [%logger{50}]: %m%n</pattern>
            </encoder>
        </appender>
        // 定义根日志记录器的级别为 INFO，并引用 STDOUT 输出器。
        // level：日志级别，INFO 表示只记录 INFO 及以上级别的日志。
        <root level="INFO">
            <appender-ref ref="STDOUT"/>
        </root>
        // additivity：是否继承父日志记录器的输出器。false 表示不继承，只使用当前定义的输出器。
        <logger name="com.公司.infosec" additivity="false">
            <level value="DEBUG"/>
            <appender-ref ref="STDOUT"/>
        </logger>
    </springProfile>

    <springProfile name="!dev">
        <!--定义日志文件的存储地址 勿在 LogBack 的配置中使用相对路径-->
        <appender name="APP_FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
            <file>/home/work/log/application.log</file>
            <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
                <fileNamePattern>/home/work/log/application.%d{yyyy-MM-dd}.%i.log</fileNamePattern>
                <maxFileSize>1000MB</maxFileSize>
                <maxHistory>20</maxHistory>
                <totalSizeCap>20GB</totalSizeCap>
            </rollingPolicy>
            <encoder class="ch.qos.logback.classic.encoder.PatternLayoutEncoder">
                <Pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%-5level] [%X{trace_id}] [%thread] [%logger{50}]: %m%n</Pattern>
            </encoder>
        </appender>

        <root level="INFO">
            <appender-ref ref="APP_FILE"/>
        </root>
    </springProfile>
</configuration>
