AI发展-自顶向下

发展里程碑：

  • 什么是大语言模型? -> 答：基于深度学习的自然语言处理模型。
  • 什么是深度学习？答：利用神经网络做自然语言处理。
  • 大语言模型的发展历程是什么？ -> 答：传统语言模型 -> 神经网络语言模型 -> 大语言模型。

AI(人工智能)是很宽泛的领域，AI的核心目的是成为人类，于是从“视、听、说”入手，演化出了AI的两大核心分支： CV(视) & NLP(听、说)。

NLP（自然语言处理）

💡

AI的两大核心应用：计算机视觉（Computer Vision，CV）& 自然语言处理（Natural Language Processing，NLP）

NLP作为人类和计算机之间沟通的桥梁，核心任务是为人类的语言编码并解码。即："理解人类，成为人类"。

NLP的发展史：

  • 基于规则的语言模型，受制于 "十分复杂的语言规则，无法涵盖所有语言现象"，其潜力有限。
  • 相比之下，基于统计的语言模型"将基于规则的问题转换成数学建模问题，由数据驱动"，这种特性为大数据时代的技术爆炸埋下伏笔。
❤️

NLP发展的两大关键点：

  1. 基于规则模型 -> 基于统计模型的跃迁。
  1. 海量语料库训练出来的大模型的使用。

统计语言模型

NLP是一个很宽泛的学科，语言模型是其中的一个核心组件，其作用是：为 NLP 任务提供对语言结构和语义的理解能力。

NLP的其它核心组件还有：分词（Tokenization）、 词性标注（Part-of-Speech Tagging）、句法分析（Parsing）、语音识别（Speech Recognition）.......

接下来让我们介绍一下语言模型，看看语言模型是怎么发展的吧。

诞生

语言模型是一种用于计算和预测自然语言序列概率分布的模型，它通过大量的语言数据，基于自然语言上下文相关的特性建立数学模型，来推断和预测语言现象。

即：“可根据给定的上下文，预测接下来出现的单词”。

基于统计的语言模型出现很早(1970年，IBM科学家采用基于统计的方法解决语音识别的问题，由此，LM诞生了)。

但由于早期网络结构、数据量、计算机算力的缺陷，早期语言模型存在不少缺点：过拟合、无法处理文本间长距离依赖性....

发展

随着NLP领域更高级算法涌现和硬件能力提升，统计语言模型也快速发展，看看里程碑吧：

图上半部分：语言模型的发展 ；图下半部分：词向量技术进展。

其中，"词向量" 为语言模型提供了更高质量的输入信息(词的向量表示)。

具体来说，词向量通过将文本映射到连续向量空间，实现了从自然语言到数学概念的转换。

向量 = 方向 + 长度。

💡

通俗理解词向量：

词向量提供了将 自然语言 规格化为 模型参数 的能力，使得模型能够理解和处理语言数据。

即：“自然语言(文本) -> 数学概念(向量) -> 模型参数”。

在理解这个规格化过程时，想象在三维空间中，存在无数的向量，词向量技术就是将文本关联到这些向量上，最终用这些向量替代文本作为模型的输入参数。

若你是开发同学，不难看出其实这是一个ETL(Extract Transform Load)的过程。

📌

NLP中的词向量。

答：词的向量表示将单词映射到连续向量空间中。每个单词被表示为一个向量，向量中的每个元素对应一个特征维度。通过这种方式，单词的语义和语法特性被编码到向量中。

  • 它使得计算机能够理解和处理语言数据，是自然语言处理（NLP）任务的基础。
  • 它使得单词的语义和语法特性能够被量化和计算，从而支持各种 NLP 应用。
📌

为何说W2V是词向量表示的重大突破？

答：它通过神经网络的方法，将单词映射到低维向量空间中，并捕捉单词之间的语义和语法关系。

例如，它能够发现 “king” 和 “queen” 之间的关系类似于 “man” 和 “woman”。

拓展：

  • 在训练时，输入是单词的上下文（通常是固定大小的窗口内的单词），输出是目标单词的概率分布。模型通过最小化预测误差来调整单词向量，使得具有相似上下文的单词在向量空间中彼此靠近。

  • 输入是目标单词，输出是上下文单词的概率分布。Skip-Gram 通过调整单词向量，使得一个单词能够尽可能准确地预测其周围的单词。这使得具有相似语义和用法的单词在向量空间中彼此靠近。

基于Transformer的预训练模型

Transformer是几乎所有预训练模型的核心底层架构，是一种深度学习模型。

为何说“几乎”，因为还有其它架构，如：RWKV。

自然语言处理中的预训练，通常指在大量无标注文本数据上训练语言模型。预训练所得的大规模语言模型也被叫作"基础模型（Base Model）"。

在预训练过程中，模型学习了词汇、语法、句子结构及上下文信息等丰富的语言知识。这种在大量数据中学到的知识为后续的下游任务(如：情感分析、文本分类、问答系统等)提供了一个通用的、丰富的语言表示基础，为解决许多复杂的NLP问题提供了可能。

2018年10月，Google提出 BERT，自此各种大型预训练模型爆发式涌现，自然语言处理领域进入了一个新时代。

2018年是预训练模型元年，当时模型参数在几亿左右，2020已出现千亿参数模型，至今已不可估量......

GPT VS BERT

  • GPT：基于Transformer的生成式预训练模型（Generative Pre-trained Transformer）。
  • GPT的核心思想是：利用Transformer模型对大量文本进行无监督学习，其目标就是最大化语句序列出现的概率。

如上所述，BERT与GPT都是基于Transformer架构的预训练模型，它两有何不同呢？见下图：

  • 模型根据上下文预测填空处的单词是什么(双向学习)，这样，模型学会了理解句子结构、语法以及词汇之间的联系。

  • 模型通过大量的文本数据学习，预测给定上文的下一个单词(单向学习)，这样，GPT学会了生成连贯的文本，并能理解句子结构、语法及词汇之间的关系。

相比之下，GPT更接近语言模型的本质，因为它的预训练过程紧凑且有效地再现了自然语言生成的过程。

这种单向学习的训练模式，为将来Prompt的流行埋下伏笔。

预训练模型的使用方式

📖

大规模预训练的目的：提高模型泛化能力。

"泛化"，即通用性。

"预训练+微调大模型"

预训练模型能够将大量通用知识迁移到各种下游任务中，应用时，我们无需自己寻找语料库、从头开始训练大模型，这减少了训练时间与数据需求。其次，微调时可以快速根据特定任务进行优化，降低了模型部署的难度。

一般来说，用于预训练的数据集规模庞大、特征复杂；而用于微调的数据集规模较小、特征明确。

  • 预训练：在大规模无标注数据集上进行模型训练，目标是让模型学习自然语言的基础表达、上下文信息和语义知识，为后续任务提供一个通用、丰富的语言表示基础。
  • 微调：是在预训练模型的基础上进行优化。结合预训练模型的泛化能力、并在小规模的有标注数据集上进行有监督学习，让模型适应特定任务的需求。

"Prompt/Instruct"模式

近年随着生成式大型预训练模型的爆火（如：GPT），"预训练+微调大模型"的使用模式有被一种称为 "提示(prompt)" 或 "指令(Instruct)" 的使用模式所取代的趋势。

📌

Prompt/Instruct 都基于一种思想：

在训练阶段，这些模型通过学习大量的文本数据，掌握了语言的结构、语法和一定程度的语义知识。那么，在应用阶段，通过在输入中提供恰当的信息和指导，可以引导大型预训练模型生成相关性更强切更有用的输出。

这种方式可以看作与模型"对话"，用户提供合适的输入(prompt)，引导模型生成符合特定目标的输出。

而Prompt和Instruct这两种模式在输入类型和任务的性质上有区别。

  • Prompt模式：输入通常是一个词或短语。模型根据提示生成自然连贯的文本，如：输入"从前"，模型返回"有个山，山里有个庙..."
  • Instruct模式：输入是一条明确的指令。模型根据用户要求，完成特定任务。如：输入"请给我讲个故事"，模型返回"从前有座山......"

在当前时代，这两种模式的区别界限被模糊了，"Instruct模式"也被称为"Prompt"，因此后文也将其统称为"Prompt模式"。

两种使用方式的异同

📌

总的来说，两种方式都利用了预训练模型的强大能力，但在实现具体任务时采用了不同策略。

  • "预训练+微调大模型"模式：通过在特定任务上对模型进行微调，使模型更加精确地适应任务需求。
  • "Prompt"模式：直接利用预训练模型的生成能力，通过设计合适的提示来解决问题。

共同点

  1. 两种模型都依赖于大型预训练模型（GPT、BERT）
  1. 两种模型都利用了预训练模型的迁移学习能力，在具体的下游任务上使用预训练好的模型，从而减少训练时间和数据需求。

大模型的经典问题

LLM 幻觉问题

📌

大模型是不完全可信的。

📖

幻觉本质是LLM概率生成与确定性知识间的 根本矛盾。

当前以 RAG为基座、辅以解码优化和强化学习的综合方案，已在工业界显著降低风险（如豆包大模型幻觉率仅4%），但彻底解决仍需理论突破与跨学科协作。

幻觉问题是目前大模型存在的一个普遍问题，通常指模型生成看似合理但实则错误、不符合事实或与上下文逻辑矛盾的内容、甚至编造数据。如：虚构新闻、虚构论文参考文献......

幻觉分类：

  1. 输入输出冲突型：模型输出与用户提供的源内容矛盾（如摘要任务中生成原文未提及的信息）。
  1. 上下文冲突型：生成内容与自身前述回答矛盾（如对话中前后逻辑不一致）。
  1. 事实性幻觉：输出违背世界常理的知识、输出无意义信息。

出现原因：

  1. 数据层面：脏训练数据或训练数据不足，AI模型的好坏取决于训练所使用的数据。
  1. 解码策略(Top-k采样、温度调节)引入的随机性，导致模型输出不准确。
  2. 注意力缺陷(上下文理解缺乏)，Transformer架构中长距离依赖捕捉不足、受制于上下文窗口长度，。
  3. 微调风险：用新知识微调模型反而加剧幻觉(模型学习速度鳗鱼知识更新)。

Agent

💡

什么是Agent(智能体)？

  • 规范理解：能够感知环境并采取行动来实现某些目标或任务的自主实体。智能体可以是软件程序、机器人，甚至是生物学上的实体。
  • 通俗理解：一个能自动干活儿的“小跟班”，它能按照设置的规则或目标，自动完成任务。

目前的AI搜索基本都是Agent模式，甚至多Agent，如：kimi生成文字内容时，首先会直接搜索相关网站。

MCP

推荐文章：学习 MCP 最好的时机是 7 个月前，其次是现在。下边内容摘自此文章。

推荐练手：扣子空间，可为Agent添加MCP。

💡

什么是MCP？

答：一个协议，旨在为大型语言模型（LLMs）应用提供一个标准化的接口，使其能够连接和交互外部数据源和工具。

简介

Model 强调服务主体是 LLM，Context 强调其信息枢纽功能，Protocol 则凸显信息交互的标准化特性。

MCP 如同 USB-C 接口般通过统一协议实现 LLM 与外部能力的高效互联。

以这张图为例，作为算力核心的 LLM，既需要调用本地数据（如磁盘存储），也需对接远程服务（如邮件服务器），而 MCP 正是实现这种多源能力整合的转换器。

其价值在于可以通过标准化协议广泛地接入外部资源，让 LLM 在完成训练后还可以突破被固有的能力边界。

MCP 官网展示的就是最经典的案例：通过接入气象数据接口 LLM 就可以准确回答 “明天会下雨吗” 这类即时性问题。

  • MCP Client：Host 内部负责与 MCP Server 交互的组件。
  • MCP Server：LLM 需要的外部能力的具象化。

目前实现 MCP Server 的编程语言主要是 Node.js、Python 和 Java。

MCP server

MCP Server 是为 LLM 赋能的关键，Server 本身对外暴露的能力又分为三种：

  • Resources：可供加工的数据。数据库、日志等。
  • Tools：执行一个具体的任务。当 LLM 将用户需求拆分为多个具体的子步骤时，可以通过调用 Tools 实现其中的一步或者多步。如：写入数据库、调function。
  • Prompts：可复用的 LLM 提示模板。一些特定逻辑会固化为 Prompts 保存在 MCP Server 中。

一个很好的例子：做饭

Resources 是各种未处理/预处理的食材，Tools 定义了 “菜刀”，而 Prompts 定义了偏好。

当我向一个基于 LLM 扮演厨师的 Agent 提出想吃 “凉拌黄瓜” 时，Agent 基于 LLM 理解了做饭的流程，通过 Prompts 知道了成品一定要放香菜，通过 Resources 得到了老家产的黄瓜，调用了多次 Tools 切出黄瓜块。

MCP 开发协议

MCP server开发协议：JSON - RPC 2.0规范，协议定义了三种类型的消息：

  1. {
    "jsonrpc": "2.0",
    "id": "string | number",
    "method": "string",
    "param?": {
        "key": "value"
    }
}
  1. {
    "jsonrpc": "2.0",
    "id": "string | number",
    "result?": {
        "[key: string]": "unknown"
    },
    "error?": {
        "code": "number",
        "message": "string",
        "data?": "unknown"
    }
}
  1. {
    "jsonrpc": "2.0",
    "method": "string",
    "params?": {
        "[key: string]": "unknown"
    }
}

MCP VS Function Calling

💡

相较于Function Calling，MCP成本更低、通用性更高。

若你是开发同学，可将其对标为 "本地函数(Function) VS 远程过程调用(RPC)"

讲 MCP 肯定会提及 Function Calling，23 年 OpenAI 发布的 GPT Function Calling 也可以实现类似的功能：通过指定的格式将外部工具传给 LLM 用于扩展其能力的边界。

但 Function Calling 是模型能力而非标准协议，不同供应商的 LLM 支持 Function Calling 的格式各不相同。

为了适配一个外部平台同一类工作可能要重复多遍，还有隐含的调优成本，因此基于 Function Calling 的产品化成本高昂。

但MCP 通过统一协议让低成本接入成为可能，当一种成本被快速降低时，想象力的空间就会急速上升。

无论是 Function Calling 还是 MCP，落脚点都是为 LLM 提供更多的业务理解。在已经初步具备与人相近理解能力的基础上，再赋予其足够多、足够广的业务能力，智能体就能脱离于个人展现出通用的生产力，我理解这才是 MCP 如此广泛被讨论的原因。

术语解释

  • NLP：自然语言处理（Natural Language Processing）
  • CNN：卷积神经网络 (Convolutional Neural Network) 是一种深度学习算法，用于图像识别和计算机视觉领域。
  • RNN：循环神经网络（Recurrent Neural Network），应用于需要处理序列数据的领域，如NLP。
  • LSTM：长短期记忆网络（Long Short Term Memory），通过引入"门控机制"，解决了RNN中的梯度消失和梯度爆炸问题。
  • Transformer：一种神经网络结构，引入"自注意力机制"，摒弃传统循环神经网络和卷积神经网络结构。
  • BERT：基于Transformer架构的预训练语言模型（Bidirectional Encoder Representations from Transformers）
  • GPT：基于Transformer的生成式预训练模型（Generative Pre-trained Transformer）。
  • Prompt：提示词工程。
  • AGI：通用人工智能（Artificial general intelligence）
  • LLM：大型语言模型（Large Language Model）
  • COT：思维链（Chain-of-Thought），一种改进的Prompt技术，模仿人类的推理逻辑，构造机器的思维链路。
  • TOT：思维树(Tree of Thought)
  • RAG：检索增强技术（Retrieval-Augmented Generation），为大模型提供外部知识库
  • MCP：模型上下文协议（Model Context Protocol ）
