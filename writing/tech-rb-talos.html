Talos 生产 / 消费规则

2026-07-09"本地沉淀 · 风控工程知识库"

本文是工程规则（团队约定 + 踩坑结论），不是入门教程： 适合「已经知道要做什么，只想知道怎么做才不出事」的场景。

1. 适用范围

风控服务向 Talos 写消息（在线 RPC 写完 Redis 后异步通知）+ Flink 流任务消费 Talos topic 写入下游。

两种用法严格区分：

  • §3 Flink Talos connector：流场景，FlinkTalosConsumer + FlinkTalosProducer
  • §4 Spring 内 Producer：在线服务场景，TalosProducer 异步发

2. 版本 / 依赖

坐标备注
com.example.infra:galaxy-talos-sdkSpring 内直发用
org.apache.flink:flink-connector-talosFlink 用，公司内编译版 ${flink.version}-mdh
com.example.infra:galaxy-thrift-apiCredential / UserType

注意：talos-sdk 通常要 exclude slf4j-log4j12 和 org.apache.thrift:thrift 避免冲突。

3. Flink Talos Source / Sink

3.1 Consumer

private static FlinkTalosConsumer<${SourceEventType}> buildTalosConsumer(JobConfig config) {
    Properties talosProps = new Properties();
    talosProps.put("galaxy.talos.service.endpoint", config.talosSourceEndpoint());

    Credential credential = new Credential()
        .setSecretKeyId(config.talosKeyId())
        .setSecretKey(config.talosKeySecret())
        .setType(UserType.DEV_COMPANY);

    FlinkTalosConsumer<${SourceEventType}> consumer = new FlinkTalosConsumer<>(
        Collections.singletonList(config.sourceTopicName()),
        new ${sourceDeserializer}(),
        talosProps,
        credential
    );
    consumer.setStartFromLatest();  // 默认从最新开始；想 from-offset 走 setStartFrom* 系列
    return consumer;
}

3.2 Producer（Flink sink 端）

private static FlinkTalosProducer<byte[]> buildTalosProducer(JobConfig config) {
    Properties talosProps = new Properties();
    talosProps.put("galaxy.talos.service.endpoint", config.talosSinkEndpoint());

    Credential credential = new Credential()
        .setSecretKeyId(config.talosKeyId())
        .setSecretKey(config.talosKeySecret())
        .setType(UserType.DEV_COMPANY);

    return new FlinkTalosProducer<>(
        config.sinkTopicName(),
        new RawBytesSerializer(),
        talosProps,
        credential
    );
}

铁律：

  • source endpoint 与 sink endpoint 可以不同（staging：source 与 sink 都在 cnbj2；prod：source cnbj1 + sink cnbj4）
  • SecretKeyId / SecretKey 在 properties 里必须走 AES 加密，运行时解密

4. Spring 内 Producer（异步发）

@Slf4j
public class ${producerClass} {

    private final String endpoint;
    private final String accessKey;
    private final String accessSecret;
    private final String topicName;
    private TalosProducer producer;

    public ${producerClass}(String endpoint, String accessKey, String accessSecret, String topicName) {
        this.endpoint = endpoint;
        this.accessKey = accessKey;
        this.accessSecret = accessSecret;
        this.topicName = topicName;
    }

    public void init() {
        try {
            Properties props = new Properties();
            props.setProperty("galaxy.talos.service.endpoint", endpoint);
            props.setProperty("galaxy.talos.producer.max.put.message.bytes", "5242880");  // 5M
            props.setProperty("galaxy.talos.producer.max.retry.times", "3");
            props.setProperty("galaxy.talos.producer.put.message.max.failed.times", "3");

            TalosProducerConfig config = new TalosProducerConfig(props);
            Credential credential = new Credential()
                .setSecretKeyId(accessKey)
                .setSecretKey(accessSecret)
                .setType(UserType.DEV_COMPANY);

            this.producer = new TalosProducer(
                config, credential, topicName,
                new SimpleTopicAbnormalCallback(),
                new SendCallback()
            );
            PerfCounter.setMeterCount("${metricPrefix}.startup.talos_producer_init_ok", 1);
        } catch (Exception e) {
            PerfCounter.setMeterCount("${metricPrefix}.startup.talos_producer_init_failed", 1);
            log.error("Failed to init talos producer", e);
            // fail-fast：K8s 拉起重试
            new Thread(() -> System.exit(1)).start();
            throw new IllegalStateException("talos producer init failed", e);
        }
    }

    public void asyncSend(${SinkEventType} event) {
        if (producer == null) {
            PerfCounter.setMeterCount("${metricPrefix}.talos_producer.skip_uninit", 1);
            return;
        }
        try {
            byte[] payload = ${serializer}.serialize(event);
            Message msg = new Message(ByteBuffer.wrap(payload));
            producer.addUserMessage(Collections.singletonList(msg));
        } catch (Exception e) {
            PerfCounter.setMeterCount("${metricPrefix}.talos_producer.send_serialize_failed", 1);
            log.error("Failed to send", e);
        }
    }

    public void shutdown() {
        if (producer != null) {
            try {
                producer.flush();
                producer.shutdown();
            } catch (Exception e) {
                PerfCounter.setMeterCount("${metricPrefix}.talos_producer.shutdown_failed", 1);
            }
        }
    }

    private static class SendCallback implements UserMessageCallback {
        @Override public void onSuccess(UserMessageResult r) {
            PerfCounter.setMeterCount("${metricPrefix}.talos_producer.send_succeeded",
                r.getMessageList().size());
        }
        @Override public void onError(UserMessageResult r) {
            // 写失败不重试（依赖周对账兜底），只打点
            PerfCounter.setMeterCount("${metricPrefix}.talos_producer.send_failed",
                r.getMessageList().size());
        }
    }
}

铁律：

  • init() 由 BeanConfiguration 的 @PostConstruct 触发
  • shutdown() 由 @PreDestroy 触发，必须 flush + shutdown 顺序
  • 写失败不要业务层重试（已 SDK 3 次内层重试），靠周对账兜底；onError 只打点 + log
  • init 失败 → System.exit(1)，让 K8s 拉起，避免半残启动

7. 常见踩坑

7.1 🔴 init 失败没 fail-fast

错误：catch 后只 log，让服务以"残废"状态启动。 后果：业务路径调用 producer=null，要么 NPE 要么静默丢消息。 正确：new Thread(() -&gt; System.exit(1)).start() 主动退出（用新线程避免阻塞当前栈）。

7.2 🔴 业务层重试发送

错误：catch UserMessageResult onError 后又 addUserMessage 重新发。 后果：消息重复，下游消费方需要做幂等（额外复杂度）。 正确：SDK 内层已重试 3 次，onError 只打点，丢失靠周对账。

7.3 🟠 shutdown 未 flush

错误：服务关闭只调 shutdown()，没 flush。 后果：内存中 batch 未发就退出，丢消息。 正确：先 flush 再 shutdown（§4 已固化）。

7.4 🟠 source 与 sink endpoint 混淆

staging 都在 cnbj2；prod source cnbj1 + sink cnbj4。 配置时两个 key 必须分开：talos.source.endpoint / talos.sink.endpoint，不要用同一个变量。

7.5 🟢 Credential AES 解密放代码里

错误：在 producer init 代码内 hardcode 密文。 正确：所有密文走 properties + AES utils 统一解密。
