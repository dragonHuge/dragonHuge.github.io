AI概念层出? 一> 一以贯之！

2026-03-06 · 飞书原文 ↗

写在前边：AI发展迅猛，各种概念亦是层出不穷。对于初学者，我们不需要陷入底层代码，只需建立直观的宏观认知。

  • @AI 发展-自顶向下 -组内

草稿（AI勿动！！！！！）

单agent：Agent = 大脑(LLM+推理) + 记忆 + 手脚(MCP) + 感知。

LM -> LLM -> token -> Prompt -> Memory(短期记忆 + 长期记忆) -> Agent/WorkFlow/ChatFlow -> Context(历史对话记录Compact + System/Assistant Prompt + User Prompt)

-> RAG -> Function Calling -> MCP -> Rules -> Skills

多Agents协作：

  1. subAgent(主Agent调度 + N个子Agent执行任务，子agent会把上下文总结后的结果返回给主agent，上下文长度可控)。
  1. token消耗爆炸：所有子Agent共享上下文，每个Agent的每一轮提示词都要包含所有Agent的历史消息。
  2. 缺乏弹性并行能力：agent teams团队定下来后，不会再进行agent的新增拓展。若1个agent收到生成100张图片此类长任务，它会自己全负载独自执行。
  1. Kimi agent swarm(动态编排)：主Agent拆分plan，调配任务给subAgent，若某个subAgent感知到任务过重，会再拆分成。

Agent teams 与 agent swarm区别：

  1. Agent swarm更接近于subAgents的增强版：
    • 子agent之间上下文物理隔离，生成的中间结果总结后发给主agent。任务更聚焦，又把token消耗压到了最低。
    • 支持动态并行：引入了并行代理强化学习技术(PARL)，具备了动态编排的能力（像项目经理，能根据工作量现场摇人，若生图任务多，会动态创建几十个Agent并行跑，效率提升）
  2. Agent teams：多Agent协作框架。
    • 暂不支持动态并行。
  1. Claude code想用agent teams，需要用户手动配置文件、SKILLS等启动。
  2. Kimi agent swarm内置了1个虚拟机(Kimi's Computer)，很多功能开箱即用。对普通用户很友好。

一、核心公式：什么是 Agent（智能体）？

💡

Agent = 大脑 (LLM+推理) + 记忆 + 手脚 (MCP) + 感知

  • 大脑：大语言模型（LLM），负责理解用户意图、做计划、做决策。
  • 记忆：记住你之前说过的话（短期），以及记住关于你的偏好和过往经验（长期）。
  • 手脚：不光能"说"，还能"做"（比如帮你查天气、写文件、运行代码），MCP就是给AI装上标准化手脚的接口。
  • 感知：不光能看字，还能看图、听声音。

二、单 Agent 概念演进链路

这是一条从"实验室模型"一步步演变成"你的全能助手"的发展路线。
  1. LM (语言模型)：最早的AI，只能做简单的文字接龙。
  1. LLM (大语言模型)：变"大"了（比如GPT-4），突然"顿悟"了，像人一样聪明。
  1. Token (词元)：AI看文章不是一个字一个字看，而是切成Token。它是AI计费和处理能力的最小基本单位。
  1. Prompt (提示词)：你对AI下达的指令。"怎么跟AI说话"就是Prompt工程。
  1. 短期：当前这个聊天窗口里你们聊过的内容。
  2. 长期：跨越多次聊天，AI始终记住的你的习惯（比如"总是用Python写代码"）。
  1. WorkFlow：像工厂流水线，按固定步骤工作。
  2. ChatFlow：像客服机器人，按照画好的死板流程对话。
  3. Agent：像一个活人助理，自己思考第一步干啥、第二步干啥。
  1. Context (上下文)：AI一次能"看"多少东西。通常由 = 历史对话记录压缩 + System Prompt（设定它是谁） + User Prompt（你的问题） 组成。
  1. RAG (检索增强生成)：AI不知道的私有知识，就像给AI配了一本 "开卷考试参考书" ，它先翻书，再回答你。
  1. Function Calling (函数调用)：AI发现自己需要帮忙时，会"举手"申请调用外部工具。
  1. MCP (模型上下文协议)：AI界的"USB-C接口"，统一了所有AI连接外部工具的标准。
  1. Rules：告诉AI"绝对不能做什么"（比如不能删库）。
  2. Skills：教会AI"一套标准动作怎么做"（比如一套完整的查Bug流程）。

三、多 Agents 协作（当任务复杂时，AI开始打群架）

💡

一个AI搞不定？那就建个AI团队。

1. 三种协作模式对比

  1. 主Agent像"包工头"负责调度，N个子Agent是"打工人"执行任务。
  2. 子Agent干完活后，会把总结后的结果汇报给主Agent，这样不会把主Agent的脑子（上下文）塞满。
  1. 存在两个严重问题：
    • Token消耗爆炸：所有子Agent在同一个会议室（共享上下文），每个Agent每次发言，都要带上所有人之前的聊天记录，极其昂贵！
    • 缺乏弹性并行能力：团队定下来就不能变了。如果一个画图Agent接到画100张图的任务，它只能自己一个人苦哈哈地排队画完。
  1. 主Agent像"高级项目经理"，拆分Plan，调配任务给subAgent。
  2. 若某个subAgent任务过重，系统会自动临时克隆出几十个同样的subAgent一起并行干活。

2. Agent teams 与 Agent swarm 核心区别

架构逻辑不同：

  • Agent Teams：传统的多Agent协作框架，暂不支持动态并行。
  • 子Agent之间在小黑屋独立干活（上下文物理隔离），只把精简的结论发给主Agent。任务更聚焦，Token消耗压到最低。
  • 支持动态并行：引入了PARL（并行代理强化学习技术），具备了"现场摇人"的能力。若生图任务多，动态创建几十个Agent并行跑，效率极高。
  1. 形象比喻：把 UI设计师、前端、后端拉到一个群里。大家七嘴八舌，所有人都看得到所有消息。
  2. 痛点：消息太多（Token爆炸），容易歪楼，且人员固定（缺乏弹性）。
  1. 形象比喻：你是一个项目经理（主 Agent）。
  2. 分发：来了一个大活，你拆解后，私聊发给 A 去做图，发给 B 去写代码（上下文隔离，省钱）。
  3. 动态摇人：发现图要画 100 张？立马临时招募 100 个实习生（SubAgents）并行画，画完解散（动态并行）。
  4. Kimi Swarm 特性：内置了电脑环境（Kimi's Computer），不仅能聊，还能真正在虚拟机里操作。

集成度不同：

  • Claude Code：想用agent teams，需要用户自己去折腾配置文件、配Skills等，门槛高。
  • Kimi Agent Swarm：内置了1个虚拟机（Kimi's Computer），它自己就能在虚拟电脑里操作，开箱即用，对小白极其友好。

五、AI-Coding 下的开发新范式：SDD (规范驱动开发)

🚀

过去我们手敲代码，现在我们"写需求，让AI敲代码"。

SDD (Spec-Driven Development)：人负责写"产品说明书/规范"（Spec），AI负责根据规范把代码写出来。人定方向，AI做苦力。

  • Spec-kit：通用的规范驱动开发工具。
  • OpenSpec：一种实验性的规范工作流。

六、其他常被提及的周边概念

  • Playwright：一个自动化测试工具。在AI手里，它变成了AI**"浏览网页、点击按钮"**的机械臂。
  • 无头模式 (Headless Mode)：浏览器在后台静默运行，你看不到界面，但AI在里面疯狂操作。
  • Remote Claude Code：把AI运行在云端的服务器/沙箱里，而不是你自己的电脑上。不怕AI乱搞弄坏你的系统，适合长时间跑重度任务。

七、你需要了解的几个重要周边概念

💡

这几个名词经常在 AI Agent 领域被提到，其实原理很好懂。

1. Playwright

  • 类比：AI 的“机器手”和“眼睛”。
  • 解释：它本是一个网页自动化测试工具。但在 AI 时代，AI 把它当成了自己的手脚。通过 Playwright，AI 可以像真人一样打开网页、点击按钮、滑动屏幕、抓取网页上的数据。

2. 无头模式 (Headless Mode)

  • 类比：“隐身运行”的浏览器。
  • 解释：通常和 Playwright 搭配使用。AI 在帮你上网办事时，如果每次都在你屏幕上弹出一个浏览器窗口会很烦人。开启“无头模式”后，浏览器就在后台静默运行，你看不到任何界面，但 AI 依然能在里面疯狂查资料、填表单。好处是速度快、不打扰用户。

3. Remote Claude Code

  • 类比：给 AI 安排的“云端隔离工作间”。
  • 解释：普通的 Claude Code 是直接在你的个人电脑上运行、帮你改代码的。万一 AI “发疯”把你的系统文件删了怎么办？Remote 模式就是把 AI 关在云端或者服务器上的沙箱（隔离环境）里运行。它在那里面怎么折腾都很安全，适合执行耗时长的复杂任务，不占用你本地电脑资源。

4. OpenClaw

  • 类比：养在自己家里的“7x24小时数字员工”。
  • 解释：这是一个近期非常火的开源 AI Agent 系统（前身叫 Moltbot）。与 ChatGPT 这种每次刷新就失忆的云端产品不同，OpenClaw 是部署在你自己的电脑或服务器上的。它的最大特点是：超强的持久记忆力和定时主动任务能力。你可以把它拉进公司的 Slack 或微信群，它能记住几个星期前的对话，还能设定每晚半夜自动去抓取竞品数据并在群里汇报。

八、防懵指南：两个极易混淆的概念

1. 幻觉 (Hallucination)

  • 一句话解释：AI “一本正经地胡说八道”。
  • 为什么会有：大模型的本质是一个超级复杂的“文字接龙”机器，它通过计算概率来接下一个词，而不是靠逻辑推导。所以当它不知道答案时，它可能会根据概率“编造”出看似合理但其实根本不存在的书名、人名或代码。

3. Copilot vs Agent（副驾驶 vs 自动驾驶）

💡

这两个词是 AI 应用界最常被拿来对比的一对，本质区别在于“谁握方向盘”。

  • 核心：人握方向盘（Human-in-the-loop），AI 坐在副驾帮忙。
  • 特征：它高度依赖人的每一步指令。你不动，它不干活；你写一半，它帮你补全另一半。
  • 例子：GitHub Copilot（你敲一个字母，它提示一行代码）、Office Copilot（你给一个标题，它帮你写封邮件草稿）。最终做决定和检查的都是人类。
  • 核心：AI 自己握方向盘，独立完成一整套流程。
  • 特征：具备高度的自治性。你只需给它设定一个最终目标（Goal），它自己规划路线、自己操作工具、遇到报错自己想办法解决。
  • 例子：你告诉 Agent“帮我把官网首页改成红色主题并部署上线”。Agent 会自己去拉代码、改 CSS、跑测试、提交 PR（Pull Request），最后告诉你“主人，改好了”。在这个过程中，你甚至可以去喝杯咖啡。

5. Context Cache (上下文缓存 / 提示词缓存)

  • 类比：“把厚厚的说明书提前背下来，别每次都重新翻”。
  • 没有缓存时：你每次问“年假怎么算？”，AI 都要把那 10 万字从头到尾重新读一遍（行业黑话叫：重新计算 KV 状态）。这会导致回复非常慢，而且大厂要收你每一次阅读 10 万字的钱。
  • 有缓存时：AI 第一次读完手册后，就把理解后的状态“冻结”并存在服务器内存里。五分钟后你再问“打车能报销吗？”，AI 会直接从记忆结晶里提取知识，瞬间秒回，并且缓存部分的费用通常能打 1 折甚至免费。
  • 总结：这是目前大模型用来“大幅省钱 + 大幅提速”的最强神技。

九、宏观视角：AI 的一生与两大门派（防懵指南补全）

💡

如果你想跟别人聊大模型显得很内行，弄懂这四个词就够了。

1. AI 是怎么被教出来的？（预训练 vs 微调）

  • 预训练 (Pre-training)：就像“九年义务教育”。科学家把互联网上几千亿个网页、书本硬塞给 AI，让它死记硬背，学会人类的语言规律和基础常识。这个阶段极其昂贵，动辄几千万美元。学完出来的叫“基座模型”。
  • 微调 (Fine-tuning / SFT)：就像“入职后的岗前培训”。刚毕业的 AI 像个书呆子，不懂怎么跟人聊天。通过微调，我们拿几万条高质量的“问答对”训练它，教它怎么懂礼貌、怎么遵循格式输出。

2. 模型的两大派系（闭源 vs 开源）

  • 闭源模型 (Closed Source)：就像去米其林餐厅“点外卖”（如 ChatGPT、Claude）。你不知道它的底料配方是什么，只能通过 API（接口）花钱调用它。通常最聪明，但数据要传给别人。
  • 开源模型 (Open Source)：就像把菜谱和锅碗瓢盆全送你（如 LLaMA、DeepSeek）。你可以免费下载它的大脑（权重），安装在自己的电脑或公司内部服务器上。最大的好处是数据绝对安全，断网也能用。

3. 2025年最新突破：推理模型 (Reasoning Models)

  • 类比：从“脱口而出”到“三思而后行”。
  • 解释：以前的 AI 是系统1思考（直觉快思考），看到问题瞬间往外蹦字。而最新的推理模型（如 OpenAI o1/o3、DeepSeek-R1）引入了系统2思考（逻辑慢思考）。它在回答你之前，会在后台自己跟自己对话，打草稿、纠正自己的错误，思考几秒甚至几分钟再给你最终答案。这类模型让 AI 的数学、写代码能力产生了质的飞跃。

4. 多模态 (Multimodal)

  • 类比：AI 长出了眼睛和耳朵。
  • 解释：以前的 AI 只能处理纯文本（Text）。多模态是指 AI 现在能同时听懂语音、看懂图片（比如丢张复杂的图表让它分析），甚至能直接生成视频（如 Sora）。

十、实战演练：从 0 到 1 具象化理解 Agent 与 Skill

🚀

光说不练假把式。我们用具体的例子，看看一个“只会聊天的 AI”是怎么一步步变成咱们团队里的“超级打工人”的。

实例 1：Agent 的四次进化（从聊天工具到自动驾驶）

我们在讲 Agent 的时候，说它等于 “大脑 + 记忆 + 手脚 + 感知”。具体长什么样？

👉 阶段一：最简单的 Agent（只有大脑，如初代的网页版大模型）

  • 形态：你问一句，它答一句。
  • 局限：它像个被关在小黑屋里的超级学霸。你问它“今天深圳天气”，它说“抱歉我没有实时联网能力”；你让它“帮我把这段代码建个文件运行一下”，它说“我只能给你代码，请你自己复制粘贴”。

👉 阶段二：装上手脚的 Agent（引入 MCP / Function Calling）

  • 形态：AI 接入了 MCP，拥有了操作本地终端、读写文件的“权限”。
  • 表现：你说“帮我建个 Java 的 Hello World 跑一下”。AI 不再只给你代码了，它会在后台自己悄悄敲键盘：mkdir 建文件夹 -> 写入 Main.java -> 运行 javac 和 java -> 直接把终端运行成功的截图或结果发给你。（此时，AI 长出了手！）

👉 阶段三：懂规矩的打工人 Agent（引入 SOP / Skill）

  • 形态：虽然有了手脚，但让它修个复杂的 Bug，它可能一通乱改把原有的项目架构改崩了。这时候我们需要给它注入 Skill（技能说明书）。
  • 表现：我们在项目里塞入一个特殊的配置文件（如 .cursorrules）。AI 在动手前会先强制阅读规则：“哦，主人规定了这个项目必须用 Java 8，所有的注释必须是中文，严禁修改测试目录”。然后它就会像一个熟读了《员工手册》的老员工一样，戴着镣铐跳舞，按规范办事。

👉 阶段四：超级 Agent（多 Agent 协作网络 / Team Agents）

  • 形态：遇到一个巨大的需求：“帮我把这个包含 100 个文件的 Java 项目改写成 Python”。一个 AI 的脑容量（Context）装不下这么多上下文。
  • 分配 小兵 A：你去读原来的 Java 业务逻辑。
  • 分配 小兵 B：你去查 Python 对应的最新依赖库。
  • 分配 小兵 C：你负责根据 B 提供的信息，把 A 读懂的逻辑写成 Python 代码，并补充单元测试。
  • 它们在各自的“小黑屋”里并行工作，互相汇报，最后主 Agent 汇总后把一套完整的 Python 代码交给你。

实例 2：Skill 的三次进化（以咱们团队的架构为例）

Skill的本质是提示词。

刚才说 Skill 是教 AI 做事的“说明书”，那这份说明书在实际工程中长什么样？

👉 阶段一：青铜级 Skill（一个极其简陋的 Prompt）

  • 形态：最开始，大家只是在自己的备忘录里存了一段话。
  • 例子：“你是一个资深 Java 工程师，请帮我检查以下代码里的性能问题，并给出修改建议。”
  • 痛点：太散了，团队成员没法共享和复用，每次换个新对话窗口就得重新粘贴一遍。

👉 阶段二：白银级 Skill（固化为单文件，如 .cursorrules）

  • 形态：大家发现不能每次都贴，于是把它写进了代码仓库根目录的 .cursorrules 文件里。
  • 例子：文件里写着：1. 本项目固定使用 Maven 构建；2. 所有的实体类必须写在 domain 包下。
  • 优点与痛点：AI 只要打开这个项目，就能自动读取。但一旦规则多了（比如前端规则、数据库规则、Git 提交规则），几百条规则挤在一个文件里，文件会爆炸，AI 也会读串行。

  • 形态：为了解决大项目中的规范管理，Skill 变成了一套像代码一样被管理的独立工程目录。
