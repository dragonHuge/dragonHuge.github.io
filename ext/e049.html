摘 要

投几十份简历没回音，改简历改到麻木——这是求职的常态。一个 6.3 万星的开源项目把 Claude Code 改造成求职流水线：先给岗位打分，再起草、由第二个 AI 代理评审、编译 PDF 逐页检查，最后用 ATS 的视角反查文本层。本文拆解它的四道质量门、那条“不许编造”的硬规则，以及真实门槛。

2025 年底，地球物理学家 Mads Lorentzen 的职位被裁掉了。

他没有立刻开始海投，而是花了几个月，给自己写了一套求职工具。结果写在项目 README 的第一屏：69 份定制申请，20 次首轮面试，1 份签下的合同。2026 年 6 月，他以 AI 工程师的身份入职。

这套工具就是今天的主角。截至 2026 年 10 月 22 日，MadsLorentzen/ai-job-search 在 GitHub 上拿到 63.2 k star、19.5 k fork，MIT 协议，主语言 Python——fork 数是 star 的三分之一，这个比例在开源项目里极不寻常，原因写在它的口号里：fork it and own it，复制一份，改成你自己的。

项目吉祥物 Pip：一只打领带、叼着信封的信使鸟

它到底是什么

一句话：把 Claude Code 变成一个求职工作台，所有数据都在你自己的机器上。

它不是一个网站，也不是一个 App。你复制仓库、填好个人档案，然后在 Claude Code 里敲斜杠命令：/setup 建档、/scrape 找岗、/apply 投递、/outcome 记录结果。全程没有服务器，材料不上传，也不经过任何第三方简历服务。

这个“本地优先”不是技术洁癖。一份简历里有姓名、电话、住址、每一段雇佣关系、薪资期望——把它交给一个在线简历优化网站，等于把职业档案的完整副本交给陌生人。本地运行意味着这些数据只在你自己的磁盘上，代价是你要自己装环境。

主流程四步，加一个可选的批量筛选：

命令干什么
/setup建档。三条路：读你的 documents 文件夹（CV、LinkedIn 导出、学位证）、粘贴一份简历、或走一遍访谈
/scrape多个招聘门户搜索、去重、按匹配度排序
/rank可选。批量给新岗位打分，deal-breaker 一票否决，过期岗位标掉
/apply完整流水线：评契合度 → 起草 → 评审 → 编译检查 → 输出核对清单
/outcome记录结果（面试到第几轮、offer、拒信、没回音），归档材料；10 天没动静会提醒你跟进

需要说明的是：它不会替你点“提交”。最后一步永远是你自己按下去的——这个设计贯穿整个项目。

四道质量门，才是它真正的差异

大部分“AI 改简历”的工具，做到“生成一段文字”就结束了。这个项目把力气花在了生成之后。

第一道门：编译成 PDF，然后逐页看。简历和求职信都是 LaTeX 排的。LaTeX 的坑在于：源文件看着没问题，编出来的 PDF 会出事——职位标题被挤到下一页成了孤行、求职信溢出到第二页、列表项的字体悄悄回退成正文体。/apply 的做法是编译完自己读渲染出来的页面，不干净就改，直到简历正好两页、没有孤立的职位标题，求职信正好一页、签名可见、字体一致。

第二道门：用 ATS 的视角反查文本层。ATS 是招聘系统里的简历筛选程序。它读的不是你看到的那张漂亮页面，而是 PDF 里抽出来的文字。LaTeX 生成的 PDF 有个隐蔽问题：邮箱位置可能是图标字形，抽出来是一串乱码；多栏排版抽出来可能行序交错。/apply 用 pdftotext 把编译好的简历文字层抽出来，逐项验证：联系方式是不是字面文本、阅读顺序对不对、岗位关键词覆盖了多少。这一步模拟的是机器审稿，不是人眼审稿。

第三道门：超页了砍哪一行，要算过。简历超过两页必须砍。多数模板的做法是按时间从最老的开始删。它不这么干：给每一行按三个维度打分——与目标岗位的相关性、在文档里的唯一性、求职信是否依赖它——然后砍总分最低的那行。一条老经历如果正好命中岗位关键词，会排在一条没命中关键词的近期经历前面。

这个设计解决的是一个真实矛盾：招聘方既要求“两页以内”，又要求“看得到与岗位相关的东西”。机械按时间砍，砍掉的常常正是最相关的那段。

第四道门：写的人和批的人，不是同一个。起草完，系统会派一个全新上下文的评审代理：它自己去研究这家公司，然后挑毛病——漏掉的关键词、太泛的表述、框架不对的地方。起草代理根据批评修改，再输出。同一个模型自查，容易自己给自己打高分；换一个干净的上下文，才有第三方视角。

它还会干这些活

除了主流程，还有十来个命令。挑六个值得说的：

/interview 按面试阶段生成准备包：那一次投递的原始岗位、面试官真正看过的那版简历和求职信、前面几轮记下的反馈，全在包里。它会调研公司和面试官，但有条规矩叫 verify-before-use——查不到出处的不写。然后把可能的问题映射到你自己的 STAR 例子上，还能模拟面试。遇到答不上来的问题，给的是“诚实的过渡答案”，不是编一段经历。

/gmail-sync 读你的邮箱，从面试邀请、测评链接、offer、拒信里提取状态，批量列出来等你批准才写进跟踪表——每一条都标了来源邮件。offer 那类它不自动改，因为那是你的决定。

/notion-sync 把流水线单向同步到 Notion 数据库，手机上看进度用。只读，不回流，文档只同步文件名。

/upskill 对比你的档案、已投岗位和被筛掉的岗位，出一张技能缺口热力图，配学习资源和时间估算。

/add-portal 给它一个你本地招聘网站的地址，它去研究搜索 URL 规律、结果页结构、robots 规则，生成一个同规格的搜索技能，跑通一次真实查询才注册。

/expand 扫你档案里已经填过的 GitHub、作品集、Kaggle、Google Scholar，把文档里没写明的能力补进档案，带来源标记。

一条不许越界的硬规则

这个项目最值得抄的，是它对“编造”的态度。

ATS 关键词检查那一步，规则写得很死：profile 里真支持的关键词才加，不支持的，承认是缺口，绝不硬塞。简历和求职信里的每一条陈述，都要回到你的实际档案里核对。

语言能力有个单独的闸门：岗位要求一门你根本没声明过的语言，硬拒；要求你声明过的语言但级别更高，只标记、不自动拒——留给你的判断，而不是悄悄丢掉。

这条规则和作者的经历有关。他在 README 里写，自己对每一位谈过的雇主都坦白了用这套工具，结果多数时候不是扣分，反而引发了真正的技术讨论。因为面试官会问你简历上的每一行。

它撞上的，是整个行业的焦虑

就在几天前，英国学生雇主协会公布了一项覆盖 155 家大型毕业生雇主的调查：92% 的雇主遇到过或怀疑求职者不当使用 AI，比上一年的 85% 又高了一截；最常见的不当使用不是写简历，而是视频面试和在线测评里的实时辅助。有能源公司因为收到 1.2 万份毕业生申请、比去年多一成，提前关闭了招聘通道。

但另一边的事实更有意思：招聘方识别 AI 的能力，其实远没有传说中那么强。他们抓到的往往不是“机器写的证据”，而是“空洞、没有细节、读完记不住”——被抓的是敷衍，不是工具。有调研显示，超过四成的雇主曾因简历造假撤回 offer，而这跟用不用 AI 关系不大，跟写没写清“你到底干了什么”关系极大。

这个项目正好站在焦虑的反面：它不追求投得多（69 份，不是 690 份），它给每个岗位打契合度、让 deal-breaker 一票否决，它在关键词上宁留缺口也不编。它压缩的是排版、核对、找关键词这些机械劳动，不是判断力。

现实的门槛

四个字先放这儿：并不轻便。

• Claude Code 没有免费额度。需要 Pro/Max/Team 订阅，或者按量付费的 API 额度。框架本身 MIT 免费，模型调用不免。

• 环境依赖不少。Python 3.10+、Bun、完整的 LaTeX（简历用 lualatex、求职信用 xelatex）。用 TinyTeX 这类精简发行版还得补装字体包，这一步最容易卡人。

• 招聘门户以丹麦为主。内置的四个站点是 Jobindex、Jobnet 这些丹麦站；跨境可用的有两个：LinkedIn 公开职位（零依赖，但自动化访问违反其条款，只能低频个人使用）、freehire 聚合 API（多市场）。其他地区要用 /add-portal 自己生成。

⚠️ 隐私这条必须照做：公开仓库的 fork 一定是公开的，而 /setup 会把姓名、联系方式、工作经历、薪资期望写进被 git 跟踪的文件。自用的正确姿势不是 fork，是私有仓库 + 把原仓库设为 upstream。

• 岗位描述被当作不可信输入（不执行里面夹带的指令、不点正文里的链接），但官方明说：这是指令层的防御，不是沙箱。

还有一句得说清：69 投 20 面是作者本人的结果，不是产品承诺。转化率取决于市场、时机、岗位匹配和你面试的表现——自动化能帮你的，是把材料做到不该被刷掉的水平。

顺便说下为什么“69 份”这个数字重要。业内把无限海投叫 spray and pray（喷完就祈祷）：同一套模板投两百个岗位，招聘方一眼能看出没有针对性，很多连初筛都过不去。少而定制本身就是策略——投得多，不等于投得对。

写在最后

求职这件事里，最容易被自动化的其实是最不体面的那部分：把同一段经历改写成十个版本、调字号让它刚好两页、对着岗位描述找关键词、检查邮箱在 PDF 里有没有变成乱码。这些活占掉了大量时间，却不产生任何判断。

这个 6.3 万星的项目做的，就是把这部分变成流水线，并且给每一道工序装了质量门——编译后要看、机器读的要模拟、砍内容要算过、写的人要被别人批。

而“要不要投这家”“我到底会什么”“面试时怎么讲那段经历”，它一个都没替你决定。这也解释了作者那句最实在的话：坦白用了工具，反而成了技术讨论的开场。在一个 92% 的雇主都在怀疑 AI 的市场上，诚实不是道德姿态，是唯一能过面试的策略。
