前言

最近，我给自己拉了个工作群。

只不过群里除了我和同事，还有Agent

要知道大部分Agent工具，大家都是各用各的。让AI帮忙做个方案，写好了先发到群里给大家看。等大家批注完，再把意见整理好转给AI。等它改完，又得发回群里。

明明是找AI来帮忙，结果自己成了它和同事之间的传话筒。那把AI和同事都拉到一个群里，不就少折腾一圈了吗？

最近爆火的Teamily，就是这个思路。

它看起来像个聊天软件，加好友，也可以把Agent拉进群。大家在同一个地方讨论需求、补充资料，需要它帮忙时就直接发消息，产出的文件也会发回群里。

而且，除了和真人一起协作，也可以拉几个不同的Agent，让它们分工干活。

Teamily

人和 Agent 一起聊

平时打开桌面端Agent，左侧大多是自己过去的历史对话记录。今天让它查资料，明天让它做网页，点开哪条，就回到那次任务里。

而Teamily的左侧看起来更像聊天工具。这里有不同Agent的聊天框，也有真人好友和群聊。

你可以添加好友，直接和人交流；聊到需要AI帮忙的事，再让Agent加入。

这和把AI的回答截图、复制，再发给别人看，是两种完全不一样的感受。

资料可以直接放进对话里，谁有补充就在这里说，Agent 做出的内容也会回到这里。后面要继续讨论，不必先猜大家看的是哪一版。

这样一件事从商量、补充资料到做出内容，都可以在参与者共同看到的对话里继续往下走。

Agent 团队接力

除了拉同事一起协作，Teamily 还内置了不少各有所长的 Agent。

比如前端开发、提示词优化、数据分析，都可以像找好友一样，点开聊天。它也有现成的 Agent 团队，可以直接选一支来做事。

这次，我在 Design Review Studio 群里发了一份挂烫机的商品资料，请 Teamily Agent 安排团队做一张产品介绍页。

我准备的材料很简单。一份挂烫机的商品介绍文档，文档里只有产品定位、规格和适用场景，外加一张产品图就是全部了。

在收到我的任务后，Teamily Agent先是列出了五项任务。

负责用户研究的Agent先读商品资料，整理目标用户、卖点和页面该讲的内容；另一个Agent搭页面架构，视觉Agent准备产品图片。等这些东西齐了，再由设计 Agent 整合成网页，最后交给审查Agent检查。

我只说了想做什么，它就把要做哪些事，分别交给谁，都安排好了。

更细的一点是，页面架构和视觉素材可以同时做，设计需要接住前面的两份成果，审查则要等页面完成。计划里连这些先后关系都写了出来

接下来，几个 Agent 陆续在群里交出结果。

有人梳理页面该讲什么，有人准备产品视觉，设计 Agent 再把前面的内容整合成网页。我可以分别点开这些结果，也能看到它们最后是怎么放进页面里的。

第一版网页的首屏已经有产品图和主文案，往下还有卖点、使用场景等内容。从页面上看，它已经是一张完整的商品介绍页了。

不过网页做出来之后，审查Agent又发来一份报告，指出四个发布前需要处理的问题。

其中最容易理解的是手机窄屏下页头被挤出屏幕；另外还有深色模式下文字不够清楚，以及主题切换按钮对屏幕阅读器不够友好。

审查报告出来后，群里的同事也看到了第一版网页。

他注意到「使用场景」还是静态排列的，通勤、短途差旅和租房三个场景都摆在那里，读者只能顺着往下看。

他直接在群里@Teamily Agent，让它安排团队先修好报告指出的四个问题，再把三个使用场景做成可以点选切换的模块，改完后重新检查一遍。

Teamily Agent 收到后，先安排负责内容的 Agent 梳理三个场景，再由 UI Designer 修改原来的网页，最后交给审查 Agent 复测。

复测也没有一次通过。审查 Agent 又找出了遗留问题，设计 Agent 接着修改。

这样来回几次，页面里的三个使用场景已经可以点着切换，手机端布局也重新调整了。

回头翻这段群聊，最初发进去的商品资料、几个 Agent 交出的结果、审查报告、同事提出的修改意见，还有改好的网页，都能在这里找到。

下一次要接着改，也不用先把前面发生的事重新整理一遍。

最后给大家看看网页的整体效果。

https://teamily.ai/link/OZlxJo5Gg2A

把分工练成循环

做完这张网页，我又照着这次的分工，在群聊里搭了一条智能体循环。它的作用就是提前安排好谁先接任务，做完交给谁，审查发现问题又该找谁改。

几位 Agent 沿着连线，依次完成需求梳理、页面结构、视觉素材和界面设计，最后交给 Accessibility Auditor 审查。

图的末端是我，审查放行后，结果就交到我这里。

每个节点要接收什么、交出什么，我都写在了图上。审查没通过时，也设好了按问题类型退回的路线。

前面在对话里发生的那些交接和修改，现在能在一张图里看清。出了问题，顺着连线就知道该找谁改。

这次我只把几位 Agent 和自己接进了图里。如果以后需要另一支团队参与，也可以把其他群组已发布的循环接进来，让它负责其中一段工作。

大伙也不用担心改草稿会直接影响已经启用的那版；确认好后再点“发布循环”，新改动才会生效。

循环发布后，我又换了一份桌面风扇的商品资料和产品图，从同一个入口发起任务。

这次没有重新安排 Agent，也没有重画流程，只让它按已有的分工再做一张产品介绍页。

之后，任务就沿着我设定好的循环往下走。最后送到我这里时，已经是一张可以打开的桌面风扇介绍页。

产品换了，走的还是前面那条流程。我不用重新安排谁先做、做完交给谁。

多人编辑同步

前面说过，Teamily 可以邀请别人一起办公。等 Agent 把网页做出来，大家也能直接打开同一份页面。哪里需要调整，就在对应的位置留言；想自己动手改，也可以同时编辑。

意见留在哪里、页面改了什么，参与的人都能看到。需要 Agent 处理的意见，还可以一起选中，交给它接着改。

写在最后

平时用 AI，我和它聊完，还是要回到另一个群里跟人商量。Teamily 让我觉得有意思的，是它把这两个地方变成了同一个地方。

这次也不是把资料交给 Agent 就能等着收工。第一版网页被审查出问题，同事提出新想法后，页面又改了几轮。Agent 能接着前面的成果做，但最后改得对不对，还是得人来看。

回头看，网页只是这次做出来的成果。Teamily 2.0 更值得我继续关注的，是它让人、Agent 和成果留在同一个地方，一件事可以在这里接着讨论、修改，再往下做。
