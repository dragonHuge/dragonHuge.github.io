原文沉淀

本文介绍了淘特App推出的动线Agent——一套由大模型（LLM）驱动的全链路用户转化引导系统。针对近90%到端用户未完成转化的痛点，该系统围绕用户旅程（ 进端/在端/离端 ）部署了三个差异化智能体。三者均取得显著业务增益，整体峰值增量GMV占比超大盘5%，且通过技术手段将token成本降低60%以上。未来将推动三端从数据回流走向共享决策状态，构建统一的用户智能体。

摘要

在注意力经济时代，短视频足够好刷，游戏和内容 App 也在持续争夺用户时间。如果用户打开了一个购物 App，本身就是一次昂贵且高价值的行为。一般电商App 的访购率约为百分之十几，这意味着近百分八九十的到端用户并没有完成转化。从入端到成交，用户并不会沿着一条直线前进，而是会经历浏览、比较、犹豫、放弃与回归，如何在这个过程中完成对用户的转化引导？

本文提出 动线 Agent —— 一套面向淘特场景、由 LLM 驱动的全链路用户引导系统。它围绕用户「进端 → 在端 → 离端」三个核心时机，部署三个差异化的智能体，构建三种互补的决策模式：

  • TensorLiftAgent（精细化模式）于进端时机，通过多维用户特征张量分解，生成网格人群和差异化的权益策略，后台天级寻优、入端毫秒命中，结合AB 实验持续汰换策略做大SOTA桶；
  • PeiAgent（快决策模式）于在端时机，端云协同实时计算用户的个性化购物热情指数（PEI, Purchase Enthusiasm Index），当判断用户的指数衰减达到某个阈值，立即触发基于行为序列与意图的AI推理的权益干预；
  • DeepFlowAgent（慢思考模式）于离端未购时机，异步执行长链 CoT 深度归因推理，生成个性化权益与营销话术并多渠道召回。

效果上，三个模式均上线并达到一定规模效果：进端增益 ROI 提升三成左右；在端与离端的增量 ROI 均超过目标十个百分点以上。同时在token规模上，消耗峰值达到数百亿token/日的规模，通过技术手段也将token成本降低了超一半以上。目前三种模式只做到了数据层面的回流，还没有形成用户视角的联动，这也是下一阶段重点工作。

用 AI 重新做一遍用户动线

这一部分回答两个问题：1）用户动线agent是什么？ 2）动线agent的三种模式为什么？

▐ 动线agent是什么？

真实的用户购物过程往往不是“进入—浏览—下单”的直线，而更像：

打开 APP → 搜索商品 → 比较几款 → ... → 返回搜索 → 再看商详 → ... → 犹豫 → 暂时离开 → 跨APP对比→... → 可能再次回来。

在这个过程中，用户的意图也在变化：反复查看某件商品，可能意味着需求明确但价格尚未达到预期；频繁换搜索词，可能是在细化需求，也可能是一直没有找到合适的商品；加购后离开，既可能是等待优惠，也可能只是被其他事情打断。因此，问题不只是“有没有发优惠券”，而是：平台是否理解了用户当下需要什么，是否在合适的时刻采取了合适的动作？

用户动线agent是一套面向电商用户全动线、由 LLM 驱动并受确定性规则约束的智能经营系统，在不同时间尺度上完成用户理解、策略生成、权益干预、效果验证与持续优化。

###

▐ 三种时机，三种决策模式

如果目标都是促进转化，为什么不使用一个 Agent 处理所有场景？

原因在于，不同决策的时效、粒度和信息条件差异很大。入端策略需要覆盖较大规模人群，不能让每次打开 APP 都等待复杂推理；在端决策需要及时捕捉状态变化；离端后则可以利用更完整的行为轨迹，进行更充分的分析。

用户时机对应 Agent首要问题决策粒度计算方式时间预算
入端TensorLiftAgent这类用户适合什么目标与权益策略？人群网格后台生成与验证，在线读取策略在线命中小于 50ms
在端PeiAgent购物热情是否衰减，现在是否需要干预？当前用户、当前会话端侧感知，云端生成干预策略百毫秒级感知秒级干预
离端未购DeepFlowAgent为什么没买，是否值得召回，怎样召回？单用户及其行为序列云端异步、多阶段推理秒级到分钟级异步推理

三类 Agent 的差异，不只是部署位置不同，而是分别对应三种问题形态：

  • 进端是组合优化问题：需要从复杂人群和策略空间中寻找更优组合。
  • 在端是时机判断问题：需要在极短时间里判断用户热情是否衰减，并做轻量干预。
  • 离端是深度理解问题：可以利用更完整的行为上下文，进行多步意图推理和策略生成。

###

▐ 动线Agent 整体架构

以上是由TensorLiftAgent/PeiAgent/DeepFlowAgent共同组成的动线agent体系，以下就围绕进端/在端/离端三个问题展开：

  • 进端：TensorLiftAgent 如何实现精细化经营？
  • 在端：PeiAgent 如何抓住转瞬即逝的干预窗口？
  • 离端：DeepFlowAgent 如何完成一次深度归因？

进端：TensorLiftAgent 如何实现精细化经营？

▐ 核心思路：张量分解与区隔度寻优

###

** **

在后台定时策略运行，不直接面向用户。 将传统「人群粗放运营」升级为基于多维用户特征张量分解的精细化策略生成， 通过Agent不断从各个维度切分人群、生成策略、AB验证、回收效果，构建自优化的持续循环。 用户进端时仅做策略命中——实时匹配预先生成好的策略，保证毫秒级响应。

###

▐ 基于LLM的多层Loop寻优方案

###

* *

*每天**调度器拉起一条流水线：规划先看昨天的成绩和历史记忆，决定今天往什么方向执行；张量下钻把人群切成网格；定价给每个网格出价；回测当考官判卷，不过关就打回重做（② 中层循环）；每个环节的产物还要先过质检，不合格原地重做（① 内层循环）；校验通过才投放上线，第二天回收诊断拿真实 AB 数据批改，结论喂给次日的规划（③ 外层循环）。所有过程与经验都沉淀在 Memory Engine** 里跨天复用——整个系统就形成了一台「找答案、判卷、复盘」的寻优机器。*

###

▐ 四桶实验策略设计

线上实验则提供四类不同角色：

  • 空桶：保留自然成交基准，用来观察干预带来的增量。
  • 运营桶：承接既有人工或业务策略，提供业务比较基准。
  • 探索桶：在受控流量中验证新候选，用于不断探索潜在最优方案。
  • **SOTA桶：承接已验证的较优方案，作为后续挑战的对象。

**

为什么对照 SOTA 而不是对照空桶与空桶对照只能回答做了比不做好吗，与 SOTA 对照才能回答新策略比当前最好的策略更好吗——只有后者能保证 SOTA 桶单调变优。空桶的价值在数仓口径（绝对增量与增量 ROI），运营桶的价值在不劣于人工这条底线。

###

▐ 定价决策链

定价环节每天要做的是在 SOTA 桶现有价格的基础上，为桶内每一个人群网格重新求一个更优的确定价，产出一份整桶提案，再交给回测与线上实验去验证。

可以概括成一句话：以现价为起点、整桶只攻一个短板方向、只有目标匹配的网格才承接调价、承接格锁定历史更优点、最后在成本上限内腾挪预算。经过这样每天一轮的重新求解，SOTA 桶的价格被持续、单调地推向更优。

###

▐ 帕累托寻优

在「访购率提升 × AB 增量 ROI」这个二维平面上，各桶的表现如下：

在端：PeiAgent 如何抓住转瞬即逝的干预窗口？

▐ 实时购物热情指数

用户在 App 内的购物意愿会不断变化：一次有效搜索可能让意愿上升，连续无点击、频繁换词、商详秒退和回退首页，则可能意味着用户正在失去耐心。我们定义了 PEI（Purchase Enthusiasm Index，购物热情指数），用于实时描述用户购物意愿的变化，而不是只判断用户“有意图”或“没意图”。

PEI 随用户行为变化，并在重度衰减时触发干预，类似一支“购物体温计”，例如：

  • 搜索、点击商品、深度浏览和加购会提高热情；
  • 无点击浏览、频繁换词、商详浅出和回退会拉低热情；
  • 系统持续记录当前值、历史峰值和衰减轨迹；
  • 当 PEI 跌破个性化阈值时，触发一次干预决策。

###

▐ 端云协同：为什么算分必须在端上

PEI 的实现是一个端云协同模式：

在端内构建一个PEI（Purchase Enthusiasm Index，购物热情指数）的实时计算体系， 像体温计一样持续感知用户的购物意愿。如果热情出现明显衰减，会触发Agent的推理和干预，在用户离开前完成转化。

层职责为什么放这里
App 端PEI 实时计算 + 决定是否需要干预行为事件在端上产生，端上算分免去网络往返，才能压进 < 200ms 的约束；同时避免把全量行为流水实时上抛
服务端用户意图推理 + 生成干预策略需要聚合画像、历史记录、权益库存、成本约束，只有服务端有全量上下文

离端：DeepFlowAgent 如何完成一次深度归因？

▐ 离端其实是信息量最大的一刻

直觉上，用户关掉 App 就意味着这一轮引导失败了，只能等下次。但换个角度看，用户的完整行为序列信息在他离端的那一刻是最完整的。而"没有时间限制"并能从非结构化的日志数据中提出有效的信息，恰恰又是 LLM 最擅长的场景。

###

▐ 一个朴素猜想的验证

这个的起点是基于一个很朴素的猜想：基于用户的原始行为日志，LLM 能推导出什么？

以上基于用户的原始IPV行为日志，LLM可以结合世界知识以及当前时间地点以及气候推导出很多额外的信息（将气候和用户需求联系起来）。于是从这个猜想开始，想构建一种能力：基于用户行为序列做意图深度推理，并构建针对性的转化策略。

###

▐ 慢思考，三轮Chain架构

###

当用户没有购买就离开APP时，触发Agent的深度思考模式。 不受实时性约束，可以调用更复杂的推理链（Chain-of-Thought），深度分析用户未购原因， 并生成个性化的权益策略和营销话术，通过Push等方式推送给用户实现召回。

实现上是一套三轮 Chain 架构：

- - -

Chain 1  召回判断  ——  该不该召回？置信度多少？犹豫原因是什么？
Chain 2  选品定价  ——  钩哪个商品？发多大红包？门槛多少？成本比是否可接受？
Chain 3  文案生成  ——  Push 标题怎么写？正文怎么写？什么时机发？走哪个渠道？

为什么拆三轮，因为这三件事的失败代价、评测口径和优化手段完全不同：

  • 召回判断错了 → 打扰用户，代价是退订率和品牌感受，评测看准确率/召回率
  • 选品定价错了 → 花冤枉钱，代价是真金白银的损失，评测看成本比和增量 ROI
  • 文案生成错了 → 点击率低，代价是转化效率，评测看 CTR 和主观质量分

混在一次调用里，任何一环出问题都会污染整个输出，而且没法归因到底是哪一环错了。拆开之后每一轮可以独立评测、独立迭代、独立灰度。慢思考的另一个好处是不受实时性约束，因此可以调用更复杂的推理链，也可以用多轮换取质量。

▐ 一个真实的推理归因

以下是一个真实的推理输出：

{
    "confidenceScore": 92,
    "hesitationReason": "price",
    "needRecall": true,
    "pushTitle": "🎣 您看的加重渔网，立减6元！",
    "pushContent": "进口三层沉网捕大鱼，原价47元，专属红包再省6元！湛江老乡专享",
    "searchKeyword": "加重渔网",
    "redPacketThreshold": 4700,
    "recommendedRedPacketAmount": 600,
    "redPacketCostRatio": 0.128,
    "userIntent": "用户为55岁男性农林牧渔从业者，多次浏览垂钓用渔网（价格47-52元）和低价小说（18-39元），结合其职业和地域（湛江沿海），对渔具需求明确且真实，小说浏览可能为兴趣延伸。核心意图是购买实用渔网用于捕鱼作业。",
    "recallReason": "用户多次深度浏览高相关性渔具商品，职业与商品强匹配，且最后行为聚焦在渔网上，价格敏感但购买力中等（buyLevelCode=7），通过精准红包可有效降低决策门槛促成转化"
}

可以看这几处：

  • "湛江老乡专享" —— 地域信息被用成了情感钩子。这不是模板里配的字段，是模型自己决定要这么说的。
  • "进口三层沉网捕大鱼"—— 这是渔具行业的专业卖点话术。模型知道捕鱼用的沉网和观赏渔网不是一回事，知道"三层沉网"对这个用户意味着什么。
  • "原价47元，专属红包再省6元" —— 47 元正是用户反复浏览的那个价格带的下沿。门槛 4700 分贴着到手价定，面额 600 分对应 12.8% 的成本比，全落在合规区间内。
  • "小说浏览可能为兴趣延伸" —— 它没有被那几条低价小说的浏览记录带偏，正确判断出主线意图是渔具、小说只是干扰项。

传统规则系统能写出"您关注的商品降价了"，但很难写出"湛江老乡专享"和"三层沉网"——因为它不知道湛江靠海、不知道沉网是干什么的、也不知道这两件事和买渔网有什么关系。

下一步：走向统一的用户智能体

动线 Agent 的价值，在于尝试建立一种新的用户经营方式：平台能够沿着用户完整旅程持续感知状态，在不同时间尺度上做出合适决策，并通过真实业务结果不断修正自己。用户进端时，系统已经为他准备了更精细的策略；用户在端内犹豫时，系统能够感知热情变化并及时提供帮助；用户未购离开后，系统还能理解他为什么放弃，并给出一个更有针对性的回来理由。

但三种模式分别落地，只是全链路经营的起点。用户不会感知自己正在被哪个 Agent 服务，他只会感知平台有没有理解自己、给出的权益是否一致、提醒是否过于频繁。

因此下一步协同需要从共享数据走向共享决策状态：已经发放和使用过什么权益，当前还有哪些动作在执行，用户是否完成购买，预算与频控还剩多少。新的决策应基于这些状态，而不是每个模式都从零开始判断。接下来的重点需要补齐一些基础能力，例如统一用户经营状态，建立全链路实验视角，让个性化与自优化服从证据等。

最终，动线 Agent 希望形成的能力可以归结为一句话：看得见用户的状态变化，算得清干预的真实增量，能在有效窗口内行动，也能根据结果修正甚至撤销自己的判断。
