摘要速览

研发全链路中大量人工耗费在方案设计、代码评审、测试验证等非编码环节，频繁上下文切换和协作等待制约研发效能。如何让 AI 从只辅助写代码，扩展到需求→方案→编码→测试→部署的全链路自动化？

核心内容

  • 三阶段演进模型：L1 纯人工 → L2 人机协同（当前主力）→ L3 全自动化。L2 的核心是打通工具链（MCP），L3 的核心是多 Agent 自主协同的"N Agent 交付模式"
  • L2 实践路径：先做"技术方案→代码"（模板化技术方案 + Rules + MCP 工具 + AI 自我总结），再扩展到"技术方案→测试→部署"（Lego 环境一键创建、DDL 秒级申请、接口自动化测试、无人值守发布），最后向上延伸到"需求→代码"（PRD-Agent + 需求模板/澄清/评分规则）
  • L3 架构公式：AI 全自动化交付 = LLM + Harness Engineering（工作流 + 知识库 + Skills 管理）+ Business Engineering（Skills + 知识库沉淀）
  • 双轮驱动体系：交付框架（需求→发布全流程自动化 + 质量门禁 + 闭环反馈 + 自修复）+ 治理框架（运行时监控 + 自动巡检修复 + 异常实时感知 + 知识自动回溯）
  • 六大核心挑战：交付流程标准化、需求标准化、Skills 沉淀/标准化、知识库搭建、代码质量保障、线上问题治理
  • 实测数据：6 个试点需求三轮迭代，需求评分 80+、技术方案评分 80+、平均对话轮次 2 轮、代码行采纳率 90%+、AI 生成率 80%+
  • 效率提升：跨平台从 6 个降为 CodeBuddy 内闭环，操作步骤从 12 步优化到 5 步，测试环境创建节约 60%+ 时长，部署阶段节约 50% 时长

这是目前看到的最完整的大厂 AI 研发全链路自动化实践案例。L1→L2→L3 的演进模型清晰，每个阶段做什么、沉淀什么、卡点在哪都有具体说明。尤其是"交付框架 + 治理框架"的双轮驱动思路，以及 Harness Engineering 在企业级场景的落地方式，对理解 AI 从工具到平台的演进非常有参考价值。

具体步骤（L2→L3 演进路径）

  1. 夯实编码阶段：技术方案模板化 + Rules 索引 + MCP 工具集成 → 代码生成
  2. 打通测试部署：建设 Lego/DDL/接口测试/无人值守的 MCP+Skills → 编码到部署闭环
  3. 延伸需求侧：PRD-Agent + 需求模板/澄清/评分规则 → 需求到代码
  4. 串联全链路：需求→方案→编码→测试→部署端到端，加入质量门禁和闭环反馈
  5. 引入治理框架：运行时监控 + 自动巡检 + 异常感知 + 知识自动回溯

适用 / 不适用场景

  • 适用：企业级研发团队想做 AI 研发效能提升的规划参考；关注 Harness Engineering 落地实践的人；想了解大厂如何从"AI 写代码"扩展到"AI 全链路交付"的人
  • 不适用：个人开发者（规模不匹配）；不做软件研发的人

1、背景与挑战

1.1 背景

当前从需求到交付的全链路中，大量人工仍耗费在方案设计、代码评审、测试验证等非编码环节，频繁的上下文切换与协作等待严重制约了研发效能。为此，我们在深耕AI编码能力的同时，正将自动化向上游的需求、方案设计与下游的测试、部署环节延伸，旨在通过AI将各环节无缝串联，最终实现需求至部署的全自动化交付与研发效能的全面跃升。

1.2 现状

审核将AI全自动化演进规划为L1（纯人工）、L2（人机协同）、L3（全自动）三个阶段。

2025年，我们处于以"技术方案生成代码"为核心的L2阶段。基于"研发效能提升需突破单点、覆盖全链路"的共识，我们正从聚焦Coding，向需求、测试、部署等环节系统化辐射。最终目标是借由AI将各环节无缝串联，构建需求至部署的端到端自动化交付能力，驱动整体研发效能实现80%的效能提升。

审核迈向L3需经历三段式能力阶梯：先夯实技术方案生成代码，再打通技术方案至交付链路，最终实现需求到交付的端到端跑通。在此基础之上，才会全面进入L3的全自动化交付阶段。

1.3 挑战

审核要全面演进至L3阶段，需系统应对六大核心挑战：

挑战关键举措
交付流程的标准化制定标准研发流程，让大模型按标准流程执行，支持流程回滚
需求的标准化需求模板（概述/正文/版本/依赖）+ 澄清规则 + 评分规则 + PRD-Agent
Skills技能的沉淀/标准化技术方案生成、代码生成、代码CR、测试用例执行等skill能力
知识库的搭建业务知识库（生成技术方案）+ 代码知识库（快速代码熟悉）
代码质量保障需求评审、方案评审、代码CR、安全检测等门禁
线上问题的治理全自动化治理框架：自动巡检修复 + 异常实时感知 + 系统性治理

2、详细实践

2.1 人机协同（L2）

2.1.1 技术方案到代码

主要通过"AI技术规范(索引/rules) + 模板化(技术方案/prompt) + MCP工具集成 + AI自我总结"，实现生产力提升。

2.1.2 技术方案到交付

在技术方案中扩展出执行清单，通过CodeBuddy分阶段实现：

  • 研发阶段：基于代码层级结构完成代码生成及单元测试覆盖
  • 测试阶段：通过MCP工具实现测试环境准备，基于自动化测试用例完成验证
  • 部署阶段：通过MCP工具完成发布前准备，基于无人值守完成发布

升级收益：

  • 跨平台从6个降为CodeBuddy内闭环
  • 操作步骤从12步优化到5步
  • 测试阶段环境创建/更新节约60%+时长
  • 部署阶段节约50%时长
2.1.3 需求到交付

串联需求→代码生成 + 技术方案→部署，形成端到端闭环。沉淀出1个PRD-Agent、5套规范化标准、3个知识库与3项核心技能。

2.2 AI全自动化交付（L3）

引入Harness Engineering for AI Coding理念，构建标准工程交付框架：

  • 需求→方案→开发→测试→发布全流程自动化串联
  • 需求评审、方案评审、质量门禁与MR等工程卡点保障质量
  • 闭环反馈与卡点自动修复能力

基于OpenClaw完成6个试点需求验证：需求评分80+、技术方案评分80+、代码行采纳率90%+、AI生成率80%+。

2.3 效果数据

平均生成对话轮次2轮，代码行采纳率90%以上，AI生成率80%以上。

3、实践总结

从需求侧与编码侧对典型问题进行梳理总结，大部分问题已得到有效解决，为中心内推广奠定基础。

4、未来展望

L3阶段公式：AI全自动化交付 = LLM + Harness Engineering（工作流程 + 知识库 + skills管理）+ Business Engineering（skills + 知识库的沉淀）

完整AI全自动化平台由两套并行框架构成：

  • AI全自动化交付框架：需求→发布全流程自动化 + 质量门禁 + 闭环反馈 + 自修复
  • AI全自动化治理框架：运行时监控 + 自动巡检修复 + 异常实时感知 + 知识自动回溯

二者共同构成"交付驱动效率，治理保障质量"的双轮驱动体系。

需求的标准化让需求按照标准模板输出，大模型可以基于需求生成代码 ● 制定标准的需求模板，主要通过需求概述、需求正文、版本管理、外部依赖等4个部分对需求文档进行规范性约束，提升需求的质量 ● 制定需求的澄清规则，通过对需求概述、需求正文、版本管理、外部依赖等4个部分，建立一套需求澄清的规则，在需求编写不满足条件的情况下，给出修正建议 ● 制定需求评分规则，通过对需求背景、价值衡量、解决方案、影响范围、需求正文设定一套标准的打分规则，方便衡量需求的输出质量，如果不满足评分标准，需求将被打回 ● 构建需求PRD-Agent，配置需求模板、需求澄清规则、需求评分规则，支持产品在PRD-Agent上进行需求编写、澄清等
skills技能的沉淀/标准化沉淀一套标准的skill能力，增强模型的执行和决策能力，目前需要沉淀技术方案生成、代码生成、代码CR、测试用例执行等skill能力
知识库的搭建从需求生成代码，需要高质量的上下文 ● 构建审核的业务知识库，让大模型可以基于知识库生成技术方案 ● 构建审核的代码知识库，让大模型可以快速完成代码的熟悉，从而生成高质量的代码
代码质量保障AI编码在提升速度的同时，也带来了质量失控的风险。若缺乏严格的质量门禁，代码库将在高速迭代中滑向高熵与腐化 ● 构建需求评审、方案评审、代码CR、安全检测等门禁，确保代码质量
线上问题的治理AI编码基本都在静态代码的生成，对于系统架构、性能、可用性等问题会稍显不足，需要我们有一套对线上系统的实时监控及自我修复能力 ● 构建全自动化治理框架，打通运行时日志和监测指标，实现线上服务的自动巡检与修复、线上异常的实时感知与优化，从而完成从架构、性能到可用性的系统性治理

2、详细实践

我们致力于打造一个能够实现需求至发布全链路自动化、并具备自愈能力的AI交付平台。其成熟标志是形成由多个AI智能体自主协同的“N Agent交付模式”，达成L3级全自动化。为此，我们确立了分阶段演进的路线：现阶段（L2）的核心是“人机协同”，即全力打通并集成研发、测试、部署等关键工具链（MCP），为高阶自动化奠定工程基础。待此阶段稳固后，再系统性地迈向L3的AI全自动化交付阶段。

4、未来展望

经过对L2~L3阶段的实践，然后结合业界的harness理念，我们认为L3阶段可归纳为：AI全自动化交付 = LLM + Harness Engineering（工作流程 + 知识库 + skills管理） + Business Engineering（skills + 知识库的沉淀），具体公式组成如下：

我们认为，一个完整的AI全自动化平台应由两套并行、协同的框架构成：AI全自动化交付框架与AI全自动化治理框架 。

AI全自动化交付框架旨在实现从需求、设计、开发、测试到发布的全流程自动化串联，并通过内置的需求评审、方案评审、质量门禁与MR等工程卡点，结合闭环反馈与自修复机制，保障交付流程的稳定、自适应与高质量。

AI全自动化治理框架则与其并行，通过构建覆盖运行时日志、监测指标、Spec知识与中间产物的全域数据洞察系统，实现线上服务的自动巡检与修复、异常的实时感知与优化，以及知识与Skills的自动化回溯与更新，从而系统性地保障架构、性能与可用性。

二者共同构成“交付驱动效率，治理保障质量”的双轮驱动体系，确保AI研发全流程在持续高效运转中，始终朝向有序、可持续的方向演进，如图4.1所示：

5、结语

目前，我们基于OpenClaw/CodeBuddy初步构建了AI全自动化交付框架，但其交付流程与Skills管理仍处于线下、非中心化的初级阶段。同时，AI全自动化治理框架尚在规划中。为实现体系的标准化与规模化，我们计划与研效团队协同，将这两大框架全面整合并迁移至AMS一站式研效平台，以达成线上化、中心化的统一管理。
