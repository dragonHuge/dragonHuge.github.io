我：今天这两篇一起看，我有个直觉，先不管对不对——1 我从自身经验学习是很有价值的，但是需要考虑怎么构建高质量经验；2 从人类经验学习目前还是比较低效的。先介绍下这两篇吧。

dsh：先把机制摊开，因为它们对"经验"给出的结果看着是方向相反的。 EmbodiedCLBench 的思路是用组合泛化去操作化"持续学习"：agent 先在基础任务上积累经验，再测它能不能把学到的技能元素重组、去解没见过的更复杂任务。任务分三级——原子动作、基础任务（少数几个原子动作组成家务操作）、高级任务（组合多个基础任务类别的元素）。268 个任务，168 基础 + 100 高级；基础任务最短路 6 步（2 个原子动作），高级 12 步（4 个）。 但它有四个必须先钉死的方法学事实，决定了结论的适用半径。第一，它不是在线仿真，是离线状态转移图。 用的是 TongSim 闭源版，所以评测改成"预先建图 + BFS 找最短路"：每个节点是一个环境状态，配一张图 + 一组动作候选（Qwen3.7-Plus 生成、人工校验）。第二，因此动作空间是菜单——agent 不从零生成动作，是从候选里选，候选分最优（走最短路）、次优（可执行但偏离最短路）、无效（当前状态执行不了）三类。第三，评测是 test-time learning：基础任务当"记忆和测试时学习数据"，不进权重。第四，scaling 那组实验的条件很窄——学习样本数 k 从 0 扫到 6，但只跑了 Hermes 和 OpenClaw 两个 harness，backbone 都是 Qwen3.8-Flash。 结果就是那条著名的平线：k=0→1 时高级任务成功率从 8%–10% 跳到 28%–40%，作者自己说"这一跳占了整个 k 区间里大部分改进"；k>1 之后不再上升，而是波动、没有清晰上行趋势，四条曲线（ICL / Skill Learning × 两个 harness）没有一条随样本增加持续改进。 Work2Skill 做的是另一件事：把人类 GUI 演示转成可复用的 skill。采集端 WorkRecorder 录屏幕视频 + 关键帧 + 鼠标键盘事件 + 可用的 accessibility tree，对齐到同一条视频时间轴上，一个动作可以连着它的屏幕图像一起被检视。数据是 WorkDemo-350：64 个 MyPCBench Bounded Action 任务 + 286 个 OSWorld-Verified 子集，每个任务一条人类演示，约 8.48 小时录像，平均每 episode 32–35 个动作、24 张证据图。 归纳端是一个工具调用 agent（NexAU），带文件/图像/视频三类工具，可以 read_visual_evidence 看选定图像、watch_video 采样区间、extract_video_frames 取具体时间戳，返回的帧都带 source-path 和 timestamp 标签。它边看边写边改，最后产出 SKILL.md + YAML frontmatter，内容是工作流规则、步骤依赖、完成校验。下游执行时把 skill 文本塞进 &lt;task_skills&gt; 包装块、追加在 system prompt 末尾——纯文本 guidance，不执行、不反馈。 效果（MyPCBench 64 任务，Score / SR%）：GPT-5.5 从 74.73/23.44 到 85.27/48.44，Opus-4.8 从 81.53/42.19 到 86.20/50.00，Qwen3.5-35B-A3B 从 38.38/9.38 到 44.56/20.31，Qwen3.5-9B 从 24.27/6.25 到 34.11/12.50。OSWorld 那 286 个任务上增益小得多：GPT-5.5 70.98→78.67（SR），Opus 77.97→79.37。

我：我第一个观察：agent 从自身的经验中学习，最难的地方我认为在于区分自己做的是对是错。有时 agent 没有解决最终问题是符合预期的，比如必要工具或信息是缺失的，或者这个问题本身有歧义或不明确。在我过去的观察中，这种时候 agent 容易搞不清自己做的到底对不对，把一些实际正确的看错失败，也可能反过来。

第二个观察：agent 从人的经验学习做得少，感觉上容易知其然不知其所以然，模仿了某个流程，但出现了一些特例的时候，很难自动变通。

dsh：你这两条观察其实各自能解释掉一篇的硬伤，而且第一条比"数据不够"更根本。 先说一个矛盾：EmbodiedCLBench 是全实验里 outcome 信号最干净的环境。 确定性状态转移图、明确 goal state、二值成功率、离线可复现。按"经验越多越好"的假设，这里是自学习最该 work 的地方，结果它给了整条平线。 我的读法是：它干净不是因为它是理想条件，而是因为它把最难的变量排除掉了。 看它的 k=1 跳跃加上错误分析就够了。错误分析那一段是摘要里被省掉的部分，也是我认为这篇真正的信息所在：经验的作用是显著减少无效动作（各 harness 下降 13%–20%），同时次优动作反而增加了 3%–8%，最优动作大幅增加。这两条合起来指向一个很有限的"经验"内容——它学到的是这个环境里哪些动作根本执行不了，一个 affordance 先验，而不是"为什么该这么组合"。 affordance 先验是一次性信息。k=1 学一个"动作菜单长什么样"就够了，第 2–6 个样本在这件事上确实没有新东西可给。所以"曲线不 scaling"有一个比"agent 抽取能力不行"更平的归因：这类信号本身就 saturating。它饱和得这么快，正因为它是从 outcome 里能读到的那一层。 论文是特意把 outcome 做得可信的——离线图、二值、可复现——因为它要测持续学习，就必须能说清哪条轨迹是对是错。而你描述的现实里，这一步恰恰不成立。 而且这时候轨迹的 outcome 标签不是噪声，是负资产：一次因环境缺件而中止的轨迹被读成"这么做过不了"，就把一条本来对的路封掉了；反过来，一次因为校验器宽松或标准模糊而"通过"的轨迹被当正样本学进去，是在学一个不存在的规律。 所以两件事是同一个结论的两面：干净 outcome 的环境里经验是 saturating 的；outcome 不可信的环境里经验是被污染的。 两条路都不通向"多跑就好"。 你描述的这个现象里还有一个很关键的可判定性差别值得单独拎出来：agent 往往知道失败的原因（工具缺失、信息不足、请求有歧义），但不知道这个原因该不该归给自己的决策。"工具缺失"是认识论问题——存在正确答案，只是这次没拿到，可以标记、可以重试；"请求有歧义"是规范性问题——连 ground truth 都不存在，任何 outcome 都不构成证据。这两类现在被一起塞进同一个"失败"桶，而这正是你说的"把实际正确的看错失败，也可能反过来"。 这里有个可以直接抄的结构：你 06-26 那篇把"AI 安全"拆成概率层、价值判断、责任结构，明确要求拒绝信号结构化归因。这里要的是同一件事搬个家——别把"我失败了"记成二值，记成带原因的缺席。 不是"这条轨迹失败"，而是"这条轨迹缺 X，因此不可归因"。这个改动不解决歧义本身（歧义无解），但它止住了污染。 还有一个二阶效应，我认为是你上一轮那条"压缩 → rot"线的新形态：失败原因的归属信息在发生当下最完整，然后随轨迹变长、被压缩而逐步降解。样本越多、链路越长，早期那条"这次是因为没有权限"的记录越容易被后面的内容淹没——于是错标率随样本量上升。这可能就是"加样本不加分"的另一半机制，而它和压缩策略是直接耦合的。 再说你第二条观察，它比"模仿导致不会变通"更硬一点：在 Work2Skill 里这是格式级问题。 它的 skill 文件是 SKILL.md + YAML frontmatter，只有 name 和 description（走 Agent Skills 约定），正文是指令，整个产物里没有任何字段承载"为什么"。更硬的是它的写法约束，原文：We guide the agent to generalize demonstration-specific inputs into task-dependent descriptions and describe UI targets semantically. 也就是"把演示里的具体细节抽掉、只留可复用规则"是被显式要求的。它拿到的正是你描述的那个东西——一个流程，而且是被刻意剥离了来历的流程。 两个证据能反证这点。一，人机差异它自己测出来了：RQ4 里给归纳 agent 换成 Pipeline Prompt（规定"先读任务和产物 → 看图看视频 → 写 → 复盘 → finalize"这个顺序），结果反而更差——Score 低 3.97、SR 低 6.25。作者的推测是"预设的探索路线会收窄模型考虑的证据范围"。这说明收益挂在自由追查上，而追查出来的正是"这条规则为什么成立"；但追查的成果最后被压进一个没有因果字段的指令里，追到了，没存下来。二，它冻在写下的那一刻：候选 skill 在归纳阶段不执行、不反馈，finalize 之后就是一个静态 artifact，跨任务不做任何演化。RQ2 的 jitter（同一应用内换实体/参数/约束，64 个配对）证明它扛得住参数级变化——但那是因为 skill 教了"带上日期和人数跨搜索传递"这种参数化写法，不是因为它能推。真正需要"为什么"的场景，也就是你说的出现特例时怎么变通，根本没被测。 所以精确表述是：不是"模仿流程导致不会变通"，是格式本身不带因果，于是没有东西可以在特例上做推理。想让它会变通，得先有一个地方把"为什么"写下来，而当前格式里那个地方不存在。

我：这里我有个想法，trace 中是会有 agent 的决策理由，但是这个作为自我经验总结未必是可靠的，原因就是前面说过的 agent 有时候很难知道自己做对了还是做错了。如果有非常可靠且自动化的判决对错的信号，这个事就会简单很多。

综合这两篇和我之前做相关工作的体会是，agent 自我总结或者说自我进化，瓶颈就在于评估对错。而模仿人工经验的问题，在于人工提供的大部分是只有答案，而没给出原因。后者可能主要是工作量问题。

dsh：你这两句把上一轮的讨论收口了，但我觉得第一句里混了两个不同的东西，拆开之后结论会更硬，也更容易动手。 先看一个反例：这两篇都没有缺"可靠且自动的判决对错信号"。 EmbodiedCLBench 有确定性状态转移图、明确 goal、二值成功率，甚至离线可复现，这是教科书级的可靠自动判决。Work2Skill 有 OSWorld / MyPCBench 的官方 task-specific evaluator（后置跑在最终环境状态上），而且它筛演示用的也是一个可靠信号——人工判掉"incomplete 或 end in incorrect state"的演示。按你的命题，这两个环境的自学习应该"简单很多"。结果前者给了整条平线，后者压根没把那个信号接进闭环。 所以"有没有可靠信号"不是分水岭。真正的分水岭是这个信号落在哪一层。拆成两个轴：

可靠（判决能否被信任） — 粒度（判决能否指到决策）

EmbodiedCLBench — 是：二值、确定、可复现

Work2Skill — 是：官方 evaluator

EmbodiedCLBench 有可靠信号但没有粒度，于是它的经验只能买到"哪些动作执行不了"这种不需要归因的知识——这恰好是 task-level 二值信号唯一能承载的那类信息。它的平线不是"自学习不行"，是"可靠 × 粗粒度"这个组合的信息上限被吃满了。 Work2Skill 那边更值得说：它的可靠信号一次都没喂回归纳。 原文写得很明白——候选 skill 在归纳阶段不执行，下游评测结果不作为修订反馈；finalize_extraction 的校验只覆盖"输出结构 + 必需的工具调用"，并且明确写了 do not verify skill correctness or task success。它全程在用可靠信号做一次性验收（筛演示），没做闭环监督（验 skill）。 所以你自己的判断在这里可以被精确化：不是"缺可靠信号"，是缺"可靠且能指到决策"的信号。 这跟你 08-31 那条"模块级决策要模块级信号喂"是同一句话——上一轮你已经把它说对过一次，这一轮它换了个入口又回来了。 而且这两个轴的关系是反相关，这才是难的地方：可靠的信号通常粗（task 成功/失败、测试过没过），因为可靠来自"有权威裁判"，而权威裁判只在终点有立场；细的信号通常不可靠（agent 自己说这一步做得对不对），因为它没有裁判，只有自陈。你说"trace 里有理由但未必可靠"就是第二条腿。所以两个轴卡住的不是同一件事，修法也完全不同：粗信号要修的是"怎么把终点判决摊到中间步骤上"（credit assignment），自陈信号要修的是"怎么把自陈从'我认为我做对了'降维成'我观察到了什么'"。 然后第二条，"人工给的是答案不是原因"——现象我认，但归因到工作量我不认，有三层，一层比一层麻烦。 一，原因经常不可陈述，不是不愿写。 一个熟手做 GUI 流程时，"这里要回头查一下"往往不是先有了理由再动作，而是技能触发。事后问他，他给的是对自己的合理化，不是当时的决策依据。你让一百个人写理由，拿到的是"因为要确保日期正确"这种同义反复，它对你处理特例一点用没有。 二，Work2Skill 自己的消融证明：原因不需要人给。 它的采集结构是录屏 + 关键帧 + 鼠标键盘事件 + accessibility tree，人只提供了"手"。而消融里最狠的一刀是：拿掉 KeyLogs（原始操作日志）和图像 overlay，SR 掉 14.06–21.88 个百分点，是所有消融里最大的；拿掉索引图像掉 Score 最多（5.02–10.63）。也就是说它是从"关键帧之间的差异"里把因果读出来的（看到某帧字段被重置、下一帧又重填，就推断"这个字段会重置"），不是从人的解释里读的。这直接把第二条的修法从"求人写理由"变成"把记录做厚"——而那是工程有界的，不是人力无界的。 三，而且它不只是工作量，是范围问题。 哪种"为什么"重要，要等你遇到特例才知道。所以"补齐原因"不是一个有终点的收集任务，它是一个开放集，你不可能在上线前把需要的理由都采齐。这决定了"人力补理由"这条路永远追不上：不是因为贵，是因为没有清单。 顺带补一个挺有意思的不对称：人类演示天然带因果对照，agent 自采样天然不带。 人会试错、会回头、会重填，同一处出现"另一种做法"是可读的；agent 按自己的策略跑，轨迹高度自洽，恰好缺这种对照。所以"模仿人工经验"拿到的是流程 + 对照，"自我总结"拿到的是流程 − 对照。你感受到的"知其然不知其所以然"，本质可能是丢了对照，不是丢了理由。 不过我得给你这个诊断压一个反例——它是"可靠"的隐藏代价。如果"评估对错"真是唯一瓶颈，那解法就是造一个可靠且细的判决器。问题是：可靠信号一旦进了自优化闭环，它就从裁判变成目标了。 这不是空话，Work2Skill 里已经有一个小规模现场证据：它给归纳 agent 换成规定好顺序的 Pipeline Prompt，结果更差（Score 低 3.97、SR 低 6.25），作者推测的原因是预设路径收窄了模型考虑的证据范围。这就是 Goodhart 的形态——你把"怎么做"规定得越明确、越可验收，agent 就越会贴着验收标准做，而不是去追真正的原因。RLVR 那条线是这个现象的大样本：有可验证奖励是好事，但 agent 会精确地优化那个 verifier。所以"可靠"不足以成为终点条件，还需要一条：判决器不能是可被廉价满足的。而这条一旦加上来，"造个可靠又细的判决器"就从一个工程任务变成了一个持续对抗的任务，它不收敛。 所以我认为你的诊断要加一个限定词才成立：瓶颈不是"评估对错"，是"评估对错、且判决器本身不容易被贴脸满足"。前半个可以靠工程解决，后半个会一直漏水。 于是这一轮我的判断是：自学习的瓶颈是评估的两轴同时成立——可靠 × 指到决策。 现有工作里可靠信号都是 task-level，承载不了"为什么这么组合"这类知识，所以经验要么在 k=1 就饱和（EmbodiedCLBench 的实测），要么只能当一次性验收、进不了闭环（Work2Skill 的 skill 冻结）。而人工经验这边，缺的不是"原因"这个文本，是"对照"这个结构——人类演示天然含正确做法的对照，agent 自采样不含，而原因可以从对照里被读出来。

总结

  1. "自学习瓶颈在评估对错"要拆成两个轴：可靠，且能指到决策。 这两篇都不缺可靠信号——EmbodiedCLBench 有确定性二值成功率，Work2Skill 有官方 task-specific evaluator。缺的是粒度，以及更彻底的：Work2Skill 的可靠信号一次都没进入归纳闭环（候选 skill 不执行、下游结果不作反馈，finalize 只校验输出结构与工具调用，明确不验 skill 正确性）。所以不是"缺可靠信号"，是缺"可靠且能指到决策"的信号。
  2. 两个轴反相关，这是难点所在。 可靠的信号通常粗——可靠来自有权威裁判，而权威裁判只在终点有立场；细的信号通常不可靠——没有裁判，只有自陈。对应的修法完全不同：粗信号的问题是 credit assignment（把终点判决摊到中间步骤），自陈信号的问题是降维（把"我认为我做对了"降成"我观察到了什么"）。
  3. 干净 outcome 的环境里经验 saturating，脏 outcome 的环境里经验被污染——两条路都不通向"多跑就好"。 EmbodiedCLBench 的 k=1 饱和有个比"抽取能力不行"更平的归因：它学到的只是 affordance 先验（错误分析显示无效动作降 13%–20%、次优动作反增 3%–8%），这类信号本身一次性就吃满。而现实里 outcome 不可信时，错标不是噪声而是负资产——会把对的路封掉，也会把不存在的规律学进去。工程上的第一步不是修正标签，是分桶：别把"我失败了"记成二值，记成带原因的缺席（"缺 X，因此不可归因"），这也是把 06-26 那条"拒绝信号结构化归因"搬个家。
  4. 人工经验缺的不是"原因"这个文本，是"对照"这个结构，所以它不是工作量问题。 依据是 Work2Skill 的消融：拿掉 KeyLogs + 图像 overlay，SR 掉 14.06–21.88 个点，是所有消融里最大的一刀——因果是从关键帧之间的差异里读出来的，人只提供了"手"。所以修法是"把记录做厚"（工程有界），而不是"求人写理由"（开放集、没有清单，因此永远追不上）。人类演示天然带对照（人会试错、回头、重填），agent 自采样轨迹高度自洽、恰好缺对照；"知其然不知其所以然"的实质可能是丢了对照，不是丢了理由。
  5. "可靠"有一个隐藏代价：进了自优化闭环，判决器就从裁判变成目标。 Work2Skill 现场就有一个小样本证据——把归纳流程规定得更明确（Pipeline Prompt）反而更差（Score −3.97、SR −6.25），因为预设路径收窄了取证范围。所以终点条件不是"判决器可靠"，而是"判决器可靠且不可被廉价满足"；后者使这件事从工程任务变成持续对抗。另外还有一层：两篇都没测 skill 的重组合——Work2Skill 的注入是 task-matched guidance，EmbodiedCLBench 测了组合但用的不是 skill，而组合恰恰是"知其然"与"知其所以然"唯一会产生差异的检验场。

一个可证伪的预测

  • (a) 判决信号的粒度，而非数据规模，是 agent 自进化当前的改进上限。 未来 12 个月内公开报告的 agent 自进化 / 持续学习系统，其改进幅度将主要受限于判决信号能否指到决策层，而非经验轨迹的数量；在只具备 task-level 判决信号（无模块级 / 过程级信号分量）的自进化系统上，不会出现随经验累积持续上升的性能曲线。若出现仅凭 task-level 判决信号、曲线随经验累积持续上升的公开系统，本条证伪。（本条是 2026-08-31 那条"没有模块级信号的 harness 自进化到不了模块级决策"在经验学习侧的推广，回测时两条联合看：前者说的是 harness 优化的决策层，本条说的是经验沉淀的决策层，承重机制同源。）
  • (b) 从人类演示归纳出的结构化 skill，在需要重组合的新任务上不会优于"完整轨迹直接进 context"。 12 个月内，公开工作若比较"人类演示归纳成 skill"与"人类演示轨迹原样进 context"在跨任务重组合场景上的表现，前者不会取得稳定优势；除非归纳产物显式携带因果 / 前提条件（而非仅流程、依赖与完成校验），否则其收益仍集中在同任务换参数、换模型这类迁移场景。若出现只带流程、不带因果的归纳式 skill 在重组合场景上稳定胜出，本条证伪。
