2026年9月16日，一家叫 TypeSafe AI 的旧金山的 AI 创业公司发布了一个模型，名字叫 Jev。

这个模型一上线就把开发者圈炸了。不是因为它有多聪明，恰恰是因为它有多反常——它一个字都不生成。

不聊天、不写代码、不写文案、不解释理由。你问它什么，它只给你几个数字、一个选项、一串概率分布。

用36氪的话说，这是一个"哑巴模型"。

但就是这么个"不会说话"的模型，上线没几天，全球开发者围绕它砸出了近五百个开源项目。

Vercel 平台上24小时内就有接近13%的付费团队用上了它，是 Vercel 历史上采用速度最快的新模型。

Jev 爆火之后，很快有人做了一件事：把 Jev 的能力包装成可以直接给 AI 编码代理（coding agents）使用的 Skill（技能包） 集合。

这个开源项目就是 jev-skill，MIT 开源协议。

01

PART

jev-skill 是什么？

jev-skill 把 Jev 的决策能力，变成了可以直接在 Codex、Claude Code、OpenCode 这些 AI 编码代理里一键安装、拿来就用的技能。

你不需要自己写 API 调用代码，不需要自己设计 JSON 格式的请求，不需要自己处理并发和重试。

jev-skill 已经帮你把所有这些都打包好了，还附带了：

61 个社区项目和资源链接——从浏览器自动化到代码审查，从 PDF 问答到音乐生成，全是别人用 Jev 做出来的真实应用

个精心设计的 Skill——覆盖从问题设计、批量分类、文档取证、输出评估到动作选择的完整工作流

108 个场景模板——每个场景都有完整的示例代码和解释，复制粘贴就能用

个真实的输入/输出记录——全是保存下来的真实 Jev API 调用请求和返回结果

在这个项目里，你可以把它当成一个 Jev 开发者的"百科全书 + 工具箱 + 案例库"。

02

PART

Jev 到底是什么？为什么它能火？

在介绍 jev-skill 之前，得先搞清楚 Jev 本身是什么东西。这个理解了，你就明白为什么这个 skill 集合这么有价值。

系统一模型：从卡尼曼的《思考，快与慢》说起

TypeSafe AI 给 Jev 贴的标签叫 System One Model（系统一模型）。这个名字来自丹尼尔·卡尼曼的经典著作《思考，快与慢》。

卡尼曼把人类的思考分成两套系统：

系统一 快思考，自动、直觉、不过脑子。比如看到一个球飞过来你会本能地接住，或者看到邮件标题就能立刻判断是不是垃圾邮件。

系统二 慢思考，刻意、逻辑、需要努力。比如做数学题、写一份商业计划书、或者调试一个复杂的 bug。

过去这几年，整个 AI 行业都在拼命造系统二模型——GPT、Claude、Gemini、o1，一个比一个会写长文、会推理、会解释。

但 TypeSafe AI 反其道而行之。他们说：软件里真正需要的判断，90% 都是系统一。

一个 AI Agent 在干活的时候，它的瓶颈往往不是"不会写代码"，而是那些琐碎的、高频的判断。

如果每一个这种判断都走一遍大模型，慢、贵、还容易出幻觉。

Jev 的三个核心设计

Jev 的设计用三个特点就能概括：

1. 它只答三种题

题型意思返回值
Choice从你给的一堆选项里挑一个选中的选项 + 每个选项的概率分布 + 置信度
Score按你给定的等级打个分一个分数值 + 各等级的概率分布 + 置信度
Noul判断一个命题是真的概率0 到 1 之间的一个数字

而且三种题可以混在同一个请求里，并行算出答案——你问一个问题和问十个问题，延迟几乎一样。

2. 它极快极便宜

TypeSafe 自己公布的数字，对标 GPT-5.6 Terra：

指标JevGPT-5.6 Terra倍率
响应时间114ms8.5秒~75x 快
单次成本$0.000081$0.013880~171x 便宜

输入价格是每百万 token $0.042，输出免费——因为它根本不输出 token，只输出结构化数据。

3. 它零幻觉输出

这个要特别说明。很多人说大模型"会幻觉"——让它输出 JSON，它可能少个逗号；让它调用工具，它可能编一个不存在的工具名；让它从三个选项里挑一个，它可能给你第四个。

Jev 不可能犯这个错。

因为它的 API 合同里写死了：你给它什么选项，它只能在这些选项里选。 你给它三个部门（billing、engineering、sales），它就只能返回这三个里的一个，绝对不会凭空造出来一个 "marketing"。

它完全可以选错——把 billing 错分成 engineering。但它绝不可能输出不存在的东西。

对 AI Agent 来说，这个区别太重要了。静默毁掉一个 Agent 任务的，往往不是一个错误的判断，而是一个格式错误的输出让下游解析崩了。

03

PART

内置 5 个 Skill

现在来看 jev-skill 项目最核心的部分——那 5 个可以直接装到 AI 编码代理里的 Skill。

每个 Skill 都做一件事，互不重叠：

1. jev——设计问题和批量调用

这是最基础的 Skill。当你想把一个大任务里的某个判断步骤交给 Jev 时，用它来设计问题、整理上下文、组织成 Jev API 能接受的格式。

适用场景：把自然语言任务转成 Jev 能理解的结构化问题、工具路由选择、上下文截断等。

2. jev-triage——分类、标签和优先级排序

批量处理记录的神器。给它一堆工单、反馈邮件、日志条目，它可以同时给每条记录贴上分类标签、紧急程度、优先级。

适用场景：支持工单路由、紧急程度筛查、批量消息分类、邮件分拣。

jev-skill 里有一个真实的 smoke test（烟雾测试）结果：24 条人工标记好的支持工单，Jev 匹配了 24/24 的预分配标签，而 DeepSeek V4 Flash 匹配了 23/24。成本才 $0.0011——不到一分钱。

3. jev-documents——在文档和代码里找证据

给定一段源代码或一份文档，让 Jev 帮你找到某个 claim 对应的来源证据，或者从文本中抽取符合条件的片段。

适用场景：代码仓库导航、claim-to-source 验证（"这个说法能不能在文档里找到出处？"）、PDF 或文章中的段落匹配。

4. jev-eval——对照标准评估输出

给它一份评估标准（rubric），让它对 Agent 的输出、代码变更、安全测试结果等批量打分。

适用场景：代码评审优先级排序、越狱测试批量评估、PR merge 资格判断、Agent 完成度验证。

5. jev-act——选择下一步动作

这是在 Agent 执行循环里最重要的 Skill。当 Agent 要决定下一步做什么的时候，用 Jev 从一组合法动作里选一个。

适用场景：浏览器自动化里选哪个按钮、桌面操作里选哪个控件、游戏里选哪个合法走位、Agent 卡住时选什么恢复策略。

jev-skill 里保存了 14 个真实的 I/O 示例，其中有一个 stuck-loop recovery（死循环恢复）的例子特别典型：Agent 跑两次测试都报同一个 UnicodeDecodeError，没有改任何代码。

Jev 的判断是：下一步应该 inspect_input（检查输入），stuck = true，置信度 0.88。完全正确。

04

PART

快速上手

第一步：给你的 Agent 发一条消息就行

jev-skill 的设计哲学是：让 Agent 自己处理安装，你不用手动跑命令。

如果你用的是 Codex、Claude Code 或 OpenCode，直接把下面这段发给它：

`Install Jev Skills for this coding agent, including all scenario skills: https://raw.githubusercontent.com/wuyoscar/jev-skill/main/docs/install.md Check my environment and handle the installation. Use jev for setup to confirm with me: A: real Jev via my OpenRouter or official TypeSafe account; B: simulation with this agent. Wait for my choice. Guide any key entry through local secret settings, never this chat. Verify offline first; ask before sending data or making a paid call. `

Agent 会自动：

1

检查你的环境（有没有 Node.js、npm 等）

2

把 skill 文件装到当前项目里

3

先做离线验证，确保文件都就位了

4

问你要用 A（真实 Jev API）还是 B（用现有模型模拟）

第二步：配置 API Key（如果选 A）

有两种方式接入真实的 Jev API：

方式一：OpenRouter（推荐）

OpenRouter 已经集成了 Jev。如果你已经有 OpenRouter 账户，只需要设置环境变量：

`export OPENROUTER_API_KEY="你的key" `

然后在调用时指定 --provider openrouter（或默认，因为默认就是 OpenRouter）。

方式二：TypeSafe 官方直连

如果你想直接用 TypeSafe 的官方服务：

`export TYPESAFE_API_KEY="你的key" `

调用时加 --provider typesafe。

TypeSafe 官方控制台地址：https://console.typesafe.ai/

⚠️ 重要提醒：Agent 会引导你在本地密钥文件里配置，绝对不要直接把 key 粘贴到聊天窗口里。

第三步：如果没有 Key 怎么办？——用模拟模式（B）

不想申请 API key？或者只是想先体验一下？jev-skill 支持 模拟模式：让你正在用的 AI Agent 自己来模拟 Jev 的决策能力。

比如你用的是 Claude Code，就可以让 Claude 自己来做那些 Choice/Score/Noul 判断。

结果会被标记为 agent_simulation，并且会显示 jev_called: false——明确告诉你这不是真 Jev 出的结果，不要把模拟出来的概率当真。

LAST

写在最后

AI Agent 的世界正在悄悄发生一场分工：让系统一模型管判断，让系统二模型管思考和生成。

Jev 不是来取代 GPT 或 Claude 的。它是来帮它们减负的——把那些"从三个选项里挑一个"、"按个标准打个分"、"是或否"的琐碎高频判断，从大模型的肩头卸下来，交给一个专门做这件事、又快又便宜的小模型。

而 jev-skill 这个项目，就是把这种分工理念变成了可以直接用的工具。

如果你正在做 AI Agent 相关的开发，或者已经在 Codex、Claude Code 里折腾各种自动化，这个项目值得你花 5 分钟装一下试试。

那 108 个场景模板里，大概率能找到一个正好匹配你现在手头的任务。
