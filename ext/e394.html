dev-browser vs web-access：两个浏览器 Skill 的定位差异与选择原则

2026-04-07 · 文字记录 · 工具与技术/20260407-dev-browser与web-access浏览器Skill对比.md

来源：文字记录 归档日期：2026-04-07 文字记录 · 群内原文已归档（无源URL，非网页内容） 原文字符：0｜配图：0 张

摘要速览

OpenCode/Claude Code 有多个浏览器相关 Skill（dev-browser、web-access、defuddle），功能有重叠，不知道什么场景该用哪个。

核心内容

  • web-access：连接用户日常 Chrome，天然带登录态。通过 curl 调 CDP Proxy HTTP API 操控浏览器（/eval、/click、/screenshot 等）。除了浏览器操控，还集成了 WebSearch 搜索、Jina 转 Markdown、子 Agent 并行调研、站点经验积累等能力。本质是一个全能联网方案
  • dev-browser：启动独立的全新 Chromium（无登录态）。通过 Playwright API 写 JS 脚本执行自动化操作。支持 Extension 模式连已有 Chrome，但主打场景是干净环境的自动化。本质是一个可复用的浏览器自动化工具
  • defuddle：最轻量，只做一件事——把网页正文提取为 Markdown，去掉导航广告等杂质。不操控浏览器，不需要登录态

选择决策表

场景选哪个
小红书/微信等需要登录或反爬的平台web-access
搜索某个话题的最新信息web-access
登录后台看数据、发布内容web-access
读一篇公开文章提取正文defuddle
批量抓取公开网站列表数据dev-browser
自动化测试本地开发的网页dev-browser
对页面反复执行同一套操作流程dev-browser

技术差异

维度web-accessdev-browser
浏览器用户日常 Chrome（带登录态）独立 Chromium（全新无状态）
API 风格curl 调 HTTP 端点Playwright JS 脚本
页面状态操作在用户 Chrome 后台 tab，最小侵入页面状态跨脚本持久化，失败后可恢复
额外能力搜索、Jina、并行调研、站点经验无，纯浏览器操控

我的想法

  • 三个工具可以按"轻→中→重"排列：defuddle（提取正文）→ web-access（带登录态浏览）→ dev-browser（自动化脚本），日常优先用轻的
  • 以后如果要做内容批量发布的自动化，dev-browser + web-access 可能需要组合使用：web-access 提供登录态，dev-browser 提供脚本化流程

为什么有用

  • 日常处理知识卡时，抓取公众号/小红书内容用 defuddle 或 web-access，不需要动用 dev-browser
  • 如果以后要做批量内容发布（比如批量发小红书帖子），dev-browser 的脚本模式更合适
  • 三个工具互补而非替代，搞清边界可以避免选错工具浪费时间

适用 / 不适用场景

  • 适用：使用 OpenCode/Claude Code 需要联网操作的所有场景
  • 不适用：纯本地文件操作不需要任何浏览器 Skill

补充：内网 SPA / 文档平台抓取策略（2026-04-22 tech.[org].com 事故复盘）

来源：个人实践 / 事故复盘

架构侦察优先原则

遇到企业内网 SPA、飞书/腾讯文档/Notion 类嵌入链接，禁止上来就 document.body.innerText 或无脑 defuddle。正确姿势：先做架构侦察，再选策略动手。

侦察清单（进页面后先跑这四项）

  1. 网络面板看真实数据源（JSON API 还是 SSR HTML）
  2. 是否有 iframe 套娃（document.querySelectorAll('iframe')）
  3. 是否虚拟滚动（容器高度固定、子元素数量不随滚动增长）
  4. 是否 CAS / SSO 认证门（302 重定向到 login 域名）

识别特征 → 对应策略

识别特征策略
iframe 套娃定位内层 URL（iframe.src），新 tab 直接打开内层
虚拟滚动容器JS 驱动滚动容器（container.scrollTop += step）逐屏渲染后读取
DOM 拿不全（只有外壳）截图 + 视觉读取兜底
CAS 认证门先在用户 Chrome 手动登录，再用 web-access CDP 连接已有登录态

本次事故四层套娃结构（tech.[org].com 参考案例）

小米技术圈 SPA
  └── CAS 认证门（302 重定向）
        └── 飞书 iframe 嵌入
              └── 虚拟滚动容器（.bear-web-x-container）

最终策略：跳进飞书 iframe 新 tab → JS 操作 .bear-web-x-container 滚动 → 逐屏截图视觉读取，完成全文提取。
