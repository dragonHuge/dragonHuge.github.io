原文沉淀

一直想做一个个人网站。 不是单纯为了有一个主页，而是越来越觉得： 公众号、小红书、知乎都很适合传播，但如果长期在研究一个问题、构建一套体系，很多内容其实很难只靠一篇一篇的信息流完整呈现。 所以我想要的不是一个“展示页”，而是一个可以持续生长的网站。 但真正开始做之后，我发现现在做网页、部署网页其实都不难了。 AI 可以写 HTML，静态网站也可以很快上线。 真正难的是：以后怎么更新？ 如果每写一篇文章，都要重新： 写文章 → 打开网页代码 → 复制内容 → 改 HTML → 加链接 → 重新部署 那这个网站大概率很快就会停止更新。 最近终于把这件事跑通了。 现在我的流程变成了： Obsidian 写作 → 标记 published → GitHub → 自动生成网页 → 自动部署。 我只管在 Obsidian 里正常写内容。 网站负责把已经发布的内容放到正确的位置。 如果一篇文章下面继续长出很多子文章，父子关系、分类、顺序，也可以一起自动生成。 而且草稿不会被误发出去。 但跑完整套流程后，我最大的感受反而是： 这件事最难的并不是技术。 真正重要的是先想清楚： 什么是网站里相对稳定的框架？ 什么是会持续变化的内容？ 这些内容之间是什么关系？ 网站怎么知道一篇内容应该放在哪里？ 最后我用 Frontmatter 做了一层“内容协议”。 正文写给人看，Frontmatter 写给机器看。 于是 Obsidian 负责写作和内容组织，网站负责展示，GitHub 负责把两边连接起来。 我越来越觉得，这其实不是一个 Obsidian 技巧。 它更像是在搭一套自己的内容生产系统： 写作系统和展示系统彼此独立， 但内容成熟之后，可以自动流向公开网站。 现在我的网站终于不再是一个“做完了就放在那里”的页面。 而是可以跟着我的阅读、研究、思考和创作一起持续生长。 9 张图把目前的实现方式完整拆了一遍。 如果有人也想搭，我后面可以继续拆得更具体一点： Frontmatter 怎么设计 / 发布脚本怎么写 / GitHub 怎么自动构建。 #AI时代以人为中心的终身能力发展系统 #技术赋能 #Obsidan #个人网站 #内容自动化 #罗盘笔记
