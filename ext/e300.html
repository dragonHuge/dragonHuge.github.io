核心内容

1. 定位

市面上的 Agent 教程多停留在"如何调用某个框架"，本书主张从零构建，把每个组件为什么存在、解决什么问题讲清楚。目标产物不是会用一个框架，而是脑子里有一个完整的 Agent 系统模型。

2. 本书想回答的核心困惑

  • 为什么调用工具之后要把结果送回模型？——理解循环结构与控制权归属。
  • ReAct 到底解决了什么问题？——推理与行动交替的必要性。
  • Agent Memory 与聊天记录有什么区别？——记忆是有选择的沉淀，聊天记录只是流水。
  • 复杂任务为什么会跑偏？——规划、状态与反思缺位时的典型失效模式。
  • Planning / Reflection / RAG / MCP / Code Execution 在系统里各占什么位置？——每个能力是解决哪一类问题的补丁。

可执行启发

  • 学习 Agent 时先手写一遍最小 ReAct 循环，再去看框架文档，理解成本会显著降低——框架解决的是工程化，不是概念。
  • 用"为什么调用工具后要回到模型"这类问题自测是否真的理解了循环结构，而不是记住了 API。
  • 建自己的 Agent 系统时，按书的结构逐项检查：工具、记忆、规划、反思、RAG、代码执行、编排、评测，缺哪补哪。
  • 把 Agent Memory 与聊天记录分开设计：记忆要有写入策略与淘汰规则，聊天记录只做原始素材。
