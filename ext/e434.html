机制无懈可击的修正，收益全在误差棒里

参考资料

  • Multi-Token Prediction Done Right — Jayden Teoh（MIT），arXiv 2610.38331，2026-10 · link — 本次对谈的主论文，提出把 MTP 交叉熵梯度拆成 KL 自蒸馏项与残差项、并用 straight-through 梯度路由抵消残差（Soft-MTP）
  • DeepSeek-V3 技术报告 — DeepSeek-AI，2024-12 · link — 顺序式 MTP 模块 + 共享输出头的来源，也是本篇实验采用的基线架构（K=3 个 MTP 头）
  • Better & Faster Large Language Models via Multi-token Prediction — Gloeckle et al.（Meta），ICML 2024 · link — 并行式 MTP heads，"Meta 式"对照。其 §2 原文明写架构是「共享主干 + n 个独立的 transformer 层作头 + 共享 unembedding 矩阵」：独立的是头那几层，共享的是 unembedding —— 也就是说这个 trick 需要的前提在 Meta 式上本来就成立（对谈里我对这一点的质疑是错的，见文末现查记录）
  • DeepSeek-V4.1-Flash: Pushing the Limits of KV Cache Compression — DeepSeek-AI，2026-09 · link — 其 §2.4.3 明写用 DSpark 取代 DeepSeek-V3 式"与主干联合预训练"的 MTP 模块：DSpark 在预训练之后单独一个阶段训、主干冻结；post-training 期间 DSpark 继续随主干训练但梯度不回传主干。这是判断"目标被搬走"的直接依据（已核原文）
  • DSpark: confidence-scheduled speculative decoding with semi-autoregressive generation — Cheng et al.，2026 · link — 半自回归草稿 + 置信度调度验证：3 个 Transformer block、128 滑窗，一次前向并行出 5 个草稿位置的 base logits，再用轻量 Markov 头建模草稿间依赖、confidence 头估每位置的条件接受率，据此按引擎吞吐曲线逐请求定验证长度
  • Nemotron 3 Ultra 的 MTP Boosting — NVIDIA，2026 — 训练后阶段用温度缩放的前向 KL 把 MTP 头对齐到 NTP 分布；本篇称其 trick 可用于此类场景
  • On-policy self-distillation (OPSD) — Zhao et al.，2026 · 以及 off-policy RL 的 score centering — 本篇列为 trick 的其他迁移面
  • The effective rank: a measure of effective dimensionality — Roy & Vetterli，EUSIPCO 2007 — 本篇 Figure 6 用的有效秩定义（奇异值谱归一化后的熵指数）
  • Fast Inference from Transformers via Speculative Decoding — Leviathan et al.，2022 · link — 本篇的评测协议（256 prompt × 512 token 续写、K=3 草稿、自验证）
  • ALBERT / LoRA / DeepSeek MLA — 2020 / 2022 / 2024 — 对谈里用来对照"主动指定低秩"的三条线：ALBERT 的 embedding 分解、LoRA 的低秩 delta、MLA 的 latent KV
  • 本人往期《开源 drafter 的架构会收敛到半自回归》(2026-06-30) — link — 押 DSpark 式的"并行骨干 + 轻量串行修正"会成为开源主流；本篇 discussion 与 V4.1-Flash §2.4.3 都是这条判断的旁证

我：看 Multi-Token Prediction Done Right 这篇。

dsh：先把一个错误纠正掉。我先前说这篇会撞上你 07-15 那条"spec decoding 机制已定型"的判断——那是我搞错了。simple-means-spec-closed 讲的是 task 的 spec 闭合（E3 省力策略的甜区在有 oracle、文件可预判、单一测试门能判的任务上），跟投机解码没有关系，我把两个 spec 混了。真正能对上的是 06-30 那条 drafter 架构收敛的判断：它押半自回归形态（DSpark 式）成主流，而 Soft-MTP 完全没碰架构，它改的是训练目标。 反过来，这篇最扎人的地方是它自己的 discussion 写的：DeepSeek-V4.1-Flash 已经弃掉 MTP、转用 DSpark——训练后才训的投机解码器。也就是说，它优化的那个目标，在做出这套架构的实验室那里正在被搬走。 机制本身可以两段说清。标准 MTP 第 k 个头对 hidden state 的梯度是 g_hard = Wᵀ(p⁽ᵏ⁾ − x)，x 是 one-hot 目标。加一项减一项就得到精确分解，不是近似： g_hard = Wᵀ(p⁽ᵏ⁾ − q⁽ᵏ⁾) + Wᵀ(q⁽ᵏ⁾ − x) = g_KL + g_res 其中 q⁽ᵏ⁾ = softmax(W·h⁽⁰⁾_{t+k}) 是位置对齐的 NTP 分布——同一个要预测的 token，只不过是从 t+k 那个位置的 NTP 头算出来的。所以 g_KL 恰好是"把 MTP 头往模型自己的 NTP 分布拉"的前向 KL 梯度，teacher 取 stop-grad。 真正需要设计的是怎么把 g_res 精确抵消、又不建 V 维的 logits。办法是在 NTP hidden state 上注入一个数值恒为零、但反传有梯度的东西：h̃_t = h_t⁽⁰⁾ + Σ_k [sg(h_{t−k}^(k)) − h_{t−k}^(k)]，于是 ∇(L̃_NTP + L_MTP) = g_hard − g_res = g_KL。变的是这个零值注入的构造，不是分解本身——分解是一行加项减项的恒等式，谁都能写出来。这个区别决定了它到底算不算"发现"。 实证部分的关键数字：残差的 SNR 比 KL 项低 4.1×（167M）到 4.6×（1.2B），还随规模恶化；但残差占了共享主干上 MTP 梯度的 ~80%；沿残差方向走一步，NTP loss 稳定上升（沿 KL 走则下降）。训练成本上，FLOPs 10.28 与标准 MTP 完全相同，吞吐 49,748 对 49,783（−0.07%），fused-CE 峰值内存 107.0GB 也完全相同——对照组 KL-MTP 则是 FLOPs 10.43、吞吐 −5.6%、峰值内存 +21GB。 我有三个地方认为被高估。第一，收益量级和"免费午餐"的语气对不上：主表全是 +1~2% 的相邻数字，1.2B 上 zero-shot 平均是 56.80 → 57.31，而正文和附录都没有多 seed、没有方差报告；实验是单作者、8 张从 Vast.ai 租的 RTX PRO 6000、最大 1.2B × 31.5B token。机制层硬，误差棒是空的。第二，它其实不是"MTP 有害、我修好了"：看 Table 3 的 NTP 参考列，1.2B 上 NTP ppl 10.572 < Soft-MTP 10.741 < 标准 MTP 10.891——标准 MTP 在 ppl 上比不加 MTP 还差，Soft-MTP 只是把那笔税收回大半、没收完（accuracy 上三者基本打平：56.75 / 56.80 / 57.31）。第三，全文最值钱的发现可能不是"免费午餐"，是 Figure 6 那个读出矩阵有效秩：NTP 496 / 标准 MTP 131 / KL-MTP 321 / Soft-MTP 437。标准 MTP 把 unembedding 的有效秩压到了 NTP 的四分之一。 还有两个工程侧的坑。「一行代码」只在单卡成立——论文自己写需要 h⁽⁰⁾_{t+k} 和 h⁽ᵏ⁾_t 在同一张卡上、且有从 L_NTP 到 h⁽ᵏ⁾_t 的反传路径；序列分片（context parallel / ring attention）要在 shard 边界反传交换最多 K 个 hidden 梯度。而 frontier 预训练里 3D 并行是标配，落到真实 codebase 是"模型代码一行 + CP 路径一处边界交换"。另外它的真实迁移面可能不在 MTP 上：论文末尾自己说这个 trick 适用于任何"teacher 与 student 共享线性输出头"的场景，包括 Nemotron 3 Ultra 的 MTP Boosting、on-policy self-distillation、off-policy RL 的 score centering——那些地方现在要么显式算 KL、要么用 top-k 近似。

我：坦白说 1.5% 一般不值得大动干戈。有效秩这个是个好方向，但是这个东西从经验上看，可能是跟集合难度之类的因素有关。低秩分解这个事一直在做——ALBERT 就做过，后来的 LoRA，还有 DeepSeek 的 MLA，都是这方面的。在部分任务上看，低秩分解像无损，但其中一些更困难的场景可能会表现出差距。

dsh：1.5% 这条我完全接受。那这篇的价值就不能押在速度上——它唯一值得动训练代码的理由是"MTP 在偷偷收税"，而这条在 1.2B 单 seed 上不算证据。 你对低秩的质疑我认一部分，但两件事要分开：ALBERT 的 embedding 分解、LoRA 的低秩 delta、MLA 的 latent KV，都是主动指定低秩，然后去量 accuracy 掉多少；这里的 131 对 496 是涌现出来的——没人指定，是训练动力把读出矩阵压下去了，量完了反过来推断"这可能有害"。因果方向是反的：前者问"低秩到某个程度还行不行"，后者要问"没打算低秩、结果它低了，算不算坏账"。所以那套文献不能直接回答这个问题；但也正因为如此，"低秩在简单任务上像无损"这句不能用来宽慰这 131——如果 MTP 真在压秩，它压的正好是"上了难度才现形"的那一段，而且没人给它配预算或 ablation。 不过这次的硬伤我自己先说：它零干预证据。三个 MTP 目标（外加 NTP 参考）在架构、头数、参数量、数据、步数、优化器上全控住了（这点做得不错，能排除"只是头多了"的混淆），但给的全是相关性——秩低的那组刚好 loss 也差。没有任何"动秩、其他不动"的实验。而且 Figure 6 我读不到横轴，正文只给了终值 496 / 131 / 321 / 437，所以是不是训练全程曲线都不确定，按终值看更保守。 你说的"难任务才现形"，在论文里其实有影子，只是不在 accuracy 上，在采样预算上：

HumanEval（MTP → Soft-MTP）31.70 → 31.99（+0.29）36.37 → 37.26（+0.89）40.85 → 43.90（+3.05）

差距随 k 单调放大，pass@16 基本是噪声，pass@64 是 3 个点。这个形状不像"难度"，更像输出分布的覆盖度：低秩读出能表达的方向少，高频模态照得住，长尾多解场景塌缩，k 越大越吃亏。数学微调那边也同向（GSM8K +1.1 / MATH-500 +1.8，这俩本来就是单解 greedy，只能看 accuracy）。所以如果机制成立，被压的不是 ppl，是多选题空间的宽——这跟你说的"低秩在更困难场景表现差距"是同一件事，只是被换算成了 pass@k。 但我自己再泼一盆：后验截断 ≠ 训练时塌陷。最便宜的验证是拿开源模型把 unembedding 做 SVD 截断到 1/4 有效秩、简单集难集各测一遍，可前者是"学过再拿走"，后者是"从没学过那批方向"，前者能靠其他层补偿，后者没有替代路径。所以那个实验就算做出"简单集无损、难集掉点"，也只证明"秩这一维对难任务敏感"，不能证明 MTP 就是这么受伤的。 另外我在正文里找不到一个答案：这个 trick 的数学前提是 teacher 和 student 共享那个线性输出头（否则 q⁽ᵏ⁾ 和 p⁽ᵏ⁾ 不在同一坐标系，恒等式不成立）。它宣称 DeepSeek 式和 Meta 式都支持，但附录 C 的 Meta 式实验只给了 332M / 7.3B token 的 loss 曲线，没交代那批实现是不是也共享 W。而 Gloeckle 原版的 parallel heads 是每个头各自一个输出层——如果真是各自独立，这个 trick 在 Meta 式上数学不成立，"支持两种架构"就只是"两种主干结构上都能改，但都得先改成共享头"。（落稿前现查更正：最后这条我搞错了——Gloeckle §2 原文里 unembedding 本来就是共享的，独立的是那几个 transformer 层。详见文末现查记录。）

我：pass@64 这种地方的差距感觉不是特别有实际价值，计算上用各种 rollout 的方式，也很难采这么多吧。

dsh：补一句你可能还没注意到的、更利于你这个判断的证据：Table 4 那个 +3.05 分的来源是温度扫描取最好。原文写的是 top-p=1.0、no top-k，温度在 {0.1, 0.2, …, 1.0} 里扫，每格报 best pass@k。看它标的温度：HumanEval pass@64 上 MTP 选的是 T=0.7、Soft-MTP 选的是 T=0.6——这 3 分是两个不同温度下各自取到的最好值相减，中间隔着 10 档 × 2 组的选择自由度。这不是误差棒，这是选择偏差。所以不只是"k=64 没人用"，是"就算你想用，那一格也不是可靠的效应估计"。 按 k=8~16 的实际作业口径，官方效应量落在 +0.29 和 −0.40 之间，符号都不稳。那 pass@k 这条证据线我撤回——撤回之后，秩的故事就变成纯机制假设、零实证，只能作为"值得盯"的方向，不能进判断层。 剩下真正站得住的三样，都是硬数字不是效应量：① 残差占共享主干上 MTP 梯度的 ~80%，SNR 比 KL 低 4.1×→4.6×，且沿它走一步 NTP loss 稳定上升——这是实验测出来的结构量，不靠效果大小成立；② KL-MTP 的账单：FLOPs 10.43 对 10.28、吞吐 −5.6%、峰值内存 +21GB、且吃不到 fused CE 的好处——这一条与 MTP 无关，谁做共享头蒸馏都得付；③ 梯度路由表本身（输出头用 CE 还是 KL、上游用 CE 还是 KL 的三分法）比论文的主结论更耐用，它说明"输出头用 CE、上游用 KL"这个组合是一个被遗漏的格子，不是一项被发明出来的方法。 所以这篇该被记住的位置是两句话：机制是真的，收益是测不出来（或至少这篇测不出来）——这是参数级修复而不是范式级修复，决定要不要采纳的不是收益大小，是它绑在一条还在不在的路线上的；而它自己把这条路的出口写出来了——DeepSeek-V4.1-Flash 已弃 MTP 转 DSpark，它在给一个正在被搬走的目标做优化，真正耐用品是那个 trick。

总结

  1. 机制层是硬的，而且这条不依赖任何效果量。标准 MTP 的交叉熵梯度里，真正对投机解码有用的 KL 自蒸馏信号只占共享主干 MTP 梯度的 ~20%，另外 ~80% 是与 NTP 更新反相关、SNR 低 4 倍、且随规模继续变差的残差。这个结构缺陷是实验测出来的量，不是从效果反推的。
  2. 但"免费午餐"这个语气撑不住。所有可观测收益——+1.4~1.5% 提速、+1.8~2.2% acceptance length、zero-shot +0.1~0.5 分——都在单 seed、1.2B 代理模型的噪声带里；唯一"随难度放大"的 pass@k 差距，是把温度在 10 档里扫完取最好值后的相减，属于选择偏差而非效应估计；而且按实际 rollout 预算（k=8~16），官方数字连符号都不稳。
  3. "低秩塌陷"是这条轴上一个站不住脚的证据，但值得留作方向。它的读法问题不在秩本身（秩是权重矩阵的性质，不是某个评测集的性质），而在两个缺口：主动指定低秩（ALBERT / LoRA / MLA）与涌现低秩的因果方向相反，前者的结论不能拿来给后者宽慰；以及这篇完全没有干预实验，后验截断也无法替代训练时塌陷。真要立起来，得靠"MTP-trained 与非 MTP 同档模型在同一 harness 下的 pass@k 对照"或"训练全程秩曲线 + 多 seed"。
  4. 决定它命运的不是这 3 分，是路线的存亡——而且"搬走"的方式比"换掉"更彻底。MTP 头作为 drafter 的价值，正在被训练后的 DSpark / DFlash / EAGLE 这条线重估。V4.1-Flash 的 §2.4.3 把这件事写得直白：DSpark 在预训练之后单独一个阶段训练、主干冻结；post-training 期间 DSpark 继续跟着主干走，但梯度不回传主干。换来的是"drafter 始终跟得上演进的 policy"，代价是 drafter 从预训练目标里彻底脱钩。于是"MTP 头该怎么训"的适用范围，从"所有用 MTP 的预训练"缩到"还在预训练阶段就把 drafter 绑上去的那部分栈"——而这个收缩发生在论文写出来之前。真正耐久的反倒是那句与 MTP 无关的话：共享线性输出头时，KL 梯度可以从交叉熵梯度里精确找回、不必建 V 维 logits，它该被归到后训练蒸馏工程（MTP Boosting、on-policy self-distillation、RL score centering），那里现在还在为显式 KL 付 +21GB 峰值内存和 −5.6% 吞吐的账。顺带一句：DSpark 的形态（一次前向并行出 5 个草稿位置 + 轻量马尔可夫头修依赖）正是 06-30 那条"drafter 会收敛到并行骨干 + 轻量串行修正"的判断，兑现比窗口来得早。

一个可证伪的预测

未来 12 个月内（至 2027-11）：

(a) 不会有一个以 MTP 头作 drafter 的前沿开源模型，把"残差抵消"式训练修正写进默认预训练目标。 判据：DeepSeek / GLM / Kimi / Qwen / MiniMax / Nemotron 系下一代的训练目标描述与模型卡。若出现，且同时报告了同 harness 下可测的投机解码收益（>2% 加速或 >3% acceptance length），本条证伪。

(b) 会出现至少一个公开工作，把"共享线性头下 KL 梯度可免建 V 维 logits 地精确恢复"用于训练后蒸馏（MTP Boosting / on-policy self-distillation / off-policy RL score centering 之一），并给出与显式 KL 的开销对比。判据：这类工作的方法与开销表。若到 2027-11 仍只有这一篇，说明 trick 的迁移面被高估，(b) 证伪。

两条合起来押的是同一件事：trick 活下来、目标不一定。
