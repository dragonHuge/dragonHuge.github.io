Agent 应用开发 — 五阶段学习计划

📅 2026-05-20 · 📄 Agent应用开发/学习计划.md

Agent 应用开发 — 五阶段学习计划

总时长：约 10-14 周（按每天 2-3 小时计） 方法：每阶段以一个可交付的小项目收尾，不做纯理论学习

第一阶段：RAG 基础与全链路搭建（第 1-3 周）

目标：从零搭一个能用的 RAG 系统，跑通全链路

第 1 周：向量检索基础 + 最简 RAG

知识点：

  1. Embedding 原理
    • 什么是向量嵌入：把文本映射到高维空间，语义相近的文本距离近
    • Embedding 模型选型：OpenAI text-embedding-3-small/large、BGE-M3、Jina v3
    • 维度与性能的 tradeoff：高维更精准但更慢更贵
  1. 向量数据库
    • Chroma：轻量级，适合原型和小规模（本地嵌入式）
    • FAISS：Meta 开源，高性能，适合大规模（需自己管理持久化）
    • Milvus/Qdrant/Weaviate：生产级分布式方案
    • 相似度算法：余弦相似度 vs 欧氏距离 vs 内积
  1. 最简 RAG Pipeline

``` 文档 → 切分 → 向量化 → 存入向量库 查询 → 向量化 → 相似度检索 → Top-K → 拼接 Prompt → LLM 生成 ```

动手：

  • 用 LangChain + Chroma 搭建一个最简 RAG，支持对你自己的 Markdown 笔记提问
  • 不求完美，跑通全链路即可

检验标准：

  • 能对你的 03-学习/AI底层原理/LLM-Agent工程原理.md 提问并得到合理回答

第 2 周：文档解析与 Chunk 策略

知识点：

  1. PDF 解析
    • PyMuPDF (fitz)：快速提取文本，保留结构
    • Unstructured：智能解析，自动识别标题/表格/图片
    • 难点：扫描件 PDF（纯图片）、多栏布局、表格嵌套
  1. OCR 技术
    • Tesseract：开源 OCR 引擎，多语言支持
    • PaddleOCR：百度开源，中文效果优秀
    • 应用场景：扫描件 PDF、图片中的文字
  1. VLM（视觉语言模型）
    • 为什么不只用 OCR：OCR 只提取文字，VLM 能理解图表含义
    • 模型选型：GPT-4V、Claude Vision、Qwen-VL
    • 应用：流程图理解、图表数据提取、截图内容解析
  1. Chunk 切分策略（核心！）
    • 固定大小切分：简单但可能切断语义
    • 递归切分（RecursiveCharacterTextSplitter）：按分隔符层级递归（nn → n → 空格 → 字符）
    • 语义切分：用 Embedding 相似度判断语义边界
    • 文档结构切分：按标题层级（H1/H2/H3）切分
    • Overlap（重叠）：相邻 chunk 重叠一部分，防止边界信息丢失
    • chunk_size 和 chunk_overlap 的调参经验
  1. 元数据绑定
    • 给每个 chunk 标注：来源文件、页码、标题路径、创建时间
    • 元数据在检索时的作用：过滤、加权、溯源

动手：

  • 给 RAG 系统加 PDF 和图片解析能力
  • 对比不同 Chunk 策略的检索效果

检验标准：

  • 能正确解析一个包含文字+表格+图片的 PDF
  • 对比至少 3 种 chunk 策略的检索结果差异

第 3 周：混合检索与 Rerank

知识点：

  1. BM25（稀疏检索）
    • 原理：基于词频和逆文档频率的传统检索算法
    • 优势：精确匹配关键词、不需要 Embedding、对专有名词/代码友好
    • 局限：不理解同义词和语义
  1. 稠密向量检索
    • 原理：用 Embedding 模型把文本映射到向量空间，按相似度检索
    • 优势：理解语义、处理同义词
    • 局限：对精确匹配弱（如错误码、函数名）
  1. 混合检索（Hybrid Search）
    • 为什么要混合：BM25 擅长精确匹配，向量擅长语义匹配，互补
    • 融合策略：
    • RRF（Reciprocal Rank Fusion）：按排名倒数加权，简单有效
    • 加权分数融合：手动设置 BM25/向量的权重
    • 实现：LangChain EnsembleRetriever
  1. Rerank（重排序）
    • 为什么需要：初始检索（BM25/向量）速度快但不够精准，Reranker 精度高但慢
    • Cross-Encoder 原理：把 query 和 document 拼在一起过一个模型，输出相关性分数
    • 模型选型：Cohere Rerank、BGE-Reranker、Jina Reranker
    • 和 Bi-Encoder（Embedding）的区别：Cross-Encoder 更精准但不能预计算
  1. 查询改写（Query Rewriting）
    • 用 LLM 把模糊问题改成更精准的检索词
    • 多查询生成：一个问题生成多个变体，分别检索，合并结果
    • HyDE（Hypothetical Document Embeddings）：先让 LLM 生成一个假答案，用假答案的向量去检索

动手：

  • 实现 BM25 + 向量的混合检索
  • 加上 Reranker 精排层
  • 对比纯向量 vs 混合检索 vs 混合+Rerank 的效果

检验标准：

  • 量化对比三种配置的 MRR 和 Hit Rate

第二阶段：RAG 高级与工程化（第 4-5 周）

目标：从"能用"到"好用"——评测驱动优化 + 工程化

第 4 周：评测体系搭建

知识点：

  1. RAGAS 评测框架
    • 安装和基本用法
    • 四个核心指标的计算方式：
    • Faithfulness：回答中的每个 claim 是否能在 context 中找到依据
    • Answer Relevancy：回答是否切题（用生成的问题反向验证）
    • Context Precision：排在前面的 context 是否比后面的更相关
    • Context Recall：ground truth 中的 claim 是否都在 context 中出现
    • 构建评测集：手动标注 question-answer-context 三元组
  1. 检索评估指标
    • MRR（Mean Reciprocal Rank）：正确答案平均排在第几位
    • Hit Rate@K：正确答案是否在 Top-K 中
    • NDCG：考虑排序位置的评分
  1. 评测驱动优化循环

``` 修改参数 → 跑评测 → 对比指标 → 分析瓶颈 → 下一轮修改 ```

  • 可调参数：chunk_size、overlap、top_k、embedding 模型、reranker 模型、BM25/向量权重

动手：

  • 为你的 RAG 系统搭建 RAGAS 评测流水线
  • 构建 20+ 条评测数据
  • 通过评测结果优化至少一个参数

检验标准：

  • 有可复现的评测脚本
  • 能用数据说明某次优化的效果

第 5 周：工程化优化

知识点：

  1. 增量索引
    • 文档 Hash 检测变更：只重新处理改变的文件
    • 增量更新 vs 全量重建的 tradeoff
    • 文档删除处理：标记删除 vs 物理删除
  1. 缓存策略
    • QA 缓存：相同/相似问题直接返回缓存答案
    • Embedding 缓存：避免重复向量化
    • LLM 调用缓存：减少 API 费用
    • 缓存失效策略：TTL、文档更新触发
  1. 工厂模式与可插拔架构
    • 为什么要解耦：方便 A/B 测试不同组件
    • 解析器工厂：PDF/Markdown/Image 各有解析器
    • 切块器工厂：不同切分策略可插拔
    • Retriever 工厂：BM25/向量/混合可切换
    • Reranker 工厂：Cohere/BGE/Jina 可替换
  1. 问题路由（Question Routing）
    • 判断问题类型：事实型/分析型/对比型/操作型
    • 不同类型走不同检索策略
    • 实现：LLM 分类器 或 规则匹配
  1. 引用核查
    • 验证生成内容有据可查
    • 标注引用来源（具体到哪个 chunk/文件/页码）
    • 减少幻觉的关键手段

动手：

  • 给 RAG 系统加增量索引和缓存
  • 实现至少两种组件的可插拔替换

检验标准：

  • 修改一个文档后，只有该文档的 chunk 被重新索引
  • 缓存命中率能量化展示

第三阶段：Agent 架构设计与实现（第 6-8 周）

目标：从"读懂 Claude Code"到"自己能设计 Agent 架构" 前置：你已经有 LLM-Agent 工程原理的理论基础，这阶段重点是工程实现

第 6 周：Skill 路由系统设计

知识点：

  1. Tool 与 Skill 的分层
    • 原子 Tool：单一操作（读文件、执行命令）
    • 复合 Skill：编排多个 Tool 完成一个完整任务（代码审查 = Read + Grep + 分析 + 报告）
    • Skill 目录：注册表，含元信息
  1. 意图识别与路由
    • 基于规则的路由：关键词匹配、正则表达式
    • 基于 LLM 的路由：让 LLM 判断该调用哪个 Skill
    • 二阶段召回：粗筛（embedding 相似度 / 关键词）→ 精排（LLM 打分）
    • 你目前用的 CLAUDE.md 声明式路由 vs 向量检索式路由
  1. Skill 注册与发现
    • 静态注册：配置文件声明
    • 动态发现：扫描目录自动发现新 Skill
    • 元信息标签：触发条件、适用边界、示例、版本
  1. Skill 演化管理
    • 功能重叠检测：多个 Skill 能做同一件事时怎么选
    • 版本管理：Skill 升级不影响已有流程
    • Token 成本控制：Skill 描述越多 → System Prompt 越长 → 成本越高

动手：

  • 设计一个简单的 Skill 注册和路由系统
  • 实现 3-5 个 Skill（如：文件搜索、代码解释、测试生成）
  • 用 LLM 实现意图识别路由

检验标准：

  • 用户说"帮我写测试"能正确路由到测试生成 Skill
  • 新增一个 Skill 不需要改路由代码

第 7 周：记忆系统设计

知识点：

  1. 记忆分类学
    • 短期记忆：当前会话上下文
    • 长期记忆：跨会话持久化
    • 程序性记忆：how-to（"怎么做"）
    • 情景记忆：what-happened（"发生了什么"）
    • 语义记忆：what-is（"是什么"）
  1. 记忆提取
    • 从对话中自动提取值得记住的信息
    • 提取策略：关键事件检测、用户偏好识别、错误经验捕捉
    • 提取时机：对话结束后 / 关键节点实时提取
  1. 记忆存储
    • 文件存储：Markdown（人类可读，Claude Code 方案）
    • 向量存储：支持语义检索
    • 结构化存储：JSON/SQLite（精确查询）
    • 混合存储：文件 + 向量索引
  1. 记忆检索与注入
    • 全量注入：所有记忆都塞进 System Prompt（简单但不可扩展）
    • 按需检索：根据当前上下文检索相关记忆（可扩展但有延迟）
    • 混合策略：高频记忆常驻 + 低频记忆按需检索
  1. 记忆整理（AutoDream）
    • 合并重复记忆
    • 解决冲突（保留最新）
    • 删除过时信息
    • 提升高频使用的记忆权重

动手：

  • 给你的 Agent 加一个跨会话记忆系统
  • 实现记忆提取 + 存储 + 检索 + 注入的闭环

检验标准：

  • 第一次对话告诉 Agent 你的偏好，第二次对话 Agent 能记住
  • 记忆文件人类可读可编辑

第 8 周：多 Agent 协作

知识点：

  1. 中心化 vs 去中心化
    • 中心化（Coordinator 模式）：一个主 Agent 统一调度，子 Agent 受控执行
    • 去中心化（Swarm 模式）：无中心，Agent 间自由协商
    • 编程场景选中心化的原因：确定性和可控性
  1. 子 Agent 生命周期
    • 创建：主 Agent 决定需要帮手 → fork 子 Agent
    • 配置：提示词 + 工具白名单 + 模型选择
    • 执行：子 Agent 独立 Agent Loop
    • 返回：只返回最终结果
    • 销毁：完成即销毁
  1. 上下文隔离
    • 为什么要隔离：防止上下文互相污染、控制 Token 消耗
    • Fork 隔离：子 Agent 看不到主 Agent 的完整历史
    • Worktree 隔离：子 Agent 在独立 Git 分支工作
    • 文件系统隔离：子 Agent 只能访问特定目录
  1. 通信与同步
    • 单向通信：主 → 子（任务指令）→ 返回结果
    • 双向通信：Agent 间互发消息（Agent Teams）
    • 状态同步：共享任务列表、进度更新
  1. 安全约束
    • 工具权限白名单：没给的工具就真的调不了
    • 路径边界限制：子 Agent 只能访问指定目录
    • 嵌套限制：防止递归创建子 Agent

动手：

  • 实现一个主 Agent + 2 个子 Agent 的协作系统
  • 如：主 Agent 拆任务 → 搜索 Agent 查资料 → 编码 Agent 写代码

检验标准：

  • 子 Agent 真正并行执行
  • 子 Agent 无法调用权限外的工具

第四阶段：高级主题与拓展（第 9-11 周）

第 9 周：上下文压缩与成本优化

知识点：

  1. Prompt Cache 优化
    • 静态前缀 + 动态后缀的排布策略
    • 缓存断点设置
    • 缓存命中率监控
  1. 分层压缩实现
    • 工具结果预算控制
    • 会话摘要
    • 完整压缩
    • 应急压缩
  1. Token 成本建模
    • 输入/输出/缓存读写的价格差异
    • 每轮 API 调用的成本估算
    • 优化 ROI 分析

动手：

  • 给 Agent 加上下文压缩机制
  • 实现 Token 消耗追踪和成本报告

第 10 周：Agentic RAG + GraphRAG

知识点：

  1. Agentic RAG
    • 传统 RAG 的局限：单次检索、无法多步推理
    • Agent + RAG 结合：Agent 自主决定是否需要检索、检索什么、检索几次
    • 多步检索：第一次检索结果不够 → 改写查询 → 再检索
    • Self-RAG：模型自己判断是否需要检索、检索结果是否相关
  1. GraphRAG
    • 知识图谱 + RAG：把文档中的实体和关系抽取成图
    • 优势：多跳推理（A→B→C）、全局视野
    • 微软 GraphRAG 框架：社区检测、分层摘要
    • 和传统 RAG 的对比：结构化关系 vs 纯文本相似度
  1. RAPTOR
    • 树状结构检索：chunk → 聚类 → 摘要 → 更高层聚类 → 更高层摘要
    • 多层级检索：根据问题复杂度选择合适的层级

动手：

  • 把你的 RAG 系统改造成 Agentic RAG
  • 或实现一个简单的 GraphRAG

第 11 周：MCP 开发与 Prompt 注入防御

知识点：

  1. MCP Server 开发
    • MCP 协议规范：工具定义、资源发现、采样
    • 用 Python/TypeScript SDK 开发 MCP Server
    • 注册到 Claude Code / 其他 Agent 中使用
  1. Prompt 注入防御
    • 直接注入：用户输入中包含"忽略前面的指令"
    • 间接注入：工具返回结果中包含恶意指令
    • 防御策略：输入过滤、输出检测、分层提示词隔离、角色锚定
    • 实际案例分析

动手：

  • 开发一个 MCP Server（如：本地知识库查询工具）
  • 实现基本的 Prompt 注入检测

第五阶段：综合项目实战（第 12-14 周）

目标：把所有知识点融合成一个完整项目

第 12-14 周：构建你自己的 AI Coding Agent 或 RAG 系统

两条路线选一条：

路线 A：Mini Agent（侧重 Agent）

  • 基于 Claude/OpenAI API 实现一个简化版 Coding Agent
  • 核心模块：Agent Loop + Tool System + Skill Router + Memory + Context Compression
  • 支持：代码阅读、修改、测试、Git 操作
  • 额外加分：MCP 集成、多 Agent 协作

路线 B：Production RAG（侧重 RAG）

  • 基于你的知识库场景构建一个生产级 RAG 系统
  • 核心模块：多格式解析 + 混合检索 + Rerank + 评测 + 增量索引 + 缓存
  • 额外加分：Agentic RAG、GraphRAG、多模态

检验标准：
